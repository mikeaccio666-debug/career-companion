# 05 全旅程与关键流程

> 状态：v2（2026-10-06），按简报 v3 与总编辑裁决修订，Codex 按此实现。代码基线 `965db09`，引用写文件和函数名。
> 分期以 07 为准；待确认对象的模型与状态机以 03 §9 为准，状态文案与色调以 08 §7.10 为准；编排以 03 §4–§6 为准；主动消息的类型、额度与默认时间以 02 §9 为准；付费时机以 06 §7 为准；Discord 形态以 10 §3 为准。**路由由本文 0.3 定名；看板字段由本文 3.1 定义。**
> 示例用户是 01 的林舟（一年制 MS CS，找 SWE），「墨」是**他给主理人起的名字**；身份边界用赵可（按他自己录入的日期，处在 OPT 待业期）。公司均为示例。

## 这份文档回答什么问题

1. 用户从注册到入职经过哪七个阶段，每个阶段谁主导、什么时候算走完（第 1 节）。
2. 十六个关键流程怎么一步一步走：入口、界面和文案、失败与边界、验收（第 2 节）。
3. 共用对象与本文字段到 09 表的对照（第 3 节）；Discord 的补充差异（第 4 节）；落到现有代码（第 5 节）。

**结论**

- 七个阶段（初见 → 定方向 → 打磨 → 出击 → 面试 → Offer → 落地）是派生状态，不是关卡，可以重叠、可以回退。
- P0 做：初见（含邀请码与协议确认）、今天、小组对话、待确认、面试间逐回合、被拒后的即时回应、回流、记忆、真人意向、旅程页与故事库；其余按 07 进 P1a / P1b / P2。P0 小组只有主理人、前、投、面；岗位只来自用户收藏和粘贴的 JD。
- 底线一：要发给别人的消息和材料，都先进待确认；表单里哪些项可以替你做，由你在小组对话里逐项确认（见 11）；最终提交永远由你本人点。
- 底线二：对外材料和复盘不引入用户已确认资料以外的事实，材料包逐句标来源；身份信息只原样显示用户录入的内容。
- 底线三：所有用户文字（含诞生前）先过安全分级；被拒不出现红色和 Rejected；被拒后 48 小时、危机后 14 天不出现付费建议。

## 0. 共用约定

### 0.1 所有流程都遵守的规则

| 规则 | 具体要求 |
|---|---|
| 主动消息 | 类型（`kind`）、额度、免打扰、默认时间、例外溢出的取舍见 02 §9。本文每条主动消息标明 `kind` 和「占额度」「例外」或「不推送」。专家只在群里说话，不推送（03 D5） |
| 对外发出 | 要发给别人的消息和材料，都先进待确认（2.4）；表单里哪些项可以替你做，由你在小组对话里逐项确认（见 11）；最终提交永远由你本人点。主按钮：用户自己发出的「确认这一版」；交给插件的「确认这一版，交给插件」；只有产品或蔓藤真正代为送出（`in_product`）才写「封缄寄出」；「缄」只作动效和图形 |
| 有据可查 | 对外材料、故事、面试复盘不引入用户已确认资料以外的经历、数字、公司、日期（02 §3.3） |
| 状态覆盖 | 存为 `overlays` 数组（02 §8.1）。被拒（只限 2.7 的完整流程）后 48 小时、危机后 72 小时不发任务类主动消息；被拒后 48 小时、危机后 14 天内不出现付费建议（06 §7.2）。面试和截止提醒在任何覆盖期、「今天不想」「先歇几天」期间都照发，只去掉准备任务 |
| 颜色与数字 | 不出现红色负面状态、连胜、失败计数、拒信数量；印章红只用于印章和确认动效（08）；数字等宽、陈述事实，不做百分比施压 |
| 语言 | 情绪与说明用用户的情绪语言；实战材料和面试间一律英文 |
| 危机 | 所有用户自由文本（含诞生前、面试间回答、Discord）落库后先过 02 §10.2 的同步分级器；L2 由服务端固定模板和资源卡回应（02 §10.3），不经过模型；当前流程挂起，之后可以继续 |
| 身份信息 | 只原样显示用户录入的日期和数字，带「信息与提醒，不是法律意见」；身份相关数字只能来自经专业人士审核的配置（02 §3.3） |
| 岗位来源 | P0 只处理用户收藏的岗位，默认贴 JD 文本：`source='manual'`、`state='unknown'`，标「你贴的 JD · 没核实是否还开放」，不做关闭检测。读链接是 P0 后段可选（07 P0-9），自动找岗位是 P2（2.16） |
| 赵可检查 | 每个流程上线前过一遍 01 §2.4 的五问，任何一项答「是」就不上线 |

## 1. 七个阶段

### 1.1 总表

| 阶段 | 用户目标 | 主导 | 关键时刻 | 进入 | 退出 |
|---|---|---|---|---|---|
| 1 初见 | 得到自己的主理人和第一份三件事 | 主理人（career-intake） | 第一封信 | 注册并同意协议 | 第一封信送达 |
| 2 定方向 | 收敛成「主攻 + 对照」，作为暂定假设 | P0 主理人；规（P1b） | 晨报；两方向卡（P1b） | 初见完成且没有 `active` 目标 | 用户确认至少一个主攻方向 |
| 3 打磨 | 一份能投的英文简历，3 个能讲出口的故事 | 前；教（P1b） | 故事库；待确认（简历版本） | 有主攻方向 | 一个已确认的简历版本（原稿可直接确认，2.16）且 3 个 `confirmed` 故事（假设）。用户说「先投起来」可提前进出击 |
| 4 出击 | 每周投一批精准的岗位 | 投；脉（P2） | 待确认；晨报；投递授权对话（P1-1） | 有已确认的简历版本 | 持续到落地；出现 OA 或面试时并行进入面试 |
| 5 面试 | 准备并完成每一场 | 面；教（P1b） | 作战简报（P1-4）；被拒之后 | 看板有 OA 或面试 | 都结束：有 offer 进 Offer，否则重心回出击 |
| 6 Offer | 看清条款，比较，决定 | 主理人；规（P1b）；蔓藤导师 | Offer 那天 | 看板有 offer | 接受一个进落地；全部婉拒或失效回出击 / 面试 |
| 7 落地 | 办妥入职前的事，留下这一段 | 主理人 | 年鉴（P2） | 标记接受 offer | 入职后 30 天（假设）：收尾信，主动消息停止，账号保留 |

### 1.2 阶段怎么算

- 派生状态，每晚和每次看板变化时重算，缓存为 `journey_focus`；任何阶段都可以 @ 已上线队员、进面试间。
- 可以重叠：旅程页显示「现在的重心」，取有活跃事项的最靠后阶段。中途进来的用户直接落到对应阶段，初见不跳过。
- 回退是正常的：只写「现在的重心：出击」，不写「退回」「失败」。系统事件行只在进入面试、Offer、落地时出现。

## 2. 关键流程

每个流程按「入口 → 步骤 → 失败与边界 → 验收」写。Discord 差异见第 4 节和 10 §3。

### 2.1 初见：不填表的对话式 onboarding

顺序（07 P0-5）：注册与同意 → 基本事实 → 情境题（快速通道可跳过）→ 预览 → 起名、刻章 → 诞生 → 初见对话（含简历、身份日期）→ 第一封信 → 三件事。注册后进入 `/welcome`；第一封信之前隐藏底部导航和指挥台。

**原则**

- **不填表**：O1 起全是群聊一问一答，快捷回复或打字都行；除起名外每问都能跳过。
- **诞生前由「待命名的主理人」主持**：空白虚线印章，「你的主理人 · 还没有名字」加「AI」标识；说的话全部是固定文案，不调用生成模型（02 §2）。
- **诞生前同样跑安全分级**：O1–O4 的打字、打字回答选择题、诞生前问别的问题，落库后都先过 02 §10.2 的分级器；分级调用不算「生成」。L2 命中时由待命名的主理人发服务端固定模板和资源卡（02 §10.3），不当成跳过。
- **诞生后由主理人本人用说话方式卡对话**；身份相关的句子用固定文案。简历和身份日期都不是必需的。
- **进度存在服务端**：`onboarding_state`（`step` 取 O0…C8、`answers_partial`、`updated_at`），放在 `platform_career_profiles` 或单独建表（09 定）；O2、O3 每答一题 PATCH 一次。刷新、换设备都从当前步骤继续。

| F-1 在读 | 「要不要记下 I-20 上的 program end date？」 | `program_end_date`（`sensitive`，专家只拿到年月） |
| OPT / STEM OPT | 「要不要现在记下 EAD 卡上的起止日期？」→「目前有工作吗？」[有] [没有] [不想说] → 没有：「你自己记的待业天数是多少？不确定就空着。」 | OPT 起止、`employment_reported`、`unemployment_days_reported` + `reported_at`（`restricted`）；不存待业开始日，不推算 |

```

### 2.2 今天：晨报与今天页

**入口**：群里的晨报信件；底部导航「今天」；邮件提醒链接；Discord 的 [看完整晨报]。

**晨报**（`morning_brief`，**占额度**，C8 选的时间，诞生次日开始）

- **生成**：提前 20 分钟（假设）由调度器排任务，走 03 的后台生成路径（不占轮次锁、经过费用护栏）：纯函数 `pickTodayThree`（`packages/career-core`）挑三件事 → 按说话方式卡写信 → 过 02 的校验器。
- **结构**（正文 ≤ 200 字，所有渠道相同）：问候 → 今天最重要的一件事 → 队伍昨天做了什么（≤ 2 条）→ 三件事 → 出口。
- **不放**：拒信原文和数量、与被拒有关的字样（预览和邮件提醒同样）、身份限制的概括句、`sensitive` / `restricted` 记忆、身份日期、付费内容。投的每日汇报、周报草稿一句带过。

```
墨 · 晨报 · 10 月 8 日 周四

早。你收藏的两个后端 new grad，投昨晚备好了材料包，在待确认。
今天最重要的是第 2 件：订单服务那个故事，下周一的面试会用到。

1  看 Ramp 那份材料包            10 min   投
2  讲顺「订单服务限流」           30 min   前
3  练一道 behavioral（英文）      15 min   面

今天不想做也可以，回我一句就行。                  墨 · AI 主理人
[就这三件]  [换一件]  [今天不想]
```

- [就这三件]：变为 `accepted`，按钮换成 [做完 1] [做完 2] [做完 3] [挪一件到明天]（10 §3.5）。[换一件]：先选换哪件，再给 ≤ 3 个替代；当天最多换 3 次（假设）。
- [今天不想]：当天不再出现任务类内容，只回「好，今天不提了。」并给 [歇 1 天] [歇 3 天] [歇 7 天]。暂停期间默认保留面试和截止提醒，回复里列出保留了哪几类并给 [都关掉]；其他主动消息停发（02 §9.3）。

**`pickTodayThree` 规则**（单元测试覆盖）

1. 先放硬约束：48 小时内的截止、72 小时内面试的准备。
2. 其余按阶段从已上线队员的候选里挑，同一位最多 2 件；只放免费或「已包含」的内容（06 §7）。
3. 总时长 ≤ 每日预算：默认 90 分钟（假设），可改；焦虑型用户按 02 §2.3 的决策表收紧。
4. 覆盖：2.7 完整流程的被拒后 48 小时最多 1 件轻量的（`saved`、`applied` 的结束不触发）；危机后 72 小时不出，除非用户主动要。
5. 昨天没做的可以再出现一次，不加「昨天没做」标签；连续两天没做的回到候选池。
6. 每件事链接到一个动作（待确认、面试间、请某位队员），动作完成即自动标记完成。

**今天页**（`/today`；宽屏时部分区块进右侧指挥台，布局见 08）

| 区块 | 内容 | 空状态 |
|---|---|---|
| 晨报 | 今天的信，折叠成两行；简版标「简版」 | 「明早 9:00 是第一封晨报。」 |
| 三件事 | 待做 / 做完 / 挪到明天 / 不做了；「加一件我自己的」 | 「今天没有安排。想做点什么，在小组里跟墨说；休息一天也行。」 |
| 今天的日程 | 面试、截止、用户设的提醒；等宽时间，显示双时区 | 不显示 |
| 待你确认 | 数量和最早截止，[去确认] | 「没有要你确认的东西。」 |
| 队伍动态 | 过去 24 小时：印章 + 一句话 + 时间（「投 · 备好 2 份材料包 · 23:10」） | 「队伍今天还没动静。」 |
| 本周你做了什么 | P0 三格：练了几题、改了几个故事、确认了几份材料（「联系了几个人」P2 加） | 「这周还没有记录。」 |
| 身份时钟 | P0 只原样显示录入的日期，没有倒数和进度条；P1-3 起倒数默认关，在「我 → 身份时钟」打开；脚注「信息与提醒，不是法律意见」 | C5 跳过或不想说时整块不出现，不提示录入 |

**身份时钟提醒**（P1-3；`identity_reminder`，例外）：只按用户录入的日期和他自选的提醒点触发；默认提醒点上线前须移民专业人士审核。节点：program end、OPT 起止、STEM OPT 结束、待业天数（按用户确认的 `unemployment_days_reported` + `reported_at` 顺延，计数默认不显示）、H-1B 注册季（cap 抽签注册通常在每年 3 月；只对有已接受 offer 且开启的用户）、自定义节点（「DSO 说的 STEM 延期递交日期」）。文案是服务端模板，天数由服务端计算，模型不改写，例：「你录入的 OPT 结束日期是 2027-09-30，还有 90 天。OPT 相关的时间安排请和 DSO 确认，要我把要问的问题列一下吗？」具体政策时间不写成规则；不写「还剩多少天可以待业」「来得及」「超限」；Discord 只说「有一个你设置的日期提醒」。

**失败与边界**

| 情况 | 处理 |
|---|---|
| 到点没生成好 | 再等 15 分钟；仍失败发简版（`generated_by='fallback'`）：固定模板加三件事，不调用模型；规则也失败就沿用昨天没做完的。绝不发报错信 |
| 送达失败 | 通知 outbox 按租约重试；最终失败留在网页，不换渠道补发 |
| 时区变化 | 以「我 → 偏好」为准；浏览器时区连续 2 天不同，问一次 |
| 连续 3 天没打开 | 按 02 §9.3 第 4 天问一次「要不要我隔天来一次？」 |
| 当天有面试 / 暂停期内 | 晨报第一句写面试，三件事只围绕面试 / 不发晨报；两种情况下面试和截止提醒都照发 |
| 例外超过 2 条 | 按 02 §9.2 的优先级保留，挤掉的并进次日晨报；同一天多场面试合并成一条 |

**验收**

- [ ] 同一自然日占额度的主动消息 ≤ 1，跨渠道合计（单元测试）。
- [ ] 晨报不含 `sensitive` / `restricted` 内容、身份日期、身份限制概括句和被拒字样（校验器与字符串测试）；生成失败时只有简版或什么都没有。
- [ ] 三件事不超预算；被拒覆盖内最多 1 件；点「今天不想」后当天没有任务类内容，面试和截止提醒照发。

申请问题   3 题 · 1 题需要你自己回答（work authorization）
依据       蔓藤方法 · 简历与 JD 差距分析 v1 · 你确认的故事 2 个
[确认这一版]  [改一下]  [不投了]                      [稍后再看]
```

- **逐句来源**：生成时服务端给 cover letter、申请回答、简历改动的每一句标来源（档案字段、故事 id、简历版本段落、JD 原句）。载荷加 `claims[]`（文本区间与 `source_refs`），校验纯函数放 `packages/career-core/src/pending/`。
- **原稿里没有的事实**：找不到来源的句子用 `--warn` 下划线标「这句找不到依据」（08），逐条 [保留] [删掉]，保留即视为用户本人确认；处理完之前「确认这一版」不可用，旁边提示一次。
- **身份类申请题**（sponsorship、工作授权、公民身份、EEO）：`answer_source` 只能是 `profile_confirmed`（服务端从用户亲手确认的档案字段确定性填入，注明确认日期）或 `user_required`（「需要你自己回答」，不预填），不能是 `model_draft`。投的上下文里只有占位符；校验函数拒绝模型生成的这类答案。
- **JD 身份限制**（`sponsorship`）三个取值：`explicit_no`（明确不担保，或要求公民、U.S. person、ITAR、clearance 的原句）、`explicit_yes`、`unknown`。服务端关键词规则（citizen、U.S. person、ITAR、clearance、sponsorship、work authorization 等）定位英文原句并校验是 JD 原文子串；显示原句和查看时间。没找到写「没找到相关原句（10/07 查看），提交前请自己扫一眼」，不写「未提及」。

### 2.5 面试间

**入口**：小组里 @面「练一道」；三件事；作战简报 [开始第一轮]（P1-4）；旅程的面试详情；`/interview/new`。一个练习会话对应一个 `interview_room`（03 D2），同一事务创建；每个回答作为会话消息由轮次服务写入，先过分级器。小组里只出现「面试间 · 进行中」和结束后的小结卡。

| | 逐回合（P0） | 实时（P1-11） |
|---|---|---|
| 怎么说话 | 英文题面 + 朗读 → 按住说或打字 → 转写 → 追问或下一题 | 全屏实时通话，可打断（OpenAI Realtime + WebRTC + semantic VAD） |
| 上下文 | 记忆、故事库、题目流、历史 | 服务端下发指令、固定声线和题目计划，只用 `normal`（12 §5.1） |
| 暂停与计时 | 「暂停，去小组」常驻；正计时，可隐藏 | 「暂停，用中文问一句」；倒计时（08） |
| 时长 | 按题 | 每次 10 分钟、每小时 4 次（`/voice/session` 路由的现有限制） |

声线唯一来源 `PLATFORM_INTERVIEWER_VOICE`，两种模式一致；主理人的声音不进面试间。任何 AI 声音第一次播放前弹出 12 §6.1 的说明；标题区始终显示「AI 声音」。

| 步 | 界面 | 示例 |
|---|---|---|
| 1 设置 | `/interview/new`：题型（behavioral / 项目深挖 / SQL / 统计与 ML 概念 / product sense）、目标公司（可选）、题数（默认 3，假设）、「每题后反馈 / 结束后再看」 | 「面试间只用英语。复盘可以用中文。」 |
| 2 设备检查 | 麦克风权限，试说一句 | 「说一句 Hello，我看看能不能听清。」 |
| 3 出题 | 英文题面大字、朗读、正计时 | "Tell me about a time you had to make a decision without complete information." |
| 4 作答 | 按住说或打字；单段 120 秒（产品假设，前端限制，到时提示并分段）；转写可点「转写有误」修正 | — |
| 5 追问 | 0–2 个（题库 `follow_ups`） | "What would you do differently now?" |
| 6 每题小结 | 做得好一行 + 最该改一行 | 「结果没说出来。上线后效果怎样，用你自己的数字补一句；不知道就说不知道。」 |
| 7 复盘 | 每题一张卡，见下 | — |
| 8 回到小组 | 小结卡（不推送） | 墨：「面说你第二题比上周清楚：2:48，上次 4:05。」[存进故事库] |

```
Q2 · Behavioral · decision without complete information
你的回答   2:48（上次同类题 4:05）                 [看转写]
评分（蔓藤 rubric v3）
  Situation 清楚 3/3 · 你本人做了什么 2/3（"we" 9 次，"I" 2 次）
  结果 1/3（没说上线后的效果）· 长度 2/3
做得好   不确定的地方说得很具体。
最该改   最后一句补上结果。用你自己的数字，不知道就说不知道。
[再练这一题]  [存进故事库]  [我不同意]
```

**复盘规则**

- 默认用中文，引用原句保留英文；可切到英文复盘。评分只描述这一次，不说通过概率；rubric 标版本，没有时标「通用」（04 §3.2）。
- 复盘和「更好的说法」只用用户这一次回答里的经历和数字；缺的地方留空位，不从记忆、故事库或别处补。存进故事库前由用户确认（2.16）。
- 「我不同意」P0 先记在这一题上，P1-4 起进审核队列（04 §3.2）。AI 评分记 `practice_review`、`verification = self_reported`，按 `careerProgress` 只算暂记；真人导师评阅后才算确认（`packages/career-core/src/progress.ts`）。只和自己的上一次比。
- 只存转写，不存音频（`audio_retention = none`）；不做说话人识别、不存声纹（12 §6.2）。

| 情况 | 处理与文案 |
|---|---|
| 麦克风不可用 | 「没拿到麦克风权限，我们先用打字练。」附开权限说明 |
| 转写失败 | 「这段没听清，再说一次，或者改成打字？」不计入评分 |
| 用中文作答 | 面试官英文拉回："Let's keep it in English — take your time." 复盘标「这题用了中文作答」，不评表达分；坚持先理思路：「可以先回小组跟前辈用中文理一理。」[暂停，去小组] |
| 实时断开（P1-11） | 5 秒内退到逐回合，声线不变，已说的保留 |
| 实时到时或次数用完（P1-11） | 第 8 分钟提示「还有 2 分钟」，到时直接复盘 /「这一小时的实时练习次数用完了，一问一答不受限制。」 |
| 关掉页面 | 已完成的题和转写已保存：「上次练到第 2 题，接着练还是看复盘？」 |
| 「我在真实面试，帮我答」 | 「面试间只用来练习，真实面试里我不能帮你答。面完我们一起复盘。」 |
| 危机信号 | L2 立即结束练习，回到小组发模板和资源卡；实时模式按 12 §5.1 |

**验收**

- [ ] 题面、追问、面试官的话全是英文；转写语言为英文（第 5 节）；每个回答都经过分级器。
- [ ] 复盘不出现这次回答以外的经历与数字（评测集）；每题有 rubric 来源；「你一定能过」类表达 0 次。
- [ ] 不存音频；（P1-11）实时断开后 5 秒内退到逐回合，声线不变。

### 2.7 被拒之后

**入口**：旅程里把投递改为「已结束」；小组里说「被拒了」；粘贴拒信。

**哪些结束会触发**：只有 `closed_reason ∈ {not_advanced, rescinded}` 且 `closed_at_stage ∈ {oa, interview, offer}` 走完整流程。`saved`、`applied` 阶段的结束，以及 `no_response`、`role_closed`、`withdrawn`、`declined`，只静默归档：移到「已结束」，下一封晨报一句带过（「Acme 那份申请结束了，已经归档。」），不进 `post_rejection`，不写信。

| 步 | 时间 | 界面与文案 | 分期 |
|---|---|---|---|
| 1 即时回应 | 立即，`ConversationTurns.post()`，**不推送** | 按性格的一两句（02 §14.4）。墨：「收到。走到终面，说明简历、OA、技术面都过了。今天不复盘，明天想聊再聊。」 | P0 |
| 2 看板 | 立即 | 「已结束 · 这一轮没走下去」，记 `closed_at_stage`；不用红色，不出现 Rejected，不统计累计数量 | P0 |
| 3 覆盖 | 48 小时 | 与看板变更同一事务写 `overlays`（`post_rejection`）：温度 +1、推进力 −1；不发任务类主动消息；24 小时内不复盘；不出现付费建议 | P0 |
| 4 信 | 下一个晨报时间，取代当天晨报（`rejection_letter`，占额度）；三件事（≤ 1 件，可选）以任务卡附在信后 | 见下；同一用户 7 天内最多 1 封，多家合并、逐家点名、不写总数 | P1-5 |
| 5 复盘邀请 | 满 24 小时后，主理人在晨报里提一次（可选） | 「想复盘 Acme 那一轮的话，面在，15 分钟。」接受后面入场 | P1-5 |
| 6 复盘 | 面 + 面经（方法卡 `rejection.review`）；一个能改的点进下一次三件事；之后才可能邀请匿名贡献 | — | P1-5 |

| 情况 | 处理 |
|---|---|

### 2.8 给爸妈的周报（P1b · P1-8；用户完全控制内容）

| 4 下周 | 连续两周删掉同一类段落，第三周默认关掉并告诉用户 | — |

| 情况 | 处理 |

| 关闭功能 | 立即停止；已有草稿保留到用户删除 |

**验收**：[ ] 默认关闭，关闭时不生成草稿，代码里没有发送周报的路径。[ ] 草稿里没有身份日期、被拒信息、身心状况句、`sensitive` / `restricted` 内容（上下文组装与评测测试）。

### 2.9 Offer 那天与落地（P1b · P1-13）

**入口**：旅程里把投递改为 Offer；或在小组里说「拿到 offer 了」。口头 offer 记 `offer_state = verbal`。

| 多个 offer | 比较表只在网页；条款不进 Discord、周报和年鉴分享版 |

### 2.11 回流用户（中断一周后回来）

**定义**：距用户最近一次主动发消息或操作满 7 天（假设）后的第一次回来。

你不在的这 9 天

### 2.13 投递授权对话与插件投递（P1a · P1-1）

授权清单、问法、底线和代码改动以 11 为准；授权记录、一份申请的完整流程和回执以 03 §10 为准。这里只写用户看到的部分。没装插件时材料包只有 `user_sends`。另有「页面直填」入口（11 §4.1）：只用已确认的档案和简历版本，看板新建「已投（自己找的）」，不计入每日上限。

**A. 投递授权对话**

**入口**：第一次需要插件投递前，由投在网页小组里发起，主理人在场：用户第一次说要投、第一次点「确认这一版，交给插件」，或第一次连上插件时（11 §4.1）。还没确认时插件照常填普通字段，所有授权项留给用户，浮层顶部一行「投递授权还没确认，代勾和代签都留给你 · 去小组里确认 ›」，不弹窗、不拦填写。

| 步 | 界面 | 规则 |
|---|---|---|
| 1 开场 | 投的消息 + [现在问] [晚点] | 说明为什么问、约 5 分钟（假设）、点确认卡才生效 |
| 2 分组问 | 每组一条消息挂分组提问卡（08 §7.14），答完一组再问下一组 | 一 申请表里的常规条款（5 项）→ 二 签名与声明（2）→ 三 放弃权利或接受调查的条款（6）→ 四 账号与页面操作（3），问法与后果见 11 §3.2、§3.4。每项只有「可以替我勾」「不要，留给我自己」，不预选、不推荐；组末「这一组都可以」只是一次填好这一组 |
| 3 照资料作答 | 同一次对话 | EEO、标准工作授权与 sponsorship、能否联系现雇主：用户逐项给答案（EEO 可选「不愿透露」），确认后存进档案（11 §3.3） |
| 4 底线 | 投一段话，不需要回答 | 无论怎么选都不做的事（11 §5.1），如替你点最终提交 |
| 5 确认卡 | `apply_authorization` 待确认（03 §9.1），样式见 08 §7.14 | 逐项列出四组 16 项和照资料作答的答案，[确认这些授权] [改一下]；点了才生成授权记录（来源 `web_chat`）。卡面任何一项改了，旧卡作废、重出一张 |

> **投**：开始替你填申请表之前，先问清表上的条款哪些我可以替你勾、哪些留给你。分四组，问完出一张确认卡，你点了才算数；之后填表时我不再打断你。
> **墨**：这些没有标准答案，按你自己的想法选。
> （第一组的分组提问卡；林舟点 [这一组都可以]）
> **林舟**：第三组，仲裁和放弃集体诉讼都不要，其他可以。
> **投**：我按你说的点好了：仲裁协议、放弃集体诉讼和陪审团是「不要，留给我自己」，背景调查、面试录音、AI 评估面试、申请相关的短信电话是「可以替我勾」。对的话看下一组，不对直接改按钮。

- 用户用自己的话回答时，投把理解的结果点成按钮状态请他核对；聊天里的文字本身不改授权，只有确认卡改。
- 中途离开：已答的留在对话里，回来接着问；确认卡之前什么都不生效。

**补问**：插件每次填完上报没有记录、文案版本对不上、对应不到问题的项（不带原文）。投攒在一起，在投递汇报之后一次问完，出一张只含这几问的确认卡；同一批一天最多提醒一次；用户选了「不要」的项不补问（11 §4.4）。

**修改**：用户在小组里说「以后仲裁别替我勾」，投回一张只列改动项的确认卡，点了才生效。「我 → 投递授权」（`/me/apply-consent`）可以查看每项的回答和确认时间、逐项修改，改完同样出确认卡（来源 `web_settings`）。撤回只影响以后的申请，正在填的那一份不变。插件里只读，「改授权 ›」跳回网页小组。

**Discord**（P1-2）：只收「有 N 项需要补问」的提醒和回网页小组的链接；只能收紧（改成「不要」，来源 `discord`）；改成「可以替我勾」的确认卡只在网页小组确认（10 §3.7）。

**B. 一份申请经插件投递**

| 步 | 在哪 | 界面与文案 |
|---|---|---|
| 1 选最后一步 | 待确认详情 | 已连接插件且网站受支持：[确认这一版，交给插件]，次按钮 [我自己投]。没装：只有 [确认这一版]，下面一行「装上插件，重复的表格可以替你填。」（插件发布前不显示） |
| 2 填写 | 插件 | 只用确认的那一版，按授权记录全部自动，填写中不弹任何授权提问。「不要」、没有记录、版本对不上的项不碰，在页面上高亮成「留给你」；这一页有「留给你」时不翻页，顶部「这一页有 N 项留给你」，用户处理完点「继续自动填写」（11 §4.7，样式 08 §10.3） |
| 3 提交 | 浮层或网站按钮 | 永远由用户本人点。浮层的提交卡列出这份申请里替你勾了什么、依据哪一问；有代签时第一行「属实声明和签名是替你签的」；还有「留给你」的项时写明几项（11 §4.5） |
| 4 回执 | 本机存原文快照，后端只存摘要 | 四块：替你同意了、替你拒绝了、留给你自己的（写明原因）、替你注册或登录的网站（08 `ApplyReceipt`） |
| 5 回到小组 | 群里 | 投每天一条汇报（11 §4.6），不推送、不占额度、不镜像到 Discord；有补问时接在汇报后；晨报一句带过 |

| 情况 | 处理 |
|---|---|
| 浮层里点提交 | `sent`（`extension_receipt`），看板「已投」，`application` 证据 `user_confirmed` |
| 用户在网站页面上自己点了提交 | 浮层和看板上的按钮写「我已投」，点后记 `self_reported`（03 §10.3） |
| 用户在页面上改了确认版本里的内容 | 允许，记 `sent`（`extension_receipt_modified`），回执带 `page_edits_count` 和改动的字段名，写「你在页面上改了 2 处」；成长证据仍记 `user_confirmed`（03 §10.3） |
| LinkedIn、Indeed Apply | 插件不操作（11 §5.1）；只能 `user_sends`：「这家要你在 LinkedIn 上自己点」 |
| 验证码、单点登录、账号被锁 | 交还用户；投在汇报里写清要做什么 |
| 中途失败或放弃 | 材料包保持「已交给插件」，可以下次再填或 [我自己投] |
| 每天的量 | 材料包路径受 03 §9.7 的上限；批量预填 P2 |

**验收**：[ ] 除用户本人点击外没有任何路径触发最终提交（以 11 的测试为准）。[ ] 插件填写中不出现任何授权提问；聊天文字不改授权，只有确认卡改；Discord 只能写「不要」。[ ] 分组提问卡和确认卡不预选、不出现「推荐」。[ ] 每份经插件提交的申请都有回执，摘要能在小组和看板上找到，页面改动都记在回执里。

### 2.16 旅程页与故事库（P0-9、P0-4）

**旅程页**（`/journey`；组件 `JourneyBoard`、`ApplicationCard`、`InterviewRow` 见 08）：现在的重心（1.2）；方向卡（标「暂定」和复看日期，`exploring` 写「还在比较」）；看板（桌面按 3.1 分列，「已结束」默认折叠、颜色中性；手机用分段控件加分组列表）；面试；故事库；简历版本；真人服务（2.15）；身份时钟（只原样显示）。

**收藏岗位**

| 方式 | 处理与字段 |
|---|---|
| 贴 JD 文本（默认） | 看板 [收藏一个岗位] 或在小组里贴；投抽出公司、岗位、地点、截止，用户核对后保存。`source='manual'`、`state='unknown'`，标「你贴的 JD · 没核实是否还开放」，不做关闭检测 |
| 贴链接（P0 后段可选） | 只读 Greenhouse、Lever、Ashby 的公开页，一次可贴多条，走服务层内部调用、学生端无审批。成功：`source` 取该站、`state='observed_open'`、`checkedAt`，标「实际页面观察 · 10/07 查看」；失败：「这个链接我读不了，把 JD 文字贴过来就行。」 |
| LinkedIn、Indeed 链接 | 只存不抓（11 §5.1），请用户贴 JD |

- 字段：公司、岗位、链接、JD 原文、地点、截止（带时区）、`role_family`（投建议，用户可改）、私有备注、`sponsorship` 与命中原句（2.4 的规则，贴文本同样跑）。
- 去重：同一 `canonicalUrl`，或公司加规范化岗位名相同：「这个岗位你 10/05 收藏过了。」[打开那条] [还是新建]。
- 旧四种状态：「搜索发现」= `CareerJobsPort.search` 的结果（P2）；「实际页面观察」= 读取成功的 `observed_open`；「仍可核实的岗位」= `observed_open` 且 `checkedAt` 在 7 天内（假设）；「适合你」不是字段，由用户收藏表达，队员只给有依据的理由，不打分。

**阶段变更**：只有用户点（卡片 [改阶段]，文案按 3.1）或用户点击产生的回执能改；改为「已结束」时选一个中性原因，`closed_at_stage` 自动记下，按 2.7 分级。队员的提议显示成卡片上一条小条：「投 提议：改成 OA？」[是] [不是]。

**故事库**（`/journey/stories/:id`）

- 来源：前辈在对话里整理一段经历（evidence-story）→ `proposed`，小组里一张「存成故事？」[存] [先不]；面试间 [存进故事库] → `draft`，用这次转写作素材；用户 [新建故事] → `draft`。
- 状态：`proposed`（用户还没看）→ `draft`（接受了，在改）→ `confirmed`（用户点 [确认这个故事]）。只有 `confirmed` 计入阶段 3 退出条件，能被材料包和简报引用；改已确认的故事生成新 `revision`，需再确认。
- 故事卡：标题、STAR 四段、题型标签（ownership、ambiguity、conflict 等）、练过几次、最近用时（来自练习记录）、关联证据；英文版为主、中文版供理思路，宽屏两栏、手机切换。
- 数字和结果只能由用户填写或确认；队员起草时缺数字就留空位。

**简历版本**：显示 `track`、`label`、状态（`draft` / `active` / `archived`）、来源和血缘。**上传或粘贴的原稿可以直接确认为第一个可用版本**：生成「原稿 v1」的 `resume_version` 待确认，用户确认即 `active`；文字抽取失败时请用户粘贴。

空状态：看板「还没有收藏的岗位。贴一段 JD 就能开始。」；故事库「还没有故事。和前辈聊一段经历，或者在面试间练完后存一个。」；简历「还没有简历。上传一份，或者贴文字。」

**验收**：[ ] 只有用户请求或用户点击产生的回执能写阶段历史（接口测试）。[ ] `source='manual'` 的岗位在任何界面都不出现「已关闭」；身份原句都是原文子串。[ ] 只有 `confirmed` 故事进入材料包和简报；原稿确认后可直接用于材料包。
