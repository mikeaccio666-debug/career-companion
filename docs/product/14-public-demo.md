## 1. 这份演示要达到什么

### 1.1 给谁看，看完记住什么

一句话记忆点：**一个你起名的主理人，背后一支 AI 队伍；它们做事，你做决定。**

| 谁 | 多半从哪来 | 看完要记住的 | 最该看的幕 |
|---|---|---|---|
| 在美中国留学生（STEM 硕士、找 new grad） | 微信群、Discord 群里的链接，手机打开 | 只用记一个名字；要发给别人的东西先给你看，最终提交永远是你自己点；被拒那天它先问你想聊还是想歇 | 初见、待确认、被拒之后（诞生后的分叉或「3 分钟看重点」） |
| 家长 | 孩子转发到微信 | 孩子不是一个人扛；它不替孩子乱投，不编造经历；跟爸妈说什么由孩子决定 | 家长说明页 `/parents`，再看被拒之后、待确认、周报预览 |
| 合作导师机构（蔓藤） | 产品负责人直接发 | 真人导师、授权题库与评分标准在体验里的位置；品牌在书面同意前不出现；不卖内推 | 面试间（旁注里的真人入口与评分标准出处） |
| 投资人 | 产品负责人直接发，多在电脑上看 | 关系加队伍的结构；难以照搬的机制（共享记忆与交接便条、逐句标来源、逐项授权与回执、授权内容）；首批是真实用户而不是演示 | 导览 `/tour`（四站，约 3 分钟，3.0.4） |

按顺序全程约 6 分钟（假设，按第 8 节实测），每一幕都能单独打开。学生从微信点开多半只有 2–3 分钟，所以诞生后的幕尾卡给出分叉，目录里有「3 分钟看重点」路线（初见 → 待确认详情 → 被拒之后 → 结尾）：这段时间里至少要看到诞生加一个后半段的幕。

### 1.2 不做什么

- 不接任何模型，不能自由聊天：访客扮演林舟，通过「你（林舟）」的选项推进；手机上不显示输入框，宽屏的输入框只读（3.0.1）。
- 不建账号，不设 cookie，不把访客起的名字和答案发出浏览器；访问统计只记打开了哪一页。
- 不展示价格、付费推荐、服务卡和内推；不演示危机流程，不放资源卡。
- 不出现蔓藤的名字与品牌、真实公司、真实学校、真实人物；不演示规划师、技能教练、人脉官（P0 只有主理人、前、投、面）。
- 不给任何身份、签证的数字结论，不倒数。
- 不承诺上线日期和结果，不写「上岸率」；P1 的功能标「之后的版本」。
- 不做英文版（首版）；简历、面试题和面试回答照真产品用英文。
- 不是首批招募入口；候补名单开不开、谁保管，公开发布前必须定（待确认 6）。
- 不替代真产品的隐私政策和用户协议；演示只有自己的隐私说明（第 7.5 节）。

## 3. 演示脚本

### 3.0 共用约定

#### 3.0.1 演示外壳

- **演示条 `DemoStrip`**：每一页最顶上，吸顶，`min-height` 32 加顶部安全区，放不下时（200% 缩放、系统大字）折成两行；`--tint` 底，12/18 `--ink-2`；左边固定文字「演示 · 对话为预先编写 · 数据为虚构」，右边等宽幕号「5 / 11」和「目录」（< 640 时只留图标，`aria-label="目录"`）。幕号同下表（落地页算第 1 幕）；子路由沿用父幕的号（`/pending/resume-v2` 是 6，`/end/parents`、`/end/discord` 是 11）；`/privacy`、`/parents`、404 不显示幕号，只留「目录」；导览写「导览 2 / 4」。`role="note"`，在 DOM 里是第一个可读元素，不可关。
- **幕标题与旁注 `SceneCaption`**：内容区第一行，**随内容滚走、不吸顶**；12/18 `--ink-3`：「第 5 幕 · 对话与单聊」（`h1`，`tabindex="-1"`）加文字按钮「关于这一幕 ▾」。展开是 `--tint` 底、13/20 `--ink-2` 的旁注（文案见各幕「演示标注」），末尾是分期标签；一幕有两种分期时放两枚，各带前缀（3.8）。导览里默认展开，并多一行「为什么这样做」（3.0.4）。落地页没有 `SceneCaption`。不写上线日期。
- **目录 `SceneIndex`**：底部抽屉（宽屏是弹窗）。最上面一个按钮「3 分钟看重点」（初见 → 待确认详情 → 被拒之后 → 结尾）；然后十一幕（标题、一句话、分期标签，见下表）；最后「外观：跟随系统 / 浅色 / 深色」、「一次显示全部消息」开关、「重新开始」。
- **幕尾卡 `SceneEndCard`**：每幕最后一张，`--tint` 底、圆角 8、内边距 16：一句「这一幕你看到了：……」（各幕给出），主按钮「下一幕」，上方 13px 写下一幕的名字。走重点路线时按钮写「下一站」，去路线里还没看过的下一站，都看过就到结尾，另有文字按钮「回到按顺序看 ›」。初见的幕尾卡是分叉（3.2）。它是外壳，不是队员说的话，没有印章。
- **「你（林舟）」选项 `ScriptChips`**：访客扮演林舟发言的地方，样式同 `QuickReplies`（08 §7.4），上方 12px `--ink-3`「你（林舟）：」；点后作为林舟的用户气泡出现。可访问名「你（林舟）说：……」。
- **输入框**：手机上不渲染 `Composer`；底部这一块由 `ScriptChips`、`QuickReplies`、外壳按钮或幕尾卡轮流占用，有人说话时留空。宽屏照 08 显示只读 `Composer`，占位符「演示里不能打字，点上面的选项继续」，不显示附件、语音、斜杠命令和「停下」。不用 `MentionPicker`（叫名字不需要 @，03 §4.4）。
- **手机的竖向空间**（微信内置浏览器 390 宽的可视高度约 650–700，需实测）：吸顶的只有 `DemoStrip` 和 `RoomHeader`（整页幕是顶栏）；对话幕（主线、单聊）里 `BottomNav` 隐藏（与 08 §7.13「输入框聚焦时隐藏」同理），今天、待确认、旅程照常显示。

## 4. 起名与性格变体的规则

### 4.1 三道情境题与映射

题目和选项取自 02 §2.3 的 Q1、Q2、Q7，文字不改；每题可跳过。

| # | 题目 | 选项 → 变体 |
|---|---|---|
| 1 | 周日晚上十点，你发现这周计划投的 10 个岗只投了 3 个。你最希望身边的人—— | A 先别提，让我缓一缓 → 暖；B 帮我把剩下的拆成明天能做完的两件 → 稳；C 直接告诉我这周时间花哪去了 → 直；D 陪我吐槽两句，然后再说 → 暖 |
| 2 | 你把简历发给朋友看。你更想收到哪种反馈？ | A 先说哪里好，再说一个最该改的 → 暖；B 按优先级列出全部问题 → 稳；C 一句话：能不能投，不能的话卡在哪 → 直 |
| 3 | 正着急的时候，有人开个玩笑，你通常觉得—— | A 挺好，能松口气 → 暖；B 看时候 → 稳；C 正事别开玩笑 → 直 |

**怎么定变体**（纯函数，单元测试覆盖下面的例子）
1. 每道答了的题给一个变体投一票。
2. 票数最多的变体胜出。
3. 平票时，第 2 题投的变体在平票之列就取它；否则取稳。
4. 一题都没答，或在开场选了「赶时间，用默认的」：稳。

例：B/B/A → 稳；A/A/C → 暖；C/C/B → 直；A/B/C → 稳（平票，第 2 题投稳）；A/C/跳过 → 直（平票，第 2 题投直）；跳过/跳过/A → 暖。

## 6. 必须守的线

设计负责人的决定逐条落成可检查的规则。任何一条不满足都不上线。

### 6.1 不接模型、不建账号、不存访客数据

1. 页面运行时只向本站发请求（静态资源）、访问统计的上报地址、候补名单的提交地址（开启时）。用 7.1 的 CSP 限死，没有任何模型或第三方接口。

3. 不设 cookie：页面不写 `document.cookie`；托管返回的响应里没有 `Set-Cookie`（包括托管方的安全防护 cookie，7.3）。
4. 访客起的名字、三道题的答案、各幕的选择，只在页面内存和 `sessionStorage`（3.0.5）；不进网址、不进访问统计、不进候补名单、不进日志；字体和字形包都不按字取文件（7.7）。
5. 唯一会离开浏览器的访客输入是候补名单里主动填写的邮箱和身份一项（开启时）。

### 7.1 托管与部署

- **推荐 Cloudflare Pages**：静态托管，免费档够用（需核实额度），与 13 §3.2 的维护页、R2 同一个 Cloudflare 账号；演示和维护页是两个独立的 Pages 项目。
- **代码位置**：`apps/demo`（静态站，构建产物写到忽略目录）；不依赖 `services/platform-api`、`packages/ai-core`，不进 `apps/web` 的构建。
- **构建与部署**：不用 Pages 的 Git 集成（它会给每个分支生成公开预览，构建镜像对仓库钉死的 Node 与 pnpm 版本的支持也需核实）。在 GitHub Actions 里按仓库钉死的版本构建（`pnpm --filter <演示包名> build`），再用 `wrangler pages deploy` 直传；部署 job 绑定受保护的 environment，要产品负责人批准，Cloudflare API 令牌只放在这个 environment 的 secrets 里。这样没有分支预览，没批准的版本不上任何公开网址。
- **`pages.dev` 主机**：项目的生产别名 `<项目>.pages.dev` 仍可公开访问，用 Bulk Redirect 301 到自定义域名（需核实）；做不到时至少在 `_headers` 里给它加 `X-Robots-Tag: noindex`。对外只发自定义域名（在微信里也更不容易被拦）。
- **路由**：按 3.0.4 预渲染每个路径，加真正的 `404.html`，不配单页回退。
- **`_headers`**：
  - 全站：`Content-Security-Policy`（下面）、`Strict-Transport-Security`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`Permissions-Policy: camera=(), microphone=(), geolocation=()`；收录没开放时加 `X-Robots-Tag: noindex`（7.2）。
  - 缓存：`/assets/*`（文件名带内容哈希的脚本、样式、字体、印章字形包）`Cache-Control: public, max-age=31536000, immutable`；HTML 和 `/og/*` 用 `Cache-Control: no-cache`。Pages 的默认缓存行为需核实。
- **CSP**（统计 beacon 的网址按实际接入方式核实；走本站 `/cdn-cgi/rum` 时去掉两个外部主机）：

  ```
  default-src 'self'; script-src 'self' https://static.cloudflareinsights.com; connect-src 'self' https://cloudflareinsights.com; img-src 'self' data:; font-src 'self'; style-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'
  ```

  - 没有内联脚本：首帧前设 `data-theme`、`data-companion-ink` 的那段脚本做成同源外置小文件，在 `<head>` 里同步加载（或用 `'sha256-…'` 哈希放行）。
  - 没有 `style` 属性：预渲染的 HTML 里不写 `style="…"`；印章角度用预设的 class，或在脚本里用 CSSOM 设 CSS 变量。
- **不注册 Service Worker、不放 manifest**：08 和 10 的 PWA、离线外壳是给真产品的；演示一旦被缓存，下线页就到不了打开过的访客。

### 7.8 可访问性

- 目标 WCAG 2.2 AA；对比度按 08 §2.5 的 token（文字 ≥ 4.5:1，非文字 ≥ 3:1），含深色和 `prefers-contrast: more`、`forced-colors: active`。
- `<html lang="zh-CN">`，英文段落（简历、面试题、回答、授权英文原文）加 `lang="en"`；有「跳到内容」链接；演示条是第一个可读元素。
- 主线和单聊的消息流 `role="log"`、`aria-live="polite"`，转发卡是带 `aria-label`「转自前辈，AI」的 `article`（08 §7.1）；`TypingIndicator` `role="status"` 只播报一次；确认仪式、授权确认、提示条用 `role="status"`；面试间新题播报题目。
- 换幕后 `<title>` 随之更新，焦点移到幕标题（3.0.4）；叠层用返回键或 Esc 关闭后，焦点回到打开它的按钮。
- 全部可以只用键盘完成：快捷回复、转发卡按钮和「你（林舟）」选项是按钮；授权每项是 `fieldset`，按钮带 `aria-pressed`；回车不触发隐式提交。
- 触屏点击区 ≥ 44×44；不靠悬停；颜色从不单独表达含义。
- 没有时限：队员发言的节奏不会让内容消失，可以「一次显示全部消息」；减少动态时所有仪式改为 150ms 淡入。
- 示意框（插件、Discord）里的内容是真实文字，不是图片；框本身有 `aria-label`（「示意：插件在申请页上的样子」）。
- 走查：iOS Safari 加 VoiceOver、安卓 Chrome 加 TalkBack、桌面键盘；200% 缩放下手机宽度无横向滚动（含旅程页和插件示意）。

### 7.9 性能目标（假设，上线前实测）

- 落地页首次加载 ≤ 150 KB（压缩后）：界面先用系统字体，兜底子集用 `font-display: swap`、不阻塞首屏，落地页不加载宋体。整个演示（全部十一幕，不含印章字形包）≤ 1.5 MB。
- 印章字形包单列：约 1 MB（需实测），只在起名时懒加载，不计入首屏。
- 手机 4G、美国网络：LCP ≤ 2.5 秒，CLS ≤ 0.1，INP ≤ 200ms。大陆网络、微信内置浏览器：首屏可读 ≤ 5 秒（尽力而为，以实测记录为准）。
- 没有大图和视频；印章、示意框都用 CSS 和文字画；不引入大型前端框架，脚本按幕懒加载。
- 关掉 JavaScript 时，靠预渲染（3.0.4）仍能读到落地页和各幕的标题与说明，并显示「这个演示需要打开 JavaScript」。

### 7.10 更新与下线

- **改内容**：文案、公司名、日期、产品名都在一个内容文件里；改动走 PR，设计负责人看文案、产品负责人批准发布；页脚版本号加一。每次发布前跑第 8 节能自动化的检查。
- **回退**：Pages 保留历史部署，出问题时回到上一个版本（需核实操作方式）；回退后再查原因。
- **定期复查**（每月一次，或以下事件发生时）：律师对「陪伴」「companion」、AI companion 法规的结论（02 §11.4）；律师对 11 §7 的答复（3.9 改用审过的文案）；合作导师机构书面同意使用名称；正式产品名确定；真产品首批开放；发现虚构公司名撞上真实公司。
- **下线**：出现法律或合作方要求、安全问题、或真产品决定取代演示时，24 小时内发布一个只有一句话的页面：「这个演示已经下线。」（需要时加一行正式产品的网址）；下线页自带新的标题、描述和换了名的分享图（HTML 是 `no-cache`，演示没有 Service Worker），但已经发出去的卡片可能被微信、Discord 按网址缓存（需核实），点开看到的是下线页；候补名单按 7.6 导出给保管人后按期删除，并在 `/privacy` 写明。紧急时可以先在 Pages 上解除自定义域名绑定。
