## 这份文档回答什么问题

- 「小组」三种调性怎样收成一套视觉语言；颜色、字体、字号、间距、印章、航空信纹的 token（浅深两套确定值）。
- 核心组件的结构、状态、可访问性和分期；全产品的按钮、状态文案与色调（唯一出处 7.10）、禁用词；现有代码怎么迁移；Discord 里怎样对应。

不展开：组件何时出现、流程和枚举（05）；谁接话、转发与单聊（03 §4）；事件与引擎行为（15）；授权问题内容（11）；声线（12）；Discord 交互（10）。

**结论**
1. 一条主线加每位队员的单聊；内容三种形态：气泡（黑体）、信件卡片（宋体、信纸、航空信纹、印章落款）、任务卡片（等宽数字、状态标签）；队员在主线里只以转发卡出现；旅程页是整页指挥台。
2. 实心印章 = AI 队员；任何一张界面截图里都看得到 AI 标识。真人用 `--air` 实线圈，不用印章。
3. 印章红只有四处用法，负面状态一律不用红；最小字号 12px；仪式动效只有两种，都以服务端确认为准。
4. 用户自己发出的东西按钮写「确认这一版」；「封缄寄出」只给产品真的会送出的对象；「缄」只是动效和图形。
5. 分期以 07 为准：P0 的发言者只有主理人、前、投、面；没上线的队员不出现在任何界面上。
6. 丝滑靠真实进度：1 秒内有反馈，进度短语只说真在做的事；输入框有字是「发送」、空时是「停下」。

## 1. 设计理念

### 1.1 主线、单聊与三种内容

| 形态 | 是什么 | 视觉签名 | 谁能发 |
|---|---|---|---|
| 气泡（对话） | 日常对话 | 黑体；印章头像；细边框 | 主线：主理人、用户；单聊：这位队员、用户；真人导师只在 `mentor_room`（P1-10，03 §11.3） |
| 转发卡（气泡的变体） | 队员在主线里的原话 | 黑体；卡头方印加「转自 前 · 前辈 · AI」；圆角 8；底部 ≤ 3 个按钮 | 已上线的队员（经 `consult`、叫名字、回复卡、单聊结论、投递汇报，03 §4.5） |
| 信件卡片（来信） | 值得记住的时刻 | 宋体；信纸底加阴影；顶部航空信纹；印章落款 | 主理人；例外是真人导师评阅（P1-10） |
| 任务卡片（指挥台） | 要拍板或要看清状态的事 | 黑体；1px 边框、无阴影；状态标签；等宽数字 | 负责的队员或主理人 |

此外有系统事件行、系统通知（7.2）和整页（待确认详情、作战简报、旅程、面试间）。宋体只在信里，等宽只给数字。五个界面：今天 = 信件加指挥台模块；对话 = 对话列表加当前房间（主线或某个单聊）；待确认 = 展开的任务卡；旅程 = 指挥台整页；我 = 列表和设置（区块见 05）。

### 1.2 判断规则

按顺序判断，命中就停：
1. 要用户做决定，或有要看清的状态和数字（对外材料、投递进度、作战简报、回执、Offer 清单、投递授权确认）→ 任务卡片。
2. 第一封信、晨报、被拒之后、Offer 那天、求职年鉴（含落地收尾信）、真人导师评阅 → 信件卡片。其他内容再重要也不写成信。
3. 队员在主线里说的话 → 转发卡（可挂任务卡、题卡）；单聊里队员的话是普通气泡。
4. 房间层面的状态（面试间、后台任务完成、单聊里的危机去处、导师授权）→ 系统事件行；系统层面的提示（额度、订单状态）→ 系统通知。
5. 其余是气泡，可挂附件：快捷回复、记一条卡片、投递授权分组提问、出处标签、资源卡、付费推荐卡。

**每天最多两封信**：晨报加一封事件信；第一封信不计入；被拒之后的信取代当天晨报（02 §9.2）。事件信超出时按「被拒之后 > Offer 那天 > 导师评阅 > 其他」保留；同一天已有 Offer 信时，被拒改为主理人的一条普通气泡，次日晨报再提。由服务端信件调度强制执行（上限见 02 §9.1），有单元测试。给爸妈的周报不是主线里的信：它是 `parent_report` 待确认对象，parents 变体只作 `/pending/:id` 里的预览（7.6），不占名额。

约束：一张任务卡只装一个决定；信里不放对外发出的按钮；队员不写信，主理人在信里只按产物和版本提一句（「前改好了 后端-v3」），不转述队员的话；危机场景（02 §10）只用气泡和资源卡。被拒（触发条件见 05 §2.7）后，P0 是主理人的一条气泡（不推送），P1-5 起是下一个晨报时间的 quiet 信。

### 2.2 语义色的克制用法

- **印章红只有四处**：「缄」字印章（网页 `SealCeremony` 与插件信封 `envelope.ts`）、信件顶边的航空信纹、Offer 信的「贺」字印、面试间录音中的 8px 圆点。网页和插件都用静态检查保证 `--stamp` 只被这些组件引用。
- **负面状态不用红**：被拒、逾期、失败、出错、删除用 `--ink` / `--ink-2` 加文字，要用户处理时用 `--warn`。diff 删除 `--ink-3` 加删除线，新增 `--air-tint` 底。
- **语义色只在状态标签里**：浅底、深字、带文字，不铺色块。`--ok` 与教、`--warn` 与面同值是有意的，靠形状区分。
- **全产品只有一个计数**：「待确认」导航旁的等宽数字，`--ink-2`，只数有截止时间的条目（01 §8.4）；不画圆点，超过 9 也写实际数字。

### 2.5 对比度底线、特殊模式与写法

- 文字（含 12px）≥ 4.5:1；图标、输入框边框、分段控件、焦点框 ≥ 3:1（所以输入框边框用 `--ink-4`）。单元测试读取 token，按 2.1、2.3、2.4 的阈值算对比度和色差，含用户气泡的 on-ink 组合（7.1）。
- `prefers-contrast: more`：`--ink-3` 取 `--ink-2` 的值，`--rule` 取 `--ink-4` 的值。`forced-colors: active`：印章去墨底，改 CanvasText 外框和字；航空信纹隐藏；状态标签加 1px 边框。
- `tokens.css`（路径由 09 定）：`:root` 放浅色值和 `color-scheme:light`；`@media (prefers-color-scheme: dark){ :root:not([data-theme="light"]){…} }` 和 `:root[data-theme="dark"]` 写同一组深色值；`:root[data-companion-ink="<token>"]{--member-companion:var(--companion-<token>)}` 七条；`body` 用 `--paper` 底、`--ink` 字、15px/1.6 `--f-ui`。「我 → 偏好 → 外观」：跟随系统 / 浅色 / 深色。建议用一个 JSON 生成 `tokens.css`、插件 `css.ts`、Discord 十进制色值和对比度测试输入。

| token | 字体栈 | 只用于 | 字重 |
|---|---|---|---|
| `--f-ui` | "Noto Sans SC","PingFang SC","Hiragino Sans GB","Microsoft YaHei",system-ui,sans-serif | 全部界面文字 | 400 / 500 / 700 |

- **最小 12px，没有例外**（印章字是图形，不小于 11px）。同一屏不超过 5 档；手机不缩小字号，跟随系统字体放大；不用全大写英文，不靠字距装饰。
- 中英混排：中文与英文、数字间写半角空格；事件行和进度短语里成员名后加空格（「面 在那边等你」）；中文句用全角标点；公司名、岗位名、OA、OPT、sponsorship 保留原样；`line-break: strict`；根元素 `lang="zh-CN"`，英文段落加 `lang="en"`。
- 数字与日期：数据位 `10/09` 周四；24 小时制，对外事件带时区（`23:59 PT`）；句子里「10 月 9 日（周四）」；时长 `20 min` / 「20 分钟」；进度 `0 / 3`；不写百分比或完成率（01 §7.4）。

## 4. 间距、圆角、阴影、分隔线、图标

- **间距**以 4px 为基准：`--s-0_5` 2、`--s-1` 4、`--s-1_5` 6、`--s-2` 8、`--s-3` 12、`--s-4` 16、`--s-5` 20、`--s-6` 24、`--s-8` 32、`--s-10` 40、`--s-12` 48、`--s-16` 64。页面边距手机 16、≥ 640 为 24；头像与气泡 8；同组气泡 4、组间 16；事件行上下 12；任务卡页眉页脚 8×12、主体 12；信件内边距手机 20/20/14、桌面 24/24/16。点击区触屏 ≥ 44×44，鼠标 ≥ 24×24。
- **圆角**：`--r-xs` 3（小方印、行内提及）；`--r-sm` 4（信件、标签）；`--r-md` 8（任务卡、转发卡、输入框、分段控件、名单行、记一条、资源卡、推荐卡）；`--r-lg` 12（弹窗、抽屉、插件卡片）；`--r-bubble` 14（靠发言者的角 4）；`--r-pill` 999（按钮、快捷回复、日期胶囊）。
- **阴影只有三种**：`--sh-line` `0 1px 0 var(--rule)`；`--sh-paper` `0 1px 0 var(--rule), 0 16px 30px -24px var(--shadow)`（只给信件和确认时抬起的任务卡）；`--sh-overlay` `0 0 0 1px var(--rule), 0 12px 32px -12px var(--shadow)`（弹层、抽屉、弹窗、提示条）。
- **分隔线**：细线 1px `--rule`；粗线 1.5px `--ink` 只用于旅程页列标题和数据表顶边；虚线 1px dashed `--ink-4` **只表示空位和作废**，真人不用虚线。
- **图标**：线性，1.5px 描边，20px（密集处 16），`--ink-2`，可沿用现有图标库；不用插画、叶子、花、星光；表示 AI 用印章；旁边一定有文字或 `aria-label`。

## 5. 印章系统

### 5.1 结构与尺寸

阴文：墨色实底；距外沿 5% 一圈纸色内框线（线宽为边长 3.75%）；一个汉字，宋体 700，字高为边长 48%，几何居中后下移 2%。纸色是所在模式的 `--sheet`。

| 档 | 边长 | 字 | 内框线（距外沿 / 线宽） | 方印圆角 | 用于 |
|---|---|---|---|---|---|
| xs | 20 | 11 | 无 | 3 | 三件事、任务卡页眉、@ 选择器、事件行、队伍动态 |
| sm | 24 | 12 | 1.5 / 1 | 3 | 转发卡头、队伍名单行、手机信件落款 |
| md | 32 | 15 | 1.5 / 1 | 4 | 气泡头像、对话列表的主线行、`RoomHeader`；「缄」 |
| lg | 40 | 19 | 2 / 1.5 | 5 | 信件落款、资料卡 |
| xl | 64 | 31 | 3 / 2.5 | 8 | 我 → 主理人、起名、面试间逐回合 |
| xxl | 96 | 46 | 5 / 3.5 | 12 | 诞生、年鉴封面、面试间实时 |

旋转：头像、列表、资料卡 −3°；小于 24px 不旋转也不画内框线；信件落款在 −6° 到 +2°、偏移 ±2px 内，以信件 id 为种子；「缄」「贺」固定 −6°；旋转不改变布局占位。

### 5.2 形状就是身份

| 谁 | 外观 | 字 |
|---|---|---|
| 主理人 | 圆形印章，主理人墨色 | 生成系统给候选、用户选定（02 §5.3）；不能用规、前、导、教、面、脉、投、伴、缄、贺、蔓、藤 |
| 队员 | 方形印章，队员墨色 | 前、投、面（P0）；规、教（P1b）；脉（P2） |
| 确认动效、Offer 贺印 | 方形印章，`--stamp` | 缄、贺 |
| 真人（蔓藤导师、同期伙伴） | 不是印章：1.5px `--air` 实线圆圈，`--sheet` 底，`--ink-2` 宋体 600 字 | 授权期内的导师用姓氏一字；不具名的导师入口用「导」；同期伙伴「伴」（P2） |
| 用户本人 | 不是印章：`--tint` 圆底，`--ink-2` 黑体 700 | 称呼首字 |

**实心印章 = AI 队员**，用户和真人都不用。「导」只出现在真人圈里。Discord 会把方印裁成圆，所以名字永远跟在印章旁边。

### 5.3 渲染与生成

- `Seal` 参数：`glyphPath`（或 `char`）、`inkToken`（取自该消息的 `speaker_snapshot`）、`shape`（round | square）、`size`、`rotate`。墨底和内框线由前端画，颜色取 CSS 变量，不依赖宋体是否已加载。
- **字形来源由 09 决定。** 推荐：构建时离线从 Noto Serif SC 700（OFL）为《通用规范汉字表》一级 3,500 字生成 SVG path（100×100，无颜色），作为静态资源，脚本放 `scripts/`；运行时只查表（02 §5.3 的候选字本就限于一级字）。Discord PNG 的生成方式和依赖由 09 拍板，或只在诞生、重新刻章时按 (字, `ink_token`) 生成并缓存；队员的 path 和 PNG 进仓库。
- 预览阶段没有字，只画圆形墨底和内框线（02 §2.6）。重新刻章或退休后，历史消息保留旧的字和墨。文件只含一个字和墨色，文件名用不可猜测的 id；打印和 PDF 用浅色值。
- 印章一律 `aria-hidden`；单独出现时（诞生页）加 `role="img"` 和 `aria-label`（「墨的印章，字是墨」）。

### 7.1 对话消息 `GroupMessage`、`SpeakerGroup` 与转发卡 `ForwardCard`

**谁在哪说话**（03 §4）：主线里只有主理人和用户的气泡，队员只以转发卡出现；单聊里只有这位队员和用户的气泡；真人导师只在 `mentor_room`（P1-10，03 §11.3）。

**气泡 `GroupMessage`**
- `--sheet` 底，1px `--rule`，圆角 4 14 14 14，15/24，最宽 min(92%, 36em)，头像 md 印章。用户气泡靠右，`--ink` 底、`--paper` 字，圆角 14 14 4 14，最宽 80%。
- 发言者行：名字 13/500 `--ink-2`，时间等宽 12 `--ink-3`。主理人写它的名字。单聊里队员**每天第一组**写全「前 · 前辈 · AI」，之后只写「前」，悬停或长按显示「前辈 · AI」。信件和任务卡在时间前加类型（「墨 · 晨报 · 08:00」）。
- 单聊里队员的气泡与主理人的相同，区别只在方形印章。真人导师的气泡 1px `--air` 边框，真人圈头像，发言者行固定带「真人 · 蔓藤导师」。
- 分组 `SpeakerGroup`：同一发言者、相邻、间隔 ≤ 5 分钟、中间无事件行，只在组首显示头像和发言者行（每天第一组的全称不受影响）；信件、任务卡、转发卡总是另起一组。
- 来自 Discord 的消息，发言者行末加「· 来自 Discord」。含身份信息的消息加 12px 锁形标记「只在网页显示」（05 C5）。
- 正文：段落、列表、粗体、链接（`--air` 下划线）、行内代码（等宽 13px、`--tint` 底），不渲染标题。**用户气泡（on-ink）**：链接 `--paper` 加下划线；行内代码和 @ 提及用 `color-mix(in srgb, var(--paper) 14%, transparent)` 底、`--paper` 字；进对比度测试。
- 状态：生成中（无闪烁光标；多步的文字依次追加，步间一行进度，7.3）；排队中（生成中发出的用户气泡透明度 .6，下方 12px `--ink-3`「排队中」，并入下一步后恢复，15 §3.5）；已停下（末尾 12px「已停下」）；没说完（已显示的句子保留，末尾 12px「没说完，断了」加 [重试]）；发送中；没发出去（「没发出去 · 再试一次」）；已删除（「这条消息已删除」）。
- **引用回复**：长按、右滑（触屏）或悬停出现的「回复」，可回复转发卡和单聊里的气泡；发出的气泡上方带一行 12px `--ink-3` 引用条「回复 前：保留第一条…」（截一行），由被回复的那位接话（03 §4.1）。
- 消息流 `role="log"`、`aria-live="polite"`；每组是 `article`，`aria-labelledby` 指向发言者；用户气泡读屏前缀「你说」。

**转发卡 `ForwardCard`**（消息 `kind = forward_card`；何时出现见 03 §4.5，生成与校验见 15 §5.3–5.4）

```
墨   我请前辈看看第一屏。                       ← 引子：主理人的普通气泡，≤ 30 字，可以没有
┌ [前] 转自 前 · 前辈 · AI · 10:42      墨给前的交接 ▸
│ 保留第一条「QPS 从 2k 到 9k」。最该改的是第二条：没写规模。
│ 改后 Built a REST API serving ___ daily users  〔原稿里没有〕
│ 简历 后端-v2 已放进待确认                       ← 落点行
└ [看差异]  [去单聊接着改]  [先不]
```

- 结构：卡头（sm 方印；12/500 `--ink-2`「转自 前 · 前辈 · AI」；等宽时间；右侧文字按钮「墨给前的交接 ▸」，有交接便条才出现）→ 正文（15/24，队员这次运行的原话，可内嵌题卡、改前改后对照、清单）→ 落点行（12 `--ink-3`；没有结论写「这次没有结论」）→ 出处标签 → 按钮行（≤ 3 个，`QuickReplies` 的胶囊样式；第一个是这张卡的主动作，最后一个是「先不」一类的出口）。
- 样式：`--sheet` 底、1px `--rule`、`--r-md` 圆角、无阴影、无头像（印章在卡头里），左对齐，最宽 min(92%, 36em)，内边距 12，卡头与正文间 8。队员墨色只在方印上，不做边框、底色或文字（2.3）；和主理人气泡的区别靠「转自」、方印和卡片圆角。
- 引子：一条普通的主理人气泡，紧贴卡片上方（间距 4）；何时有见 15 §5.3。
- 单聊结论卡：同一组件，卡头加「· 单聊」（「转自 面 · 面试官 · AI · 单聊」），正文一句 ≤ 60 字的结论，按钮 [看结论]。投的投递汇报同一天合并成一张，挂任务卡（7.8）。
- 交接便条展开：`--tint` 底、13px、3–5 行，右侧文字按钮「这条不对」（02 §12.2）；展开按钮带 `aria-expanded`。单聊开场顶部用同一样式。

| 状态 | 表现 |
|---|---|
| 准备中 | 卡头先出现（P50 ≤ 1.5 秒，15 §1.1），正文位置是 7.3 的三点加该队员的进度短语 |
| 生成中 | 逐句出现，每句已过校验；按钮行等整张卡通过校验后出现 |
| 部分通过 | 已显示的句子保留，末尾 13px `--ink-2`「后面这段我没组织好，先不发了」加 [重试] |
| 没接上 | 卡头保留，正文一行「前 这会儿没接上」加 [重试]；不生成替代文字 |
| 已停下 | 末尾 12px「已停下」，不出按钮行 |
| 按钮已处理 | 按钮行收成一行 12px `--ink-3`「已选：去单聊接着改」；点「先不」后只剩「先不」 |

可访问性：`article`，`aria-label`「转自前辈，AI」；按钮行 `role="group"`；卡内进度短语 `role="status"`，只播报一次。

### 7.2 系统事件行与系统通知

**`SystemEventLine`**：12/18 `--ink-3`，居中，两侧各一条 1px `--rule`；带 xs 印章；最多一个去处链接（`--air`）；不做气泡、不带头像。只表示房间层面的状态，**没有入场、离场、在场的行**（队员说话一律走转发卡）。文案终稿在本节（以 03 §5.1 为底稿），成员名后加空格，真人名后带「真人 · 蔓藤导师」：

| 场景 | 例 |
|---|---|
| 面试间进行中（主线和面的单聊） | 面试间 · 进行中 · 面 在那边等你 [回到面试间] |
| 后台任务完成时任务卡已滚出视野 | 整理好了 · 3 份项目报告 [看结果]（跳到任务卡，7.8） |
| 危机发生在单聊（模板与资源卡之后，02 §10.3） | 墨 在主线陪你 [去主线] |
| 导师授权开始 / 结束（P1-10） | 李老师 · 真人 · 蔓藤导师 可以看你的交接包，到 10/22 [进导师房间] ／ 李老师 的访问已结束 |
| 诞生、改名、重新刻章、阶段 | 2026 年 10 月 6 日 · 墨 诞生；墨 现在叫 阿墨；墨 换了一枚新印章；进入落地 |

日期是 `--tint` 胶囊，同时是视觉上隐藏的二级标题。

**`SystemNotice`**：服务端按规则生成、不由队员说的提示：额度与降级（06 §12.3）、真人服务的订单与履约状态、付款说明。`speaker_kind = system`，无头像、印章和人称。左对齐整行卡片，`--paper` 底、1px `--rule`、圆角 8；行首 12/500 `--ink-3`「系统」，正文 13/20 `--ink-2`，最多一个文字按钮；不用 `--warn` 和印章红。例：「系统 · 本周的深度准备额度已用完，下周一恢复。和墨聊天、查看和确认已有内容不受影响。」

### 7.3 正在输入与进度 `TypingIndicator`

- 位置：主线和单聊在消息流底部；请队员时在转发卡内（7.1）。发出消息后首个可见反馈 P50 ≤ 1 秒（15 §1.1）。
- 三个 5px `--ink-4` 圆点加 12px 文字：先「墨 正在输入…」，开始调用工具就换成进度短语（03 §5.2、15 §3.4，如「投 在读这个岗位的 JD…」），随步骤切换，并行的几步合成一句。只说真在做的事：不显示工具名、模型名、供应商，不编步骤，不故意放慢。圆点 .3–1 透明度依次变化，周期 1.2s；出字后消失。
- **依据行**：用过工具的回答，气泡或卡片底部留一行 12px `--ink-3`「看了：你的旅程 · 资料库 2 段 ▸」，展开只列来源类别和出处标签（15 §3.4）。
- 超时：20 秒没有任何事件，短语换成「投 还在想…」；45 秒判失败「投 这会儿没接上」加 [重试]（15 §10，假设），不生成替代文字。
- `role="status"`，每个短语只播报一次。

### 7.4 输入框、@ 提及、快捷回复

**`Composer`**：多行输入（16px，1–8 行自动增高）、附件、语音输入、发送；下面一行斜杠命令胶囊，只列已上线功能（P0：/模拟面试、/改简历；/给爸妈的周报 P1-8 起），点了直接触发技能（15 §4.1）。占位符：主线「和墨说点什么，也可以叫队员的名字」；单聊「和前辈说点什么」（字随名字变）。回车发送，Shift+回车换行，输入法组字时不发送（沿用 `isComposing`）。引用回复时输入框上方有一行引用条（「回复 前：…」加 ×）。没有模型名、供应商和 Agent 开关。

**发送与停下分开**（15 §3.5）：

| 输入框 | 本房间有轮次在跑 | 右侧按钮 |
|---|---|---|
| 有字 | 有或没有 | 「发送」；生成中发出的显示「排队中」 |
| 空 | 有 | 「停下」（次按钮加方形图标，`aria-label="停下"`） |
| 空 | 没有 | 「发送」，不可用 |

回车永远是发送，不会触发停下；停下没有全局快捷键。

**`MentionPicker`**（可选的输入辅助）：叫名字不需要 @（03 §4.4），@ 只帮记不住名字的人。输入「@」时在光标上方弹出，宽 280；每行 xs 印章、「前 · 前辈」、一行 12px 职责。只列已上线成员；用户手打未上线队员时按 05 §2.3 回应。按字、全称、拼音、首字母过滤（「@前」「@前辈」「@qian」「@qb」）。↑ ↓ 选择，回车或 Tab 插入，Esc 关闭；`role="listbox"`。插入后成为整体，退格一次删掉；渲染为「@前」（`--ink` 500、`--tint` 底），等于在句首叫名字。单聊里 @ 别的队员不换人，选择器底部一行「去主线叫它」。真人导师不能 @。

**`QuickReplies`**：胶囊 13px `--air` 字、`--sheet` 底、1px `--rule`，高 32（触屏 44），最多 3 个；每组必须有一个「不」的出口（「换个时间」「今天不想」）。点后收起，选项作为用户气泡出现；对话往后走 10 条后变成不可点的文字。主理人「先问」的按钮（15 §3.2 的 `ask_user`，如 [请前辈看看] [先不]）用同一样式，点了直接执行预置的动作，不再经模型判断。

### 7.5 对话列表、房间头、队伍名单、身份标签、出处标签

**`ChatList`**（对话列表）：宽屏左栏 240，`--sheet` 底，独立滚动；手机是「对话」界面的第一屏，点一行进入房间。分三组，组标题 12/500 `--ink-3`（03 §5.3）：
1. **主线**（置顶，不能移动）：md 圆形主理人印章、主理人名 15/500，下面一行 12px 最近一条（`sensitive`、`restricted` 内容只写「一条消息」），右侧等宽时间。
2. **队伍**（`MemberRail`，即队伍名单）：每位已上线队员一行 `MemberRow`，点开就是它的单聊（第一次打开时创建，03 §6.2）。
3. **真人与社区**：见下。

**`MemberRow`**：高 52、圆角 8；sm 方印，「前 · 前辈」15/500 加 `IdentityTag`，下面一行 12px：聊过的写最近一张结论加等宽时间（「后端-v3 已放进待确认 · 10:58」），没聊过的写一句话职责（「改简历、讲项目故事」）；面试间进行中写「面试间 · 进行中」加 `active` 标签。当前房间行底 `--tint`；有未读时名字 700、状态行 `--ink-2`，**不画圆点、不显示数字**（2.2）。不显示在线、在场、忙闲（AI 没有上下线）。`nav aria-label="对话"`，每行是链接（「前辈，AI 队员，最近：后端-v3 已放进待确认」）。P0 例：主线 [墨] 墨；队伍 [前] 前 · 前辈、[投] 投 · 投递官、[面] 面 · 面试官。

**`RoomHeader`**（房间头）：高 56，吸顶。

| 房间 | 印章 | 标题 15/700 | 副标题 12px `--ink-3` |

### 7.8 任务卡片 `TaskCard`

- 结构：页眉（负责人 xs 印章、类型 12/500 `--ink-3` 如「[投] 待确认 · 投递材料包」、右侧状态标签）→ 对象名 15/700（「Stripe · New Grad Software Engineer」）→ 键值行 13（键 `--ink-3`、值 `--ink-2`，如「简历 v7 · 按对账项目改了 3 处」「截止 10/09 23:59 PT」）→ 出处标签 → 页脚（「看改动」[确认这一版]，最多一个主按钮、一个次按钮，其余进「…」）。
- `--sheet` 底、1px `--rule`、圆角 8、无阴影，宽 `min(100%, 560px)`。其他类型例：「投递进度」「作战简报 · Amazon 终面」「今天替你做了什么」「投递授权」。主按钮在最右；放弃类（「不投了」）用文字按钮。
- **后台任务**（15 §4.6）：页眉「[墨] 后台 · 整理 3 份项目报告」加状态标签；键值行是进度短语加等宽步数（「读出文字 3/3 · 正在找项目事实 2/3」），每 ≤ 10 秒更新，进行中页脚只有文字按钮「停止」。完成后键值行写产出（「3 个项目、11 条事实已作为提议放进旅程」），按钮 ≤ 2（「逐条看」「请前辈挑进简历」）；没做完写清原因加「再试一次」（「读不出第 3 份报告的文字，可以粘贴给我」）。任务在跑时用户照常聊天；结果卡不推送。
- **确认按钮按最后一步写**（`final_action`，03 §9.2），可访问名与可见文字相同：
  - `user_sends`（用户自己发）、`none`（确认即可用，如简历版本）：「确认这一版」。
  - `extension`（交给插件，P1-1）：「确认这一版，交给插件」。
  - `in_product`（交接包、面经贡献、合作企业转递，产品或蔓藤运营真的送出）：「封缄寄出」。
  - 「缄」只出现在动效和图形里。其他：作战简报「打开作战简报」、回执「看明细」、投递授权「确认这些授权」「改一下」（7.14）。

| 状态 | 表现 |
|---|---|
| 悬停 / 处理中 | 边框变 `--ink-4` / 主按钮「正在确认」并禁用 |
| 确认作废（回到 `pending`） | 标签「内容改了，需要重新确认」，主按钮仍是「确认这一版」，可「看改动」 |
| 已被替换 | 文字 `--ink-3`，边框虚线，quiet 标签，按钮换成「看新版本」 |
| 引用的简历有了已确认的新版本 | 已确认的材料包保持有效，多一行「有更新的 v5，要换吗」加文字按钮「换成 v5」 |

### 7.9 待确认条目与确认仪式

**`ReviewItem`**（任务卡展开后，按截止排序）：依次是发给谁、哪个版本、改了什么、截止、出处、完整内容；手机上能读完全文，按钮固定在底部操作栏（64 加安全区）。差异视图手机行内、宽屏左右对照：新增 `--air-tint` 底加 1px `--air` 下划线，删除 `--ink-3` 加删除线。
- **原稿里没有的事实**（服务端按 05 §2.4 逐句来源标出）：该句加 1.5px `--warn` 下划线，行尾 12px `--warn`「原稿里没有」，每条带 [保留] [删掉]。没逐条处理完时「确认这一版」禁用，旁边提示一次「还有 2 处原稿里没有的事实，先逐条看一下」（数字按实际）。
- **申请题的答案来源**（`answer_source`，03 §9.2）：`profile_confirmed` 旁注 12px「来自你的档案 · 10/02 确认」；`user_required` 显示 `pending` 标签「需要你自己回答」，没填时同样禁用确认。
- 没有批量确认；可以批量「稍后再看」（写 `snoozed_until`，界面暂时隐藏，不改状态）。

**`SealCeremony`**（静态版 = 减少动态版）：
1. 点确认按钮：按钮立即禁用，带 `(id, revision, payloadDigest)` 提交；卡片抬起，阴影变 `--sh-paper`，160ms。
2. 服务端确认成功后，卡片主体向上收起只剩页眉和摘要一行，240ms。
3. 「缄」字印章（md，`--stamp`，−6°）落在右上角：1.25→1 倍、透明度 0→1，420ms，`--ease-out`。
4. 卡片落回，200ms；标签按 7.10 变化（例「已确认这一版 · 等你发出」），页眉下多一行等宽「r3 · 10/06 08:31」。

**等待、超时与失败**：600ms 内没返回，卡片保持抬起，印章悬在 1.25 倍、透明度在 .7–1 间缓慢变化。8 秒仍没返回：显示「还在确认，先别关页面」，并 GET 该对象当前状态，以服务端为准继续或复原（超时不等于失败）。确认接口按 `(id, revision, payloadDigest)` 幂等，重复提交返回当前状态。只有服务端明确返回错误时，印章淡出、卡片复原，页脚写「没确认上，内容没有发出。[再试一次]」。断网恢复后自动对账一次。动画永远不抢在服务端前面。

**确认之后**（05 §2.4）：`user_sends` 的页脚是「复制全文」「打开投递页面」「我已发出」，发出前可「撤回确认」；点「我已发出」后左下出现邮戳 `Postmark`（40px 圆，1px `--ink-2`，等宽「10.06」，无红色、无动效），状态「已发出」。插件核实不了网站上那一下提交时，浮层和看板按钮写「我已投」，记 `self_reported`。`role="status"` 播报「已确认：Stripe 投递材料包」及超时、失败文案；没有全局快捷键能触发确认。插件浮层保留信封动画（`envelope.ts`），换本文颜色，合盖时盖「缄」；替用户按网站提交只在用户本人点了那一下之后发生。

### 7.10 状态标签 `StatusChip`

### 7.11 指挥台侧栏 `OpsRail` 与身份时钟 `StatusClock`

**`OpsRail`**：宽屏右栏 288，`--sheet` 底，独立滚动；模块间 24，标题 12/500 `--ink-3`。顺序固定：
1. 身份时钟（不满足条件时整块不出现）。
2. 待确认：最多 3 行（对象名加状态标签），更多时「全部 5 条 ›」。
3. 下一场：公司和轮次、等宽时间（「周四 10:00 PT」）、次按钮「去练」（P1-4 起「打开作战简报」）；没有面试不显示。
4. 本周你做了：P0 三格「练了几题」「改了几个故事」「确认了几份材料」，「联系了几个人」随人脉官（P2）加为第四格。`--paper` 底，数字 `--t-num-lg`，下方 12px 标签；固定一句「只记你的付出，不排名、不打卡」；全为 0 时只显示「这周还没有记录。」

1024–1279 宽时收成右侧抽屉（`RoomHeader` 的「指挥台」按钮打开）。< 640 没有侧栏也没有抽屉，这些模块放在今天页（05 §2.2）。

**`StatusClock`**
- **P0**：只原样显示用户在「我 → 身份时钟」选定的那一个日期（「毕业日期 2027-05-15 · 你录入的」，日期等宽），没有倒数和进度条。用户在 05 C5 跳过、选「其他」或「不想说」、或从没录入时，整块不出现，也不提示录入。固定脚注 12px「信息与提醒，不是法律意见。拿不准请问学校 DSO。」；「我 → 身份时钟」有「在侧栏隐藏」开关。
- **P1-3 起**：倒数（「32 周后」，`--t-num-lg`）默认关闭，由用户自己打开；30 天内有自设提醒时加 `pending`「提醒」。功能开关关闭时界面不出现「提醒」二字。不做进度条，不随天数变色。
- 待业天数默认不显示；用户打开后 P0 原样显示「你 10/01 记的：41 天」，P1-3 前不顺延、不显示上限。不写「还剩」「来得及」「超限」「你还有资格」。

### 7.12 记一条卡片与资源卡

### 7.15 语音面试间 `InterviewRoom`

共用：面试间是面的单聊里的一种模式（03 §4.6），整页，宽屏也不保留三栏；界面中文，题目和作答英文（`lang="en"`）。标题区始终有「AI 声音」标签。**任何 AI 声音第一次播放前**（含 P0 面试官）弹出说明，完整文案见 12 §6.1，记录用户级 `voice_disclosed_at`。常驻「暂停，回单聊」。字幕默认开、可关，旁注「真实面试没有字幕，想练听力可以关掉」。

- 布局：顶栏「‹ 面的单聊」「模拟面试 · Behavioral · 2 / 3」「AI 声音」、计时和「隐藏」；中间 xl 面印章、英文题目 20/30、转写 15 `--ink-2` 加「转写有误」；底部 [按住说]、「打字」、「暂停，回单聊」、「结束，看复盘」。

## 8. 动效

除两种仪式外，动效只说明「发生了什么」，≤ 200ms（抽屉 320ms）；不弹跳、不撒花、数字不滚动、元素不抖动。`--dur-fast` 120ms（悬停、按下、新消息淡入加上移 4px）；`--dur-base` 200ms（展开折叠、标签变化、提示条）；`--dur-slow` 320ms（抽屉）；`--ease-out` `cubic-bezier(.2,.7,.3,1)`；`--ease-std` `cubic-bezier(.3,0,.2,1)`。

**仪式动效只有两种**：①**印章落下**（1.25→1 倍，700ms，`--ease-out`）：主理人诞生时先「晕墨」（05 O5 生成期间空白印章的墨色以 2.4s 为周期在 .15–.6 透明度间晕开，完成后 400ms 填满），选字后 xxl 印章落下（02 §5.1）；信件落款第一次出现（进入视口 60% 后延迟 500ms，每封信每台设备只播一次，不确定就不播）。②**确认仪式**（7.9），全程以服务端确认为准。

**减少动态**：去掉位移、缩放、旋转；仪式改为 150ms 淡入到最终状态；晕墨改为静止空白印章加「正在生成……」；输入圆点静止；音量环改文字。现有 `styles.css` 一刀切关闭动画的规则改为逐组件声明，保留 150ms 内的透明度过渡。插件「失败时信封摇一下」改为淡回原处。

## 9. 文案与语气

本节和 7.10 是全产品按钮、状态、系统文案的终稿；其他文档与此不一致时以本文为准。

### 9.1 各自的声音与按钮

| 谁 | 语气 | 签名形式（03 §2；输出契约与渲染器保证） | 例 |
|---|---|---|---|
| 主理人 | 「我」，用用户起的称呼；按说话方式卡（02）；情绪用中文；一条消息只说一件最重要的事 | 无固定形式；请队员时的引子 ≤ 30 字，不转述、不复述转发卡 | 「早。今天一件事：把推荐系统那个故事讲顺，40 分钟。」 |
| 前 | 「我」；具体、先保留再改；材料用英文 | 改前改后对照（删除 `--ink-3` 删除线、新增 `--air-tint` 底）；「原稿里没有」标记；开头先说一句会保留的 | 「保留第一条「QPS 从 2k 到 9k」。最该改的是第二条：没写规模。」 |
| 面 | 「我」；直接、少评语；题目和作答英文 | 一次一题的题卡（等宽页眉「Q1/2 · behavioral」）；点评固定两行「做得好：」「最该改：」；用户答完前不夸 | 「做得好：冲突讲得具体。最该改：结尾没说结果。」 |
| 投 | 「我」；报数、给日期、引原句 | 清单加等宽日期，JD 原句用引用块（`lang="en"`）；开头先报数 | 「3 份里 2 份能直接投。Acme 截止 10/09 23:59 PT。」 |
| 规（P1b）；教（P1b）；脉（P2） | 「我」；专业、简短、给依据；不寒暄 | 2–3 个方向的对比卡；一次一个点加「够了」的标准；≤ 4 句的英文草稿 | — |
| 系统 | 无人称；中性、简短、陈述事实；不用感叹号，不卖萌 | — | 「内容改了，需要重新确认。」 |

- 队员先靠签名形式区分，再靠语气；用户偏好只改长短、顺序和语言，不改签名形式（15 §5.4）。队员之间不寒暄、不互相附和；提到别人的产出只说产物和版本（「前改的 r2」）。
- 系统不替角色说话（不写「墨提醒你……」）；角色不说系统腔（不说「操作成功」）。
- **按钮讲清后果，一般不超过 6 个字**：「确认这一版」「改一下」「不投了」「稍后再看」「到网页确认」「读完整的信」「我已发出」。转发卡和单聊常用的：「去单聊练」「去单聊回答」「看差异」「看结论」「先不」。允许的例外：「确认这一版，交给插件」「不要，留给我自己」「暂停，回单聊」「暂停，用中文问一句」。不用「确定」「OK」和单独的「提交」；插件浮层的「提交申请」除外，它就是网站上的那一下。
- 错误提示写清发生了什么、有没有后果、下一步怎么办（「没连上，消息还在，恢复后会自动发出。」）；不显示错误码，需要时折叠在「详细信息」里。
- 中英切换按 01 §7.5：界面中文，公司名、岗位名和行话保留英文；周报里不出现没解释的缩写（OPT 写「毕业后的工作许可」）；按钮和标签不写死宽度，留 60% 余量。

### 9.2 敏感场景

| 场景 | 这样写 | 不要 |
|---|---|---|
| 被拒 | 「这一轮结束了」「没走下去」；先问想聊还是想歇 | 用 Rejected、拒信、失败、淘汰做标签；「别灰心！」 |
| 没进展 | 「要不要我隔天来一次？」 | 「你已经 3 天没投了」「再不……就来不及」 |
| 身份日期 | 「按你录入的日期」「信息与提醒，不是法律意见」「拿不准请问学校 DSO」 | 「你还有资格」「还剩」「超限」 |
| 对外发出 | 「要发给别人的消息和材料，都先进待确认；表单里哪些项可以替你做，由你在对话里逐项确认；最终提交永远由你本人点。」 | 「什么都不会发」这类绝对化承诺 |
| 付费 | 写明价格、收款方、是真人，同时给免费路径 | 限时、仅剩、名额紧张、保证 |
| 危机 | 02 §10 的固定模板 | 即兴改写；同时出现任务或推荐 |
| AI 身份 | 被问就直说是 AI；状态行「AI · 你的主理人」 | 「我也是人」「我永远在」「一直在」 |

### 9.3 禁用词

禁用词只有一份配置，放在 career-core，按短语级正则匹配；界面文案类由 08 维护，销售类由 06 维护，主理人表达类由 02 维护。界面文案的检查只扫界面文案目录，用户数据和公司名不扫；命中即测试失败。
- 打卡、连胜、streak、积分、等级、排名、打败了、超过了 x% 的用户、完成率
- Rejected、拒绝率、淘汰；作为状态标签或文案的「失败」
- 「亲[，,！]」「宝[，,！]」、加油哦、冲鸭、连续感叹号（不误伤「亲友」）
- 销售类（06）：限时、名额只剩、最后 N 个、错过就没、再不……就、包过、保证拿、内推保证、必考、一定会考、稳过（「不能保证结果」不命中）
- 我们想你了、你已经 x 天没；智能、赋能、一站式、黑科技
- Openfield、THINKING PARTNER；用户可见界面里的模型名、供应商名、环境变量名
- 连续 4 个以上大写字母且不在缩写白名单（OPT、STEM、CPT、SWE、MLE、USCIS、DSO、EAD 等）里的装饰短语

## 12. 验收标准

1. Token 测试按第 2 节阈值算对比度和色差（含 on-ink）；token 定义外无十六进制颜色；`--stamp` 只被「缄」（网页与插件）、「贺」、航空信纹、录音圆点引用；无小于 12px 的字号（含插件）；9.3 禁用词零命中；界面无模型、供应商、环境变量和声线 id。
2. 截图走查：浅色、深色、高对比度、减少动态、200% 缩放，各截 390×844 和 1440×900；手机无横向滚动（含旅程页）；被拒、逾期、出错的截图无红色；**任意一张截图里都看得到 AI 标识**。读屏走查：主线（含转发卡）、单聊、确认仪式、三件事、面试间逐回合、初见同意页、投递授权分组提问与确认卡、插件「留给你」提示。
3. 确认：断网时不进入已确认；服务端摘要与卡片版本一致；**超时后服务端才成功**时显示「还在确认，先别关页面」，对账后进入已确认，决定只记一条；重复提交返回当前状态。`user_sends`、`none` 的按钮不出现「封缄」；`approved`（`user_sends`）不是 done 色调。
4. `StatusChip` 对 03 §9.3、05 §3.1、§3.3、真人预约和后台任务的每个枚举值都有映射。付费推荐卡缺价格、收款方或「这像推销？」任一项即失败，且不出现在信件、晨报、三件事、Discord 里。
5. 没上线的队员不出现在对话列表、队伍名单、叫名字的名字表、@ 选择器、`RoomHeader` 人数和 Offer 联署里（切换 `enabled` 验证）；每天信件上限与溢出优先级有服务端单元测试。
6. `ReviewItem` 有未处理的「原稿里没有」或「需要你自己回答」时不能确认。身份时钟：C5 跳过或不想说时整块不出现、无录入提示；P0 无倒数；脚注始终在；功能开关关闭时没有「提醒」二字。初见同意页复选框默认不勾，不勾不能继续。投递授权的两个选项等宽、不预选、无「推荐」；插件浮层没有授权提问组件和「同意」按钮（静态检查）。
7. 对话：主线里队员只以 `ForwardCard` 出现，卡头都带「转自 … · AI」，按钮 ≤ 3；引子只在主理人主动请人时出现；输入框有字是「发送」、空且有轮次在跑是「停下」，回车不触发停下；进度短语和依据行里没有工具名、模型名、供应商；对话列表和名单里没有在线、在场、忙闲和未读圆点；系统事件行里没有入场离场。
