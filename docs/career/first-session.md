# 首 15 分钟：比较两个方向，选一个验证行动

观察 / 检索日期：**2026-10-06**。用户已选择这个核心结果。本文是体验设计与官方任务调研，不是已接入的产品流程；没有投递、联系雇主、调用付费模型或使用真实用户文件。

**完成条件：**用户能看懂两个方向的日常工作差异，指出自己的一个探索线索和一个未知项，选择一项愿意做的 60–90 分钟验证行动。选择是暂定假设，随新证据可修改；无需在第一次会话确定职业、拿出完整简历或证明自己已具备岗位能力。

## 两个方向卡

官方职业任务是事实；以下分组、课程项目映射和验证动作是我们的设计建议。职业家族中的全部任务不等于每个初级岗位的职责；两条方向都需要分析与沟通，不能用“数据型 / 创意型人格”把用户固定住。

| | A：市场 / 业务洞察 | B：内容策略 / 数字营销 |
| --- | --- | --- |
| 经常要解决的具体问题 | 发生了什么、证据够不够、有哪些解释、下一步该作什么业务决定？ | 对谁讲、讲什么、为什么用这个渠道、怎样知道信息产生了效果？ |
| 常见工作过程 | 收集资料 / 数据，核对口径，比较趋势，做图表，写研究结论，向业务方解释理由和限制。 | 理解受众和信息需求，研究内容 / 渠道，写和改内容，协调发布，定义指标并依据反馈调整。 |
| 常见交付物 | 研究 / 分析 brief、图表、洞察报告、判断与后续调查建议。 | 内容 brief、文案 / 素材、编辑日历、渠道方案、效果报告和下一次测试。 |
| 第一轮最值得体验的难题 | 愿不愿意核对一个数字，并在证据不足时缩小结论？ | 愿不愿意为一个明确受众反复修改信息，并解释怎样衡量？ |
| 可探索 title，不等于当前机会 | Market Research Analyst、Consumer / Customer Insights Analyst；“Business Analyst”需单看是否技术系统、运营、财务等不同任务。 | Content / Marketing / Communications Associate、Digital Marketing Coordinator；岗位名称不能替代正文职责与资历要求。 |
| 官方案例范围 | O*NET 13-1161.00 的研究、消费者 / 市场分析、报告任务；不把它泛化为全部财务、BI 或业务分析岗位。 | O*NET 13-1161.01 有数字内容、用户意图、Web 指标、KPI 和优化实验；下面的公开岗位例是其中偏内容 / 沟通的切面。 |

官方任务来源：[Market Research Analysts and Marketing Specialists](https://www.onetonline.org/link/summary/13-1161.00)、[Search Marketing Strategists](https://www.onetonline.org/link/summary/13-1161.01)。本轮不复制其整套量表，不据职业分类给出招聘概率或个人资格判断。

## IBM SWOT / 财报课程项目能提供什么线索

以下是**有条件的映射**，需要用户确认实际做过什么。课程中使用某种方法，不等于已熟练掌握；项目名称、课程要求或他人完成的部分也不证明本人贡献。

| 已有经历输入（仅在本人确认后使用） | 对 A 的探索价值 | 对 B 的探索价值 | 仍需新证据 |
| --- | --- | --- | --- |
| 阅读和比较公开财报 | 可能愿意核对数字、比较业务变化、组织证据。 | 可以作为内容 research 和事实核查的素材起点。 | 不能推出已会数据清洗、SQL、统计推断、财务建模或广告分析工具。 |
| SWOT / 战略分析 | 可追问每个判断的证据、替代解释和业务含义。 | 可追问怎样选择重点、为特定受众解释复杂信息。 | SWOT 标签本身不证明客户调研、定位能力或有效内容策略。 |
| 课程汇报 | 可以练“结论—证据—限制—下一步”的解释。 | 可以比较受众、结构、语言和视觉呈现。 | 不证明真实客户服务、受雇咨询、营销 campaign 执行或增长结果。 |
| 模糊记得获得课堂赞扬 | 可作为寻找原反馈的线索。 | 可作为寻找原反馈的线索。 | 不补写教授原话、不升级成奖项；没有找回反馈也不阻止方向探索。 |

第一轮不要求上传文件。可以先问“你更记得自己查资料、比较数据，还是组织汇报？也可以都不记得”。AI 应记录“本人回忆 / 待核实”，再让验证行动提供新证据。

## 每个方向一个 60–90 分钟验证行动

这是独立练习，交付物标注 **模拟 / 自主项目**，不发布、不联系 IBM、不代表为 IBM 或任何雇主提供了服务。允许不用 IBM，换成用户感兴趣且有可使用公开资料的主题；同一主题分别做两种任务有助于区分对工作过程的偏好，但首次只需选择一个。

### A：做一页“证据到判断”的洞察 brief

**问题：**根据一份限定的公开结果，什么变化值得继续研究？哪种解释目前还不能成立？

建议素材：本次已打开的 [IBM 2025 年第四季度结果，发布于 2026-01-28](https://newsroom.ibm.com/2026-01-28-IBM-RELEASES-FOURTH-QUARTER-RESULTS)。只截取其中的业务分部结果作练习，不把单季结果描述为今天的实时状态。若需要更多材料，可从 [IBM 官方年度报告入口](https://www.ibm.com/investor/services/annual-report) 获取对应年度报告；本轮只核实入口，没有读取完整 PDF。

1. 用约 15 分钟选一个问题和同一期间的几个数字，注明单位、期间和来源。
2. 用约 20 分钟做一张简单比较表 / 图；区分百分比变化与百分点，不混用当期汇率和固定汇率口径。
3. 用约 20 分钟写一页：两条观察、一条有依据但有限的解释、一种替代解释、一个还需要的数据。
4. 用约 10–15 分钟解释“为什么业务方应该继续看这个问题”，再记录体验；余下时间修一个发现的错误。90 分钟到即停止，不要求漂亮 deck。

**验收 rubric（自写）：**数字能回到来源；结论与口径一致；解释不超出证据；说清一个替代解释；下一步调查具体。AI 反馈仅为练习建议，不发职业能力认证。

**对方向的验证价值：**用户是在享受找出原因，还是只喜欢最终报告看起来漂亮？卡在核数但愿意继续学，是信息；完成很快却不想再做，也是信息。这个任务不证明问卷设计、因果分析、客户管理或某家岗位胜任。

### B：把同一素材转成受众明确的内容 brief

**问题：**一群没有深入技术 / 财务背景的 business 学生，应从这个公开变化中理解什么？为什么他们会愿意继续读？

可以沿用上面的 IBM 公开素材，避免两种验证任务只因主题不同而无法比较。这里的受众是模拟练习设定，**不是假装做过用户访谈的 persona**。

1. 用约 10 分钟写受众、一个信息需求、一个内容目标；将未经调查的需求标成假设。
2. 用约 20 分钟作内容 brief：核心信息、三个来源支持点、一个合适的模拟渠道和选择理由。
3. 用约 20 分钟写两个标题与一段 120–180 词英文 / 同等阅读长度的中文正文；说明两个版本各试什么，不生成未验证的产品承诺。
4. 用约 10–15 分钟写衡量计划和复盘：若以后获授权发布，观察什么、分母是什么、什么情况会改写。比如链接点击率与读者能否说出核心信息分别观察，不虚构已有结果。剩余时间修改一段，90 分钟即停止。

**验收 rubric（自写）：**受众和目的明确；事实没有被改写歪曲；信息层次适合该受众；渠道有理由；指标连接目标并有分母；知道一项尚未检验的假设。

**对方向的验证价值：**用户愿不愿意删掉自己喜欢但受众不需要的内容？愿不愿意把文案当作可测试的选择？本轮不验证 SEO 工具、广告账户、CMS、真实转化或持续运营；好的稿件也不能直接称为增长成果。

## 15 分钟怎样结束

| 时间示例 | 会话动作 | 应避免的阻塞 |
| --- | --- | --- |
| 0–3 分钟 | 确认今天的目标、可用时间和一两项经历 / 兴趣线索，允许不知道。 | 完整简历上传、长问卷、必须先找回项目。 |
| 3–8 分钟 | 用两张方向卡比较具体问题和交付；指出已有线索与待验证处。 | 直接把专业名换成唯一岗位；把样本 title 当成全部市场。 |
| 8–12 分钟 | 比较两个行动的好奇心、成本和信息价值，选一个。 | 一次完成两个完整任务；用无依据综合分替用户决定。 |
| 12–15 分钟 | 写下可审阅的行动草稿：要验证什么、材料、时间、交付、rubric、停止条件。 | 自动执行、发布、预约、联系或投递；把计划写成已完成。 |

**选择 rubric：**每项都由用户给一句理由，允许“未知”，不加权生成“职业适合度 92%”。

| 选择问题 | 有用的信息 |
| --- | --- |
| 哪一种具体工作过程更让我想试？ | 对任务的好奇，而非公司名、title 或收入想象。 |
| 我已有哪一条线索？ | 本人能说明的经历；线索不是技能认证。 |
| 哪个困难我愿意练？ | 核数 / 推理，或受众 / 改稿等；现在不会不是排除理由。 |
| 哪个在当前时间和工具下能完成？ | 不需要付费账号、真实数据权限、外部回复或公开发布。 |
| 做完后能消除哪个疑问？ | 是否喜欢该过程、某个关键技能缺口，而非“一次证明能就业”。 |

如果两者仍难选，优先选择最容易取得材料、最能回答当前疑问的任务。记为“先试 A / B，再看结果”，不把犹豫解释成缺乏职业目标。下次回合结合交付、帮助级别、用户体验与未知项，再决定继续、调整任务或换方向。

最终输出示例仅是格式：`方向 A / B → 来源与实际任务 → 已有线索 / 未知项 → 暂定选择及本人理由 → 一个验证行动（60–90分钟、交付、rubric、停止条件） → 等待用户审阅`。不预填用户选择，不自动替用户生成真实经历。
