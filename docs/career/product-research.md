# 求职伙伴：学习、成就与职业旅程产品研究

检索日期：2026-10-06。对象：在美国探索职业方向、缺少交流经验与人脉资源的学生，首个案例为 business / digital media 背景。本文只读官方产品、官方帮助中心与政府/行业组织页面；未注册课程、预约导师、联系公司、投递、调用付费模型或验证产品的就业效果。

**事实**指官方页面公开描述的功能或统计；这能证明产品如何介绍自己，不能证明实际效果。**建议 / 推断**是我们的产品设计，尚需用户试验。本文不提供个人工作许可或签证判断，不承诺就业。未能读取的官方数据页面单独列明，不用第三方镜像补成“已核实”。

## 1. 值得建立的产品闭环

**建议：把求职伙伴做成能陪用户完成一次学习和行动的长期伙伴。** 一个回合应留下四样东西：可纠正的经历事实、能展示的成果、一次具体的练习反馈、一个用户愿意完成的小行动。下一回合根据新证据调整方向，并减少提示。课程、岗位搜索、简历、自动填写都是这个过程里的工具。

首用户说“不知道怎样开始，也没有时间找到合适的导师”，并不是已经选定岗位后只差一封 cover letter。**用户已选定首 15 分钟的核心结果：比较两个职业方向，并确定一个验证行动。** 课程项目是探索的输入之一，帮助找到可迁移线索；没有找回文件、不记得教授点评，也不阻止方向比较。背景依据见 [现有产品 brief](../product-brief.md)，具体首轮设计见 [first-session.md](./first-session.md)。

“包装”可以是选择更有意义的业务问题、突出本人贡献、用职业语言解释分析过程、改善图表和叙事。比如把“做了 SWOT”改成“比较了哪些证据、如何形成判断、为什么另一种解释不成立”。它不需要先有耀眼的公司名或量化业务收益。课程项目、模拟项目、受雇工作分别保留自己的标签；没有真实执行的建议不写成公司实现的成果。

## 3. 第一个可验证小闭环：比较两个方向，选出验证行动

以下是**建议的试验**。首轮的完成标准是一张两方向比较卡和一个用户选择的验证计划；不是定下终身职业、完成简历或证明能力。“七天”是后续可暂停的示例，不是连续打卡要求，也不要求先把所有环节做完。

| 回合 | 用户做的事 | 伙伴做的事 | 留下的证据 / 结束条件 |
| --- | --- | --- | --- |
| 第一次，约 15 分钟 | 说出可用时间和一两项经历线索，比较市场 / 业务洞察与内容策略 / 数字营销，选择更想验证的一件事。 | 展示两种真实任务及来源；说明已有线索、未知项和验证成本，允许都不确定。 | 两方向比较卡、一个有理由的暂定选择、一个 60–90 分钟验证行动。没有文件也能开始。 |
| 按需恢复证据，约 20 分钟 | 有权访问时找回 slides / report / 课程反馈，或确认找不到。 | 指向支持判断的具体图表 / 段落；不替教授重建赞扬内容。 | 某条主张的来源与不确定项；“记得被表扬但忘了哪一点”仍是未核实记忆。 |
| 体验选定方向，约 60–90 分钟 | 完成所选的洞察 brief 或内容 / 衡量 brief，观察自己是否喜欢实际过程。 | 给清楚的任务、交付和停止条件；将提示程度与本人完成部分记录下来。 | 一个独立 / 模拟交付和一次体验反思；完成不直接代表掌握或岗位胜任。 |
| 解释与追问，约 15 分钟 | 先用自己的话讲 60–90 秒，再回答两次追问。 | 第一轮可给结构提示；下一轮减少提示，追问数据、取舍和本人贡献。 | 练习版本、提示级别、具体反馈；流利不是唯一标准。 |
| 一次外部反馈 | 自己决定是否向教授、career center 或一个合适校友请教。 | 准备两分钟背景、一份允许分享的摘要、一个具体问题及消息草稿。 | 用户审阅后自主发送 / 预约；未发送的草稿不记成 outreach，无回复也不评价人的社交价值。 |
| 延迟迁移与复盘 | 隔一段时间在不同公司 / 材料上做同类判断，尽量不用提示。 | 用冻结的 rubric 对照两次表现；记录什么会了、什么还要练。 | 一项有范围的能力证据、一条新的岗位理解、一个下一步。 |

对 business / digital media 的**首轮方向假设**固定为市场 / 业务洞察与内容策略 / 数字营销。两者都分析和沟通，区别是主要交付和问题：前者更关注证据如何支持决策，后者更关注信息如何到达受众并被衡量。O*NET 可提供任务参照，不能仅凭专业名或职业代码判断岗位资格。[市场研究任务](https://www.onetonline.org/link/summary/13-1161.00)、[数字营销任务](https://www.onetonline.org/link/summary/13-1161.01)

示例交付可以选“公开公司资料中的一个趋势，如何影响某个客户 / 营销决策”，或“为一个虚构校园活动制定指标和验证方案”。它们训练真实岗位任务，但明确标注为独立 / 模拟项目。真实雇主委托、付费实践或实习是另一种关系，需要核实适用条件后再进入；学习模拟不能替用户作这类判断。

这个闭环的创新假设是：**从两个有出处的方向开始，以已有经历作线索，用一个小任务取得新信息，再决定继续还是换方向**。项目叙事和交流练习按所选行动需要进入。它是否有效，要用第 6 节的方式试验，不能靠一次漂亮的 AI 改写验收。

## 4. 将蔓藤式 know-how 变成可更新的工作方法

这一节是**我们自己的架构建议**。蔓藤公开服务描述证明它覆盖多个求职阶段，本次没有证据可还原其内部 know-how。未来若使用其内容，应有明确授权和来源，不能把官网摘要命名为“蔓藤认证流程”。

### 一份知识不应只有长 prompt

| 工作方法版本需要包含 | 用途 |
| --- | --- |
| 方法 ID、版本、作者 / 审阅者、内容权利、来源和有效日期 | 知道谁提出规则、什么时候更新、能否用于产品。 |
| 适用对象与前置条件 | 如学生阶段、岗位家族、语言、可用时间；避免把某位导师的个案经验泛化。 |
| 输入事实及缺失时的处理 | 允许资料不足；区分本人回忆、文件事实、导师意见和 AI 推断。 |
| 步骤、允许工具、输出物、rubric、停止条件 | 每一步都能执行和审阅，避免无限聊天或机械套模板。 |
| 反例、失败方式、导师升级条件 | 解释何时不能靠该方法继续，何时需要真实反馈或专业判断。 |
| 每个规则的证据性质 | 官方数据、经验建议、用户假设分别显示；不把导师建议包装成通用事实。 |
| 版本化证据引用与隐私规则 | 原文件私有，计划只带授权引用；说明成果归属、分享范围、撤回与保存期限。 |

例如“课程项目叙事 v1”不是让模型把句子写得更厉害，而是要求恢复业务问题、本人行动、证据、判断、限制，练一次追问，再等待用户确认。导师如果建议新顺序或发现任务不适合某类岗位，成为 v2 的变更说明，而非偷偷覆盖 v1 的历史评价。

**版本与执行建议：**一次计划冻结使用的方法版本、rubric 版本、岗位来源版本和输入引用。旧成果保留它当时的语境；新方法上线可以提出迁移，显示差异并让用户选择。用户纠正或撤回一条事实后，依赖它的故事、推荐和成就需重新评估，不能继续把旧结论当作当前事实。

### 导师是一次有目的的升级

升级触发可以是：用户无法判断两个方向；分析经两次练习仍卡在同一个推理点；证据互相矛盾；需要对行业实际工作作判断；或讨论涉及专业资格 / 实际雇佣关系。不要把每个小问题都转成长时间付费咨询。

先准备一份可审阅的问题包：我要决定什么、已做什么、一个作品摘要、来源和未知项、两个希望导师回答的问题。只在用户授权后分享选定内容；导师回复需记录评阅范围和日期。“导师看过这页报告”不能升级成“导师担保我具备所有岗位能力”。ADPList 的公开流程也强调先找具体挑战，再按专长选择导师。[官方说明](https://adplist.org/find-a-mentor)

用户主动提出 ICC 或其他中介路线时，产品可以帮助列出需要核查的事实：实际岗位 / 项目、合同关系、费用与退出条件、数据来源和未解问题。本报告没有验证具体机构，也不判断个人合法性；不要因路线非主流就一概否定，也不要因为有 offer 宣传就替用户确认适用。具体工作许可等判断交给适当的学校 / 专业人士，伙伴负责组织问题与证据。

## 5. 成就系统：记录进步，不制造刷分目标

以下是**拟定规则**，尚未验证留存或学习效果。参与、能力证据和实际职业结果应分层展示；模型反馈不能直接发放“已掌握”认证。

| 可以设计的里程碑 | 最小证据 | 防止虚假进步的处理 |
| --- | --- | --- |
| 解释一个判断 | 一条来源、一段本人解释、一次新追问；保留当前仍不确定的地方。 | 同一成果反复改写不增加成就；陈述变好和理解变好分开。 |
| 独立迁移一次 | 新材料 / 新任务、冻结 rubric、低提示或无提示尝试。 | 不能只重复背熟的问题；显示帮助程度与评阅范围。 |
| 把问题问具体 | 一次练习，或用户确认的真实交流及从反馈中提取的下一步。 | 消息草稿不算发送；回复数量不是社交能力；练习与真实交流分开。 |
| 做出可展示成果 | 交付物、本人 / 团队贡献、使用来源、方法与限制。 | 完成课程证书不自动满足；AI 全代写只能记辅助完成，不能证明独立能力。 |
| 采纳一次真实反馈 | 获授权的具体反馈、一次作品修改、用户说明修改理由。 | 导师身份、权限与评阅范围需核实；“赞”或模板回复不等于专业评阅。 |

**规则建议：**按 owner + 成果 / 尝试 / 实际事件身份去重，不按上传次数计数；撤回和拒绝会撤销相应当前进度。把“本人报告”“平台观察到动作”“本人确认”“外部评阅”显示为不同来源，不统一叫客观验证。内容 hash 有助于绑定版本，不能证明原创性、内容真实性或贡献归属。

不把申请数、群发数、AI 文档数、对话时长、课程数量、连续在线天数做成升级货币。可以记录一次首次完成的、合适且经确认的投递，帮助克服行动障碍；随后应看岗位契合、信息获取和反馈，不奖励海投。实际 offer 记录是职业结果，不是对用户价值或努力的排名。

允许暂停、重新开始、改变方向。失败的角色探索可能排除了一个不适合的工作，仍产生有效学习。交流 rubric 关注信息准确、表达组织、倾听、澄清、理由和下一步；不把口音、外貌、摄像头使用或单一语速当成职业能力。文字与语音练习可以分别注明场景；不因此声称二者完全等价。无需引入不可靠的 AI 文本检测来惩罚正常使用模板或辅助工具。

## 6. 怎样验收学习与真实职业成果

**先做创始人自己的观察，再做小规模试验。** 第一轮没有资格宣称提升就业率。建议用同一用户的初次尝试、帮助后的尝试、延迟新任务作比较，记录花费时间、完成原因和用户主观信心；主观信心是自述，不能当作实际能力或心理诊断。

第二轮可招募 5–10 位自愿学生验证流程可用性。使用不同但相近的任务，冻结自写 rubric，尽可能由不了解尝试顺序的人独立评阅；既记录完成者，也记录中途退出和资料不足者。这个规模主要发现问题，不支持全国就业效果、因果结论或成功率宣传。

| 指标 | 建议定义 / 分母 | 解释限制 |
| --- | --- | --- |
| 第一轮有用性 | 开始闭环的人中，有多少人留下一个自己确认的下一步；报告人数、窗口和退出情况。 | “满意”不等于具备能力。 |
| 学习证据 | 完成基线的人中，有多少人完成延迟的新任务；分别报告 rubric 维度、帮助级别和缺失结果。 | 不以 AI 综合分或同题重答直接推得掌握。 |
| 反馈闭环 | 提出外部反馈行动的人中，有多少人自愿执行、获得反馈并作了有理由的修改。 | 无回复不能当作用户能力不足；机构访问差异会影响结果。 |
| 真实求职阶段 | 确认的岗位 / 投递事件、面试邀请、完成面试、offer、接受、入职各自独立计数。 | 这些事件不是同一个成功定义；无法归因给产品。 |
| 结果可信范围 | 来源类别、发生日期、是否仅本人确认、是否有授权凭据或明确范围的外部确认。 | 凭据存在不保证所有细节真实；未提供私密文件不意味着用户撒谎。 |

用户可选择提供已脱敏的邀约或评阅凭据、人工确认或仅自述，不要求为了升级上传完整邮件 / 薪资合同。真实成果存私有引用；公开 portfolio 必须另行审阅和授权。项目成果可以证明做了什么、如何做和如何被评阅；不能把模拟市场数据的变化改写成真实公司的收入提升。

## 7. 求职市场应该呈现什么

市场卡片的任务是帮助选择下一步，不是预测某人拿 offer 的概率。以下字段和统计规则是**我们的建议**。

### 岗位卡片比“热门职业排名”更有用

显示雇主与原始岗位链接、原始 title、实际任务、资历要求、地点 / remote 范围、薪资说明、posted / observed / checked 三种日期、当前状态、关键缺口和少量原文依据。用户可看到哪些要求明确写了，哪些是我们的映射。授权相关措辞保留明确 yes / no / unknown；公司历史数据不能替换这个岗位的当前说明，也不能替用户填表。

开始时每个方向人工核实少量岗位即可。看过 5 个广告只能说“这 5 个样本提到什么”，不能发布“全美国该岗位 80% 要求 SQL”。同一岗位经 aggregator、地域副本和多次刷新出现，要按可追踪的雇主岗位身份去重；重复发布不自动等于新增岗位。

| 信息 | 应标明的统计口径 | 常见误解应由界面避免 |
| --- | --- | --- |
| 岗位样本和技能提及 | 来源覆盖、检索条件、时间窗、唯一岗位数、缺失字段、岗位层级、去重规则。 | 广告提及频率不是实际工作时间占比；抓取样本不是全国统计。 |
| 薪资 | 数据源、年份、地点、经验范围、base / total、时薪 / 年薪、样本与缺失情况。 | 全职业中位数不是应届国际学生的起薪承诺；未写薪资不是 0。 |
| O*NET 任务 | 职业代码、版本和原始职业名称，说明不同公司 title 的映射有歧义。 | “business analyst”不能机械映射成一个唯一职业；职业家族任务不是每个岗位的全部要求。 |
| BLS 长期趋势 | 基年、预测终年、职业代码、净增长与年度 openings 分开。 | 年均预测 openings 不是现在开放的广告数，也不是净新增职位数。 |
| 雇主历史申请 / 批准记录 | 官方源、财年、记录单位、初次 / 持续等字段只有核实后才显示；公司实体匹配保留歧义。 | 历史记录不是这个岗位愿意 sponsor，也不是个人一定适用或能获批。 |

**官方统计示例：**本次打开的 BLS 市场研究职业页面显示 May 2025 中位年薪 $78,760、2025–2035 预测增长 7%、年均约 82,000 openings。页面说明 openings 含离开职业或劳动力市场后的替代需求。展示时应带完整期间和职业范围；不能写成“目前有 82,000 个适合你的岗位”或“应届薪资 $78,760”。[BLS 官方职业页面](https://www.bls.gov/ooh/business-and-financial/market-research-analysts.htm)

**核实中的一个反例：**Google 官方课程页上方显示 $75,000+ / 127,000+，FAQ 仍出现 $59,000 / 213,000。本文未确认两组数据的完整统一口径，不将它们用作当前市场事实。即使来源是官方营销页，数据也需逐条绑定期间、定义和来源，不能只摘一个更好看的数。[本次观察页面](https://grow.google/certificates/digital-marketing-ecommerce/)

DOL 的 [OFLC Performance Data](https://www.dol.gov/agencies/eta/foreign-labor/performance) 在官方搜索摘要中描述行政申请披露数据；本次打开页面及记录布局遇到抓取失败 / 403。USCIS 的 [H-1B Employer Data Hub](https://www.uscis.gov/tools/reports-and-studies/h-1b-employer-data-hub) 及解释页也未能读取。因此本报告**没有核实当前完整字段、覆盖期或导入接口**，不据此实现赞助概率、个人许可判断或已验证的 sponsor 数据源。接入前须读取相应版本的官方记录说明和数据，验证公司匹配及统计单位；不使用冒充政府域名的镜像。

## 8. 第一版范围与当前领域基础的对应

**优先交付：**首 15 分钟先留下两个有来源的方向假设和一个用户选定的验证行动。可纠正的职业档案、项目事实 / 证据卡、自写小项目 brief、逐步减少提示的练习、导师问题包和少量里程碑围绕这条旅程逐步进入。先跑通第 3 节，再扩大方法库；不能用“先完整上传项目 / 简历”阻塞第一次探索。

产品页需要把“草稿已准备”“已连接工具”“经授权完成真实行动”“结果有何来源”分开。聊天或自动化成功不能自动记成投递；导师草稿不能记成真实联系；学习完成不能记成能力认证。

大规模岗位 feed、导师供给与预约、真实雇主实践、第三方测评、内容授权、自动投递都需要独立接口和运营验证。此研究并未证明这些连接可用。现有语音、浏览器等通用底座是执行能力，不应成为求职效果的证据。

2026-10-06 只读检查 `packages/career-core` 的纯领域基础：七个 skill 分别有目标、输入、工具、产物、审阅标准和停止条件；准备器只给 `ready_for_draft`，明确外部动作禁止和必须审阅；进度按 owner 与 subject 去重，撤回 / 拒绝会影响当前进度；模型练习评分不写成已掌握。这与本研究方向一致。它目前是尚未挂接 runtime 的基础，不能描述为已实现上述端到端体验。

下一步设计需要保持：本人确认与独立核验的不同含义；导师评价的明确范围；同一项目的版本与独立尝试身份；时间 / 隐私预算；知识权利和有效期；将来修改方法时冻结已执行版本。申请等数量可以是私有旅程记录，不应直接进入分数、等级或竞争榜。
