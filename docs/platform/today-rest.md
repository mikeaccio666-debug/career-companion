# 休息选择与每日规划来源

依据产品 02 §9.3、05 §2.2、09 第 6 步。已接真实保存和 Web 设置入口；每日计划、晨报、通知 worker 尚未完成，不能把保存成功理解为调度系统已上线。

## 用户可做的事

在 `/me/companion` 的「先歇一会儿」中选择「今天不想」「歇 1 天」「歇 3 天」「歇 7 天」。先保存每日时区；没有时区时明确提示，不猜浏览器时区。首次选择默认保留面试和截止提醒；休息有效期内「都关掉」也关闭这两类。新的有效休息选择保留当前关闭偏好；旧休息完全到期后，新选择恢复默认保留。

「今天不想」持续至保存时所选时区的次日零点。「歇 N 天」采用从保存时起、N 个当地日历日后的相同当地时间，页面明确说明并显示绝对截止时间。由 PostgreSQL 和数据库时钟计算：跨 DST 可能是 23 或 25 小时；目标时间遇缺失/重复小时按 PostgreSQL 的 IANA 时区解析规则确定，最后保存 UTC 瞬间。调整每日时区不会提前结束已经保存的休息。没有客户端到期时间、客户端身份或外部执行授权字段。

同一操作重复发送不重新计算到期时间；多设备按修订冲突处理。失去确认时保留原操作，可核对或重试；离线恢复只读取，不自动重复写。账号变化清空界面状态，晚到结果不能进入新账号。刷新后读取实际保存的记录；未收到确认的内存命令不写 localStorage。

## 持久化与接口

- `GET /today/pause`：本人当前选择；尚未选择为 revision 0。
- `POST /today/pause`：`companionId`、`operationId`、`expectedRevision`、`choice`。choice 仅 `today / 1_day / 3_days / 7_days / reminders_off`。
- `GET /today/pause/operations/:id`：原操作结果及当前最新选择，用于结果未知后的恢复。

均使用现有固定账号会话、请求来源与限流检查、私有不缓存响应。新写入需要真实主理人诞生、学生账号、协议和邮箱验证；读取与旧操作恢复保留已有本人访问规则。最终会话复核失败会回滚。

迁移 `082_today_rest.sql` 新增 `platform_today_rest`：本人、主理人、修订、操作、加密记录、创建时间。本人直接外键与 `(companion_id,user_id)` 复合外键均级联删除；复合主键及操作唯一约束，沿用不可改写记录触发器。加密内容绑定表、字段、操作、本人和修订，读取核对 SQL 元数据与加密命令摘要。导出只给本人解码后的休息历史，不给凭据、加密命令或认证版本。分页超过 100 条验证，账号删除验证。

已实际检查迁移后列与外键并更新账户数据审阅基线：168 表、161 项需要投影、7 项排除。当前核心导出 95 项包含、66 项仍未实现；含文件路径为 98 项包含、63 项仍未实现。导出完成度仍为 false。

## 每日规划消费者

`TodaySources` 在与其他来源相同的账号锁及事务内读取 `TodayRestService`。rest 来源含保存修订、是否抑制任务、当前本地日对应的 optedOutDate、有效 pauseUntil、是否暂停其他主动消息以及提醒是否关闭。用户选择变化或休息到期使旧来源摘要失效；读取过期状态不改写历史。

这组来源没有补造尚缺失的危机覆盖、行为偏好、旅程焦点、每日任务历史或练习回执。后续计划接受、后台生成和通知发送必须在提交前重新读取并执行这些限制；当前没有接通定时发送，也未声称完成 `canSendProactive`、完整 `GET /today` 或主对话语义识别。

## 与今天页一致的后台恢复

休息面板现在与本人任务共用可见性/网络门槛：隐藏或离线时清空已读偏好并暂停观察，两者同时恢复才重新读取；原未知命令不会自动重发。重新读取的较新偏好不会被之前迟到的回执覆盖。保存休息后刷新本人任务也遵守此门槛。实现和本轮验证范围见 [每日计划](daily-plans.md#页面后台断网与草稿恢复2026-10-09)；休息规则、存储和提醒能力未改变。
