# 求职操作的产品事件

依据产品 07 §7.5 与 09 第 8B 步。迁移 089 建立 `platform_product_events`，接通真实投递、故事和简历保存服务，迁移 090 再接通反馈提交；不是浏览器点击上报接口，也不是完整 P0 指标系统。

## 已接通的事件

| 事件 | 实际触发 | 唯一允许的 props |
| --- | --- | --- |
| application_stage_changed | 本人成功修改申请，stage 或 closedReason 与之前不同 | from_stage、to_stage、closed_reason；无结束原因为枚举 none |
| feedback_submitted | 学生明确分享并成功保存反馈 | category=incorrect / out_of_character / too_long / sales_pressure / other |
| story_saved | 本人新建或编辑 STAR 故事 | source=user_entered |
| resume_version_created | 真正新建简历版本，包括实际文件抽取、粘贴、从已确认版本另存 | source=upload / paste / derived |

故事确认、简历确认/改稿/归档、列表读取和相同申请状态的重复选择不生成这些事件。故事保存次数不是不同故事数，投递事件不是已核实提交或面试成功记录。尚不能凭这些事件声称完整激活、留存、转化或推荐漏斗可用。

事件只由服务端在真实写入事务内产生，当前 channel 固定 web。共享契约逐事件列出字段及枚举，拒绝额外键、自由文本、访问器、无效状态和未知事件；数据库约束再次检查同一白名单。不会存储标题、原稿、STAR、JD、URL、模型数据、身份日期或源对象 ID。user_id 用于本人归属与删除，仍属于个人数据。

## 开关与一致性

`PLATFORM_PRODUCT_EVENTS_ENABLED=1` 才采集；未设置或 0 都不写入，其他值启动时拒绝。示例配置默认 0，没有更改实际运行配置，也不接第三方分析服务。

操作重放在领域回执路径返回，不再次发事件；打开开关后重放过去未采集的操作也不补录。事件 ID 由用户、操作及事件名确定；数据库冲突不能悄悄替换内容。启用时事件插入和原业务写入共同提交，事件失败或最后会话复核失败则整体回滚。没有后台异步补写或“已保存但未记录”的假成功。该路径不接危机回应，采集失败不阻挡危机资源。

## 导出、删除与保留

表包含 id、user_id、event、props、channel、occurred_at。user_id 直接外键关联用户并随账号删除级联清除，没有凭据、共享组织关系或独立保留义务；按真实迁移目录核对字段与外键后，纳入账户数据覆盖基线。

已接入现有 `AccountCoreExport` 的 productEvents 节，沿用真实密码复核、固定会话与同一账户快照，按 100 行分页读取、再次校验枚举。关闭采集不隐藏过去仍在保留期内的事件。现有账户导出整体仍标 complete=false；新增表覆盖不解除其他未完成导出项。

按 UTC 日历保留 13 个月。清理器一次最多 100 行，按 occurred_at/id 排序并使用 SKIP LOCKED；挂在现有 worker 的维护循环，即使停止采集也继续清理。失败只输出固定错误提示，不记录事件或账号。实际删除取决于 worker 持续运行与积压处理；未宣称生产清理或告警已经验收。
