# 产品反馈：持久化与运营处理接口

对应产品 07 §6.4、§7.5、§8 和 13 §8.5。已完成服务端反馈记录、运营收件箱/处理回复 API，以及学生页面的反馈表单与进展展示。**运营界面、逐消息入口和发布前运营规则仍未完成**。

## 接口与接收方

- `POST /api/platform/feedback`：真实登录的学生提交。必须明确 `shareWithSupport:true`。字段为操作编号、已展示并确认的接收组织编号、五种问题分类、固定页面类别、描述、可选的自愿粘贴片段；拒绝客户端 owner/org/完整 URL/对话编号等附加字段。
- `GET /api/platform/feedback/availability`：当前真实接收组织的编号、显示名与可用状态，不包含员工身份。
- `GET /api/platform/feedback/operations/:id`：只读核对原操作和目前的处理状态，网络恢复不会自动重发。
- `GET /api/platform/feedback`：本人列表，每页 50 条，按 UUID 稳定分页；`after` 为下一页坐标。此顺序不代表时间排序。
- `GET /api/platform/feedback/:id`：本人查看当前状态和完整的处理回复历史。
- `GET /api/platform/staff/feedback`：指定支持组织的真实员工 `ops/org_admin` 收件箱。支持 `after`、`status`，每页 50 条。
- `PATCH /api/platform/staff/feedback/:id`：员工按读到的版本分拣为缺陷、质量、政策、内容缺口或需求，写入处理状态及学生可见回复。解决/关闭必须有非空回复。后续可重新进入处理中，并保留前次处理历史。
- 全部接口固定当前账号、真实会话、请求限流；写入遵守原有 Origin/CSRF 校验；响应 no-store。反馈可用于报告初见/同意流程的问题，不要求已接受模型调用条款，不调用模型。

服务器配置 `PLATFORM_SUPPORT_ORG_ID`，默认未配置。必须是现有 active 组织，且有 active 的真实员工 ops/org_admin，提交才接受。新提交必须带预览过的 `recipientId`；与服务器配置不同则拒绝，不能在接收方改变后悄悄改发。此次新旧 API 尚未公开发布，前后端应一同升级。此配置不自动使用导师组织，不创建员工或授予组织权限。只配置 UUID 不能代替真实人员排班、客服邮箱和运营使用界面验收。

学生提交后是“已提交”，表示保存到了指定组织的可读收件箱，**不代表运营已经阅读，也不会发送邮件/推送**。员工读取和更改都通过 StaffAccess 记审计；审计失败则回复不生效。撤销角色或停用组织后不再允许工作人员读取/回复。学生仍能读取已有记录。更换支持组织配置不会转移旧记录，需要先制定旧收件箱接续安排。

## 数据与隐私

迁移 090 增加 `platform_product_feedback` 和 `platform_product_feedback_operations`。正文、用户自愿粘贴的片段和回复历史均加密，AAD 绑定表、记录、本人和版本。当前记录须匹配最新加密操作回执；篡改、缺失、跨记录替换会拒绝读取。重复操作返回同一反馈，陈旧版本或复用编号改写内容返回冲突。

暂不读取任何聊天表。自愿片段是用户提供的文本，不声称是已验证的消息副本，不会自动附上相邻消息、档案、截图、网址或令牌。学生 UI 先展示准确的共享内容与接收方，再由用户主动勾选确认；没有勾选不能提交，片段默认空，取消附上会清空输入的片段。

每个学生最多保留 500 条反馈，每条最多 100 次处理更新；描述/回复最多 4000 字符、片段最多 12000 字符。达到上限如实拒绝，不丢弃旧记录。此为实现的资源边界，不代表已定长期产品配额。

账户导出内部捕获器包含本人解密后的反馈和学生可见处理历史；操作回执只投影编号、反馈编号、版本、时间，不导出请求摘要/密文。针对本条反馈的员工处理审计以去除员工身份的关联元数据进入组织访问历史；批量收件箱访问不伪造成逐条已读回执。账户删除通过直接及组合外键级联删除两张表。目录审阅增加到 180 张表；内部导出仍 `complete=false`，不能当作完整用户下载入口。

启用现有 `PLATFORM_PRODUCT_EVENTS_ENABLED=1` 时，同一提交事务写一次 `feedback_submitted`，仅带固定分类，不带正文/片段/记录 ID。默认不开启；关闭时不影响反馈保存。反馈全文不进遥测、日志、知识库或模型评测集。

## 学生页面与恢复行为

已在 App 的固定账号 Provider 内接入通用「反馈」入口。已登录的学生可从初见、邮箱/协议确认与后续学生界面打开；不会开放聊天、工作台或越过第一封信闸门。界面为桌面 480px 弹窗、手机底部抽屉，复用 08 的颜色/字体规范。危机阻挡与连接重新确认期间关闭并暂停反馈界面，保留同账号内存中的草稿和待核对操作。

填写 → 预览描述/片段/接收方 → 主动同意 → 提交。UI 不发送 URL/query/hash、整段聊天或页面快照。关闭后草稿仍留在本页；刷新、退出或账号改变后清除；不写 localStorage/IndexedDB。未提交草稿或待核对操作离开页面时触发浏览器原生提示。

「我的反馈」读取真实记录、状态和回复历史，支持分页与手动重新读取。网络中断、后台或关闭抽屉时取消读取并清除显示数据；恢复后重新读取。回执丢失时锁定原操作，只读核对；只有用户点击原操作重试才 POST，同一次提交不换编号。读取失败不显示虚假的空列表；未配置有效接收方时明确不可提交。
