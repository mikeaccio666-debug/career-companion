# 原文件移除与真实存储清理

依据 09 §3A 的 DELETE /uploads/:id，以及原稿版本的来源与本人管理规则。网页在实际本人已上传文件列表提供「移除原文件」，确认后停止原文件使用；已保存的独立简历版本和对话文字保留。不是申请提交、专家授权或模型调用，也不自动删除独立文本副本。

## 持久化与本人权限

DELETE /uploads/:id 的闭合输入只有 operationId。真实登录、账号窗口头、CSRF 与固定会话核验后，在同一个有界事务与 owner 锁内保存原文件清理请求、解除本人 artifact 的原文件链接并删除实际 upload 行。准入撤回后仍允许本人隐私删除。中途会话变化回滚整个事务，文件访问与引用不会处于半撤销状态。不存在或外人的文件返回不存在，不接受客户端 storageKey、owner、已完成状态或租约。

迁移 061 追加 platform_upload_removals 与只追加的 platform_upload_removal_events。文件名称、实际存储坐标、接受时 auth_version 和存储 scope 保存在 DataCrypto 认证密文中，不存原始文件字节。每次合法状态更新增加 generation；读取复核独立最大事件版本、完整记录摘要、真实查询投影与认证密文，旧有效快照不能回滚当前状态。原文件的 UUID 不由客户端指定或复用。同一文件重复删除返回原真实请求的当前回执；同一已接受的 operationId 用于不同文件明确冲突；重复文件返回原请求，不把新的冗余点击冒充新请求。

原文件行在清理请求提交时消失，现有原文件读取、列表、正文抽取与依赖端口因此不能再获得它；生成结果的 artifact 行保留，但不再声称原文件可用。既有 audio transcription 外键按原约束级联删除相应来源回执。简历原稿是之前保存的独立版本，其真实初始文件指纹与历史文字仍可认证，不依赖原文件继续存在。

## 清理与恢复

首次 HTTP 请求尝试处理已持久化请求。内部清理只能领取已有真实请求，不能凭文件 ID 新签发删除权限。数据库锁内创建随机租约 token，租约 30 秒；活跃租约阻止其他进程重复领取，过期才可恢复。存储操作使用五秒取消信号，S3 SDK 收到真实 abortSignal；本地 unlink 等待实际文件操作返回。删除调用之后，只有同一存储 scope 的真实 stat 确认当前文件不存在，才能在仍有效且匹配的原租约下写 removed 回执。成功返回的存储调用本身不代表文件已经消失。失败、未知结果或取消都保留 pending，原文件访问不会被恢复；晚到的旧租约完成不能覆盖新结果。

scope 是实际本地绝对存储目录，或实际 S3 endpoint / region / bucket 的内容地址；不含凭据，不发送给用户。更换存储位置后不在新位置伪称清理了旧文件，旧 scope 请求保持待处理，必须在原存储配置下恢复。缺少 DataCrypto 或真实存储标识时，此能力明确不可用。

worker-main 在启动与既有每 15 秒恢复循环接入恢复器，一批最多 20 条；每个清理记录仍按实际数据库租约处理。已提交的本人隐私删除允许在会话或账号之后失效时继续完成，因此待清理坐标不会被账号外键提前抹掉。此批验证了真实数据库恢复器，尚未启动或部署新版本 worker 进程，也未声称生产调度和重启演练通过。

## 回执和网页恢复

- DELETE /uploads/:id：当前存储文件真实不存在后 200 / removed；仍待清理则 202 / pending，不返回模糊的成功删除文案。
- GET /uploads/:id/removal：本人真实当前回执，不返回存储 key、scope 或租约。
- GET /upload-removals：本人历史列表，每页 50 条，实际数据库游标保留时间精度。

回执包含实际 owner、文件 ID、原操作 ID、文件名称、请求时间及真实移除时间。网页检验归属与目标文件；pending 显示「访问已停止，等待存储清理」。未知写入保留原操作供查询和重试，不把一般 404 当作删除失败。刷新后从服务端读回历史，不依赖浏览器持久缓存；账号变化与卸载取消请求、清空私有选择与回执。

云存储检查仍需真实 S3-compatible 集成环境；这里的消失判定只覆盖当前 API 可访问对象。本批没有验证对象历史版本、备份或冷存储的彻底擦除；其保留与清理政策必须在上线前明确并验证。没有把账号整体删除及所有历史遗留 blob 统一清理接通；本批只恢复已经由本人提交的原文件删除请求。已完成回执的保留期限与账号删除后的回执清除仍需产品隐私与运维方案明确。
