# 第一封信的上下文组装与候选稿

依据 02 §3.3、§3.4、§5.4 和 05 C7，接续真实 O2 来源与独立后台通道。当前实现的是服务端生成准备与候选稿解析，还不是可发送的第一封信。

## 实际来源

FirstLetterSources.prepare 先冻结服务端提供的队员配置与落款日期，再读取本人真实 C7/direct_letter 来源。出生时保存的名字、用户起名来源、印章、墨色和经完成回执认证的说话方式卡/示例加入原来源快照；人格预览的 companionId、版本和墨色必须与诞生相符。sourceId 覆盖这些资料。读取仍经过原身份、协议、真实选择和安全检查，没有改用当前可编辑页面字段拼凑人格。

模型只接收名字、说话方式、示例、情绪语言、O2 白名单结构值、所需事实数量、已提供的队员名单和服务端日期。账户/会话/答案 ID、原始问卷、身份阶段、凭据及来源回执不进入 messages。完整 preparation 含私有来源坐标，禁止整个发送给模型、公开返回或记录日志。

## 策略与格式

代码拥有的 system 策略要求 AI 披露、用户起名、记忆同意与查看修改位置、对外待确认/逐项授权/本人最终提交、真实事实、已启用队员、三件事引导和人格语气。名字与说话方式等在独立 user JSON 数据消息里，不能改变平台规则。提示词不证明模型会遵守这些要求。

队员必须显式传入；空名单不会自动采用 P0 名单。配置版本、日期、策略及来源参与 preparationId，变化必须重新准备。当前没有把产品 P0 枚举当成真实上线开关，也没有新增开关：后续任务服务须从实际发布配置提供名单和版本，并在发送/保存前重查。日期由任务服务按用户时区计算后提供，本函数只核对有效日历日期，不授予时钟权威。

情绪语言 zh/en/either 原样保留，未选择为 null；未选择时提示词暂用当前中文 Web 界面语言，不声称用户选择了中文。日期、签名、印章由服务器附加，不让模型杜撰。当前长度按 Unicode 码点计算，正文连同名字、日期和换行最多 350；英语真实可用性仍需评测，不能凭结构测试声称自然流畅。

输出结构只有 body 和 factReferences。引用使用 study/graduation/roles/search_stage 这些本次可用的短标记；服务器把标记映射回真实 source_ref。零条事实要求零引用，一条要求一条，多条至少两条，重复同一问题不能凑数。不存在的标记、额外来源 ID、不在正文的引用、超长内容均拒绝。

## 候选稿不是发布许可

parseFirstLetterCandidate 的唯一成功状态是 requires_full_output_check，assurance 明确为 structure_and_reference_membership_only。它只核对格式、引用成员关系与正文引用位置，**不证明引用符合来源含义**。例如把已填学历说成博士，即便绑定了 study，仍只能成为待检查候选；测试特意覆盖此情况。必含语句、人格、语言、真实事实和禁用内容仍须在同一共用整段输出校验器中检查，然后才能持久化或发布。

后续已接入 [第一封信共用规则检查](first-letter-output-check.md)，明确违规会被拦截，其他候选仍需语义复核；不能用人格预览模式批准信件。[内部语义复核与一次重写](first-letter-semantic-review.md) 已实现调用协议，但还缺可靠的任务持久化接入、真实模型质量评测、费用预留/结算、持久化后台任务与恢复、post 主线发布和唯一送达回执。没有设置 C7 完成、生成三件事或解锁导航。C2–C6 和中途离开超时路径也仍待实现。

不新增数据库表、不迁移主库、不调用付费服务、不部署、不重启主预览。
