# PR3 前模型评测准备

依据 [09 实施路线](../product/09-implementation-roadmap.md) 第 1 步和 [15 Agent 引擎](../product/15-companion-agent-engine.md) §1.2。本阶段只准备评测，不改变产品决定，也不调用商业模型。

## 样本与比较

主理人、前辈、投递官、面试官各 30 段，共 120 段低价档；从同批固定抽 20 段正式档，每人 5 段。低价档先跑 12 段，每人 3 段，确认用量后再外推。正式档费用需要自己的小样本或保守预留，不能套用便宜模型的费用。

脚本使用虚构 STEM 硕士、项目、公司和职位，不包含个人探索或真实申请材料。每位发言者有 15 个语义场景的中英文版本，因此是 60 个语义场景、120 个语言脚本。预置历史只是测试输入，不证明产品已经生成或持久化过这些对话。期待行为用于后续评分，不能反过来塞给模型当答案。

## 使用与边界

`pnpm --filter @companion/platform-api eval:plan`（或加 `--dry-run`）只打印样本 id、分布、候选价格、摘要哈希和未测指标；不读密钥、不创建 runtime、不访问数据库或网络。任何其他参数，包括 `--live`，都返回 `EVAL_DRY_RUN_ONLY`。

独立 probe 可由测试注入 `streamModelStep` runtime，经真实 `ProviderAdapter` 和共享循环运行；没有对学生 HTTP 开放。它只有协议与循环基线：首次原始 delta、总耗时、调用用量与预算账本。提示词是标注过的测试草案，输出只保留长度与摘要，质量分数为 `null`；不是主理人的正式人格、真实身份授权、转发卡或逐句校验流程。当前 CLI 不调用这个 probe。

不能报告已校验的主理人／卡片首句、姓名路由准确率、转发卡逐字、校验误杀、缓存命中，以及持久化插话、停止、续传、后台进度。当前缺少对应 runner、校验器和事件表；用量接口也没有 cached token 分项。规划输出一律用 `null + blocked`，不填 0 或模拟通过。

路线要求 PR3 开工前测转发卡和校验误杀，却把真实转发卡安排在 PR4、校验器安排在后面的第 2 步。这是需要对齐的时序冲突。范围明确前，PR3 前置门保持 blocked；局部真实模型基线即使完成，也不能自动通过完整前置门。本阶段没有实施轮次服务或调整产品文档。

## 费用与记录

价格候选依据 2026-10-07 核对的 [OpenAI 官方价格](https://developers.openai.com/api/docs/pricing)、[Luna 模型页](https://developers.openai.com/api/docs/models/gpt-6-luna) 和 [Sol 模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)。候选用 1,050,000 的上下文总窗口作为保守输入费用预留上界，不能理解为可发送这么多输入后再追加输出；输入和输出共享窗口。计价使用 Standard 长上下文输入／缓存写入的最大单价和输出单价，不声称享受缓存折扣。候选只是研究记录，尚未成为人工批准的模型配置和预算；Fast、区域或其他计价需要各自核对。

评测账本使用整数 microUSD，按每个真实请求预留，记录成功后才可发请求。报告的用量有效且结算持久化成功后，只释放确认未消耗的预留，保留实际费用；缺失／非法用量、绑定变化、超预留或写入失败均保留预留并停止整批。失败请求也要计量，重复事件不能重复结算。账本只写 id、枚举和数字；不写密钥、消息、模型输出、工具参数或结果。

预算逻辑不替代商业调用开关、人工批准或供应商账单。本地预算按已核费率估计，未来真实运行需要绑定实际配置；当前没有跨进程续跑或账户级硬限额。当前用途仅覆盖隔离文本基线；之后真实全链路的分类、校验、评审等模型调用也须登记并计入同一评测费用，不能当作已覆盖。真实模型结果、延迟、质量和费用仍未验证。

## 验证

API 类型检查通过；4 个新增测试文件共 35/35 通过，没有跳过。实际 `eval:plan --dry-run` 命令成功，输出 120 段脚本、12 段试跑与 20 段正式抽样的规划，真实模型调用为 0。测试使用虚构资料、假 runtime 和私有内存账本，验证逐请求预留／结算、未知用量停止、配置冻结、脚本分布、环境变量无法启用 live，以及敏感错误和模型文字不进入结果记录。没有执行付费评测、更新产品方向或部署。
