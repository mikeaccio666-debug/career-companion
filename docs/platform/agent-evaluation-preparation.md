# PR3 前模型评测准备

依据 [09 实施路线](../product/09-implementation-roadmap.md) 第 1 步和 [15 Agent 引擎](../product/15-companion-agent-engine.md) §1.2。本阶段只准备评测，不改变产品决定，也不调用商业模型。

## 样本与比较

主理人、前辈、投递官、面试官各 30 段，共 120 段低价档；从同批固定抽 20 段正式档，每人 5 段。低价档先跑 12 段，每人 3 段，确认用量后再外推。正式档费用需要自己的小样本或保守预留，不能套用便宜模型的费用。

脚本使用虚构 STEM 硕士、项目、公司和职位，不包含个人探索或真实申请材料。每位发言者有 15 个语义场景的中英文版本，因此是 60 个语义场景、120 个语言脚本。预置历史只是测试输入，不证明产品已经生成或持久化过这些对话。期待行为用于后续评分，不能反过来塞给模型当答案。

样本、草案提示词与种子输入组成同一份不可变 study plan。计划固定低价档的 120 段和其中 12 段试跑，以及同一语料中的 20 段正式抽样；正式档可选择在这 20 段内先试跑，选择也写进计划摘要。每条记录使用 `development/<scriptId>` 或 `formal/<scriptId>`，绑定原脚本、种子输入、发言者、用途与阶段。模块捕获语料时先核对已审阅的原稿和两组固定抽样摘要，防止调用者在导入前修改公开数组后被当作原稿；有意更新样本需要审阅并更新这些摘要。改变脚本内容、沿用 id 替换历史，或用其他 120/20 个 id 冒充这批样本，均不能继续原计划。摘要用于确认本次研究输入，不是模型质量得分。

## 使用与边界

`pnpm --filter @companion/platform-api eval:plan`（或加 `--dry-run`）只打印样本 id、分布、候选价格、摘要哈希和未测指标；不读密钥、不创建 runtime、不访问数据库或网络。任何其他参数，包括 `--live`，都返回 `EVAL_DRY_RUN_ONLY`。

独立 probe 可由测试注入 `streamModelStep` runtime，经真实 `ProviderAdapter` 和共享循环运行；没有对学生 HTTP 开放。请求只使用预算内部冻结的绑定，另传的绑定必须逐项一致，输入必须与同一 study plan 一致；不一致时在预留或调用 runtime 之前拒绝。它只有协议与循环基线：首次原始 delta、总耗时、调用用量与预算账本。`baselineFirstDeltaMs`、`baselineCompletedMs` 包含循环与账本写入时间，不能称为供应商自身延迟。输入的 `toolCondition` 只是提示词资料，结果明确记录 `prompt_only` 和 `toolExecution = not_exercised`。提示词是标注过的测试草案，输出只保留长度与摘要，质量分数为 `null`；不是主理人的正式人格、真实身份授权、转发卡或逐句校验流程。当前 CLI 不调用这个 probe。

`runProviderPilot` 把同一计划的 12 段开发预试串行接到 probe：开始前检查全部 12 段预算绑定和全新预算，逐段等待无正文的结果摘要持久化后才开始下一段；失败、取消、未知用量或摘要保存失败立即停止，不自动预测放行、扩大到 120 段或调用正式档。一个预算实例只能启动一次，拒绝并发或重复运行。结果摘要被冻结，保存回调不能改写成功状态。`persistedCases` 是确认保存的尝试数，`completedCases` 是其中成功数；费用账本已完成但摘要保存失败时，报告仍保留已花费用，不能按未保存的摘要数退款。结果保存与费用账本目前由调用者注入，尚无真实落盘适配或 live CLI，也不支持跨进程恢复。

用户已限定真实调用只能使用 Luna；具体服务商、完整模型 ID 与本次费用上限仍待确认。候选价格和旧规格的正式档比较均不构成其他模型的调用授权。预试报告始终标明 `productGate = not_evaluated`、`qualityStatus = not_scored`，通过协议测试不等于产品质量通过。


不能报告已校验的主理人／卡片首句、姓名路由准确率、转发卡逐字、校验误杀、缓存命中，以及持久化插话、停止、续传、后台进度。当前缺少对应 runner、校验器和事件表；用量接口也没有 cached token 分项。规划输出一律用 `null + blocked`，不填 0 或模拟通过。

路线要求 PR3 开工前测转发卡和校验误杀，却把真实转发卡安排在 PR4、校验器安排在后面的第 2 步。这是需要对齐的时序冲突。范围明确前，PR3 前置门保持 blocked；局部真实模型基线即使完成，也不能自动通过完整前置门。本阶段没有实施轮次服务或调整产品文档。

## 费用与记录

价格候选依据 2026-10-07 核对的 [OpenAI 官方价格](https://developers.openai.com/api/docs/pricing)、[Luna 模型页](https://developers.openai.com/api/docs/models/gpt-6-luna) 和 [Sol 模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)。候选用 1,050,000 的上下文总窗口作为保守输入费用预留上界，不能理解为可发送这么多输入后再追加输出；输入和输出共享窗口。计价使用 Standard 长上下文输入／缓存写入的最大单价和输出单价，不声称享受缓存折扣。候选只是研究记录，尚未成为人工批准的模型配置和预算；Fast、区域或其他计价需要各自核对。

评测账本使用整数 microUSD，按每个真实请求预留，记录成功后才可发请求。报告的用量有效且结算持久化成功后，只释放确认未消耗的预留，保留实际费用；缺失／非法用量、绑定变化、超预留或写入失败均保留预留并停止整批。失败请求也要计量，重复事件不能重复结算。账本只写 id、枚举和数字；不写密钥、消息、模型输出、工具参数或结果。

记录“样本完成”要求全部调用已确认结算，且最后一次调用状态为 `complete`；失败、取消或中断的最后一次调用不能算完成。前面失败后重试成功的费用仍保留。预测只能使用计划固定的 120/20 个成员，以及已完成的固定试跑；费用预测中的 `ready` 只表示预算算术条件满足，不放行真实模型或产品前置门。

预算逻辑不替代商业调用开关、人工批准或供应商账单。本地预算按已核费率估计，未来真实运行需要绑定实际配置；当前没有跨进程续跑或账户级硬限额。当前用途仅覆盖隔离文本基线；之后真实全链路的分类、校验、评审等模型调用也须登记并计入同一评测费用，不能当作已覆盖。真实模型结果、延迟、质量和费用仍未验证。

## 验证

初次准备的 4 个测试文件为 35/35 通过。本次首轮 49 项通过后，独立复审仍发现了导入前修改原稿的缺口；修复后，5 个相关测试文件为 51/51 通过，没有跳过，API 完整类型检查通过。测试使用虚构资料、假 runtime 和私有内存账本，覆盖逐请求预留／结算、未知用量停止、固定样本与深层冻结、同 id 修改输入拒绝、每项请求绑定不一致在调用前拒绝、失败的最终调用不能完成试跑、重试费用保留，以及耗时包含缓慢账本写入。另以 5 个全新进程检验导入前改动原稿／抽样时拒绝，以及导入后原稿保持可用；这些进程包含在 51 项中，不额外相加。样本与价格源文件、四份草案人格文字均保持原字节／文字。

实际 `eval:plan --dry-run` 只输出 120 段脚本、12 段试跑与 20 段正式抽样的规划和摘要，真实模型调用为 0。环境变量不能启用 live，敏感错误和模型文字不进入结果记录。没有执行付费评测、更新产品方向或部署。预算算法原有的正式档至少 2 段完成试跑才采用 `own_pilot` 的条件保留；默认未选正式试跑时使用 `full_context`，本次不新定产品抽样门槛。


2026-10-08 补齐预试批次控制后，6 个评测测试文件 58/58 通过、无跳过，API 类型检查通过。其中新增 7 项覆盖固定 12 段顺序、末段绑定缺失时零调用、已结算失败请求停止、未知费用保留预留、摘要保存失败仍计费、取消以及并发／重复启动拒绝。全部使用虚构模型和内存保存回调；真实模型调用仍为 0。
