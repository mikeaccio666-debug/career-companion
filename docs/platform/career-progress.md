# 本人成长记录：项目与投递

依据产品 09 §3A、03 D9 / §10.3 与 career-core `careerProgress`。`GET /career/progress` 现在由 `CareerProgressService` 从真实项目和申请来源合并计算。统计用于本人查看，不代表模型共享上下文、技能掌握程度或完整成就系统。

## 数据与含义

- 项目：保留现有规则。本人录入算暂记，明确确认后算确认；编辑使确认失效，撤回与删除不计。本人统计包含自己的私有项目，内部输出只含证据坐标，不输出正文或敏感度。
- 投递：只有真实申请中本人明确选择过「已投」、且当前仍保留 `submittedVia=user_sends` 的声明算 `self_reported` 暂记。直接选择面试或 Offer 不推断已经提交。口头或书面 Offer、结束申请不把暂记升级为确认，也不抹掉已付出的记录。改回收藏清除声明，删除移除记录；删除原 JD 不抹掉仍存在的申请。
- 同一实际申请 ID 只计一次，编辑、阶段往返与操作重试不会增加份数。证据引用绑定当前真实申请版本；`occurredAt` 是该版本声明的更新时间，不是已核实的提交时间，不能用于推算每日投递量。
- 本路径不签发插件回执、不写 `user_confirmed` 投递证据，也不制造首份确认投递里程碑。未来可信插件来源必须单独接入。

返回 `coverage=['project','application']`。这里 application 仅覆盖本人看板的投递声明，不代表邮箱、插件、外部系统或历史投递已全部导入。其余类型的零值表示未接入，不应解释为用户现实中从未做过。

## 读取一致性与边界

两个来源在同一个有界事务、同一个真实学生账号锁下读取，逐条解密并核对当前不可变操作与事件。批量读取全部当前记录，不能拿列表第一页或 SQL 阶段计数代替证据；超过当前每类 500 条容量则明确失败。任一来源无法核实，整个请求失败，不返回看似完整的部分统计。读完再次核会话；接口拒绝客户端 owner、额外筛选和跨账号窗口，响应 `private, no-store`。

已撤回准入的本人仍可查看自己的现有记录；员工身份、已失效会话不可读取。此接口不授予模型读取权限或执行权限。申请的真实密文与不可变操作已持久化，当前统计直接派生，不再另存一份会失步的计数表。

## 验证与后续

隔离 PostgreSQL 与真实密码登录 HTTP 验证：项目/投递合并与纯规则输出相同、暂记不升格、删除/更正/重复操作、超过列表页的数据、跨用户、会话失效、原 JD 删除、旧有效密文回滚、损坏来源，以及实际 buildApp 装配。回归同时覆盖项目故事、投递和原准备来源。共 40 项相关检查通过（其中 8 项新增），API 类型检查通过；500 条项目与 500 条申请的虚构短正文夹具在未改变的 2 秒读取事务内完成验证。这不代表大正文、并发流量或生产压测已经完成。

本批无新数据库迁移、无 UI 改动、无付费模型调用；不改变主预览或生产数据库。练习、导师评阅、外联、面试证据及信件/网页中的成长展示仍需各自真实流程接入。学生对话引擎的评测前置条件保持不变。
