# 本人成长记录：项目、投递与面试

依据产品 09 §3A、07 P0-9 与 career-core `careerProgress`。`GET /career/progress` 由 `CareerProgressService` 从真实项目、申请和面试记录合并计算。统计用于本人查看，不代表模型共享上下文、技能掌握程度或完整成就系统。

## 数据与含义

- 项目：本人录入算暂记，明确确认后算确认；编辑使确认失效，撤回与删除不计。本人统计包含自己的私有项目，内部输出只含证据坐标，不输出正文或敏感度。
- 投递：只有本人明确选择过「已投」、且当前仍保留 `submittedVia=user_sends` 的申请算 `self_reported` 暂记。直接选择面试或 Offer 不推断已经提交。Offer、结束申请不把暂记升级为确认，也不抹掉已付出的记录。改回收藏清除声明，删除移除记录；删除原 JD 不抹掉仍存在的申请。
- 面试：只有本人明确标为 `done` 的当前日程算 `self_reported` 暂记。已安排、改期、取消不计；编辑轮次与时长保留当前状态。删除移除贡献，重新完成仍只计一场；原申请删除不抹掉独立保存的面试。此记录不证明参加、通过面试、完成模拟练习或提升技能。
- 每个实际记录 ID 只计一次。证据引用绑定当前版本；`occurredAt` 是该版本声明的更新时间，不是已核实的提交或面试结束时间，不能据此推算每日活动量。
- 本路径不签发插件回执，不把投递或面试声明写成 `user_confirmed`，也不制造确认投递、确认面试里程碑。

返回 `coverage=['project','application','interview']`。范围仅包含本人当前保存的项目、看板投递声明与面试完成声明，不代表邮箱、插件或外部系统的全部经历已导入。练习、导师评阅和外联的零值表示未接入，不能解释成现实中从未做过。

## 读取一致性与边界

三个来源在同一个有界事务、同一个真实学生账号锁下读取。固定会话坐标在异步读取前复制；来源逐条解密，核对当前不可变操作与事件，读完再次核会话。批量读取全部当前记录，不能用列表第一页或 SQL 状态计数替代证据。每类当前支持最多 500 条，超出明确失败。

面试来源核对全部最新非删除回执与当前记录是否一一对应，避免缺失记录被误当作零。此完整读取也供既有今天日程和每日计划来源使用；各调用方原有准入要求保持。任何来源损坏、回滚或无法核实，整个请求失败，不返回部分统计。

接口拒绝客户端 owner、额外筛选和跨账号窗口，响应 `private, no-store`。准入撤回后本人仍可查看现有成长记录；员工身份、失效会话不可读取。统计不授予模型读取权限或执行权限。结果直接派生，不另存会失步的计数表。

## 网页

项目故事页、投递看板和面试安排的列表接入同一个 `CareerProgressPanel`。四个计数为「已由你确认的项目」「待你核对的项目」「由你记录已投」「由你记录完成的面试」。卡片解释声明来源与当前覆盖范围，提供三个来源入口；不显示虚构日期、百分比分数或成功率。仅仍有本人确认项目时出现项目里程碑。

共享 `parseCareerProgressSnapshot` 校验 ownerId、严格的三项 coverage、policyRevision、范围和里程碑一致性。旧两项 coverage 响应整体失败；服务端与 Web 应作为配套版本交付。暂记面试可以非零，确认面试必须为零。

父页面读取、保存及写入结果未知时收起计数，处理结束重新读取，不因点击本地加一。八秒无响应、读取失败、断网、页面隐藏、账号失效和卸载会清除卡片中的私人值；恢复可见或连接后只发起读取。没有轮询或浏览器持久化缓存。这不代替父页面或全应用的离线清理验收。

成长卡片使用共享设计变量和 AI 标识，桌面两列、手机纵排，支持浅深主题。详情页不显示总数。未改变学生对话引擎的评测要求。
