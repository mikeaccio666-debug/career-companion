# 本人面试日程记录

依据产品 09 §3A 的面试数据表和 08 §7.17 的 InterviewRow，服务端保存用户明确录入的真实面试日程。面试间练习与复盘生成见 05 §2.5，作战简报及提醒见 05 §2.6；这些流程需要各自的运行通道，本批仅接通日程存储和接口。

## 记录与修改

每场面试关联一份本人保存的申请。创建时在同一事务读取并核对申请的实际版本，保存公司、岗位、岗位家族和原申请版本的最小历史引用；不复制 JD 正文、私人备注、材料包或身份数据。原申请随后删除时，历史面试记录仍可由本人查看和整理；新增面试必须重新核对真实存在的申请。

日期使用明确的 UTC 时刻，并保留用户选择的命名时区。接口不从设备时区、缺失时区或不明确的当地时间推算时刻。夏令时重叠的两个时刻必须由界面明确区分并由用户选择；网页转换、双时区显示和本人操作已接线，见 [面试日程网页](./career-interview-web.md)。

- 新建状态为 scheduled。
- 修改轮次和时长保留原时间及状态。
- 显式改期保存新的时间与时区，状态为 rescheduled。
- 本人明确标为 done 或 cancelled；这些操作不更新投递看板，也不启动通知或任务。
- 删除物理移除完整记录；观察或重试旧操作返回当前记录或已删除结果，不恢复历史内容。

轮次使用 04 §3.1 的 round_type 闭集。时长是本人录入的正整数分钟，上限采用存储整数边界，不代表推荐时长。每人最多 500 场属于当前资源边界；列表每页 50 场，按记录创建时间稳定分页，可按状态筛选。列表批量核对各记录的独立最新回执，不逐项执行额外回执查询。

## 账号和持久化

固定真实登录会话、学生账号、账号窗口和 CSRF；同一账号的写操作串行核对版本。新增、编辑、改期和状态变更需要当前协议与邮箱准入。准入撤回后，本人仍可查看、观察原操作和删除记录；退出或撤销会话后不能读取。

迁移 064 保存加密日程及不可修改的操作回执。完整日程含公司、岗位、时刻、时区、时长，仅存在认证密文中。回执只含坐标、摘要、动作、版本及服务端接受时间。每次读取以独立最新回执核对密文和镜像元数据；恢复旧密文、复制其他行密文或改动坐标会如实失败。账号删除同时清除日程和回执。

## 接口

接口根路径为 /api/platform/career/interviews，响应使用 private, no-store。

| 方法和路径 | 含义 |
|---|---|
| GET / | 本人列表，支持 after 和 status |
| GET /:id | 本人完整记录 |
| POST / | operationId、expectedRevision=0、applicationId、applicationRevision、roundType、startsAt、timeZone、durationMin |
| PATCH /:id | operationId、expectedRevision、roundType、durationMin |
| POST /:id/reschedule | operationId、expectedRevision、新 startsAt、新 timeZone |
| POST /:id/status | operationId、expectedRevision、done 或 cancelled |
| DELETE /:id | operationId、expectedRevision |
| GET /operations/:id | 查询原操作的真实回执与当前结果 |

客户端不能签发来源、所有者、确认时间、简报或复盘引用。briefId 和 debrief 当前恒为 null；未接日历 MCP、提醒调度、主理人回应或面试间练习；InterviewRow 的日程网页见上述独立说明，不向模型发送这些记录。

## 验证

真实 PostgreSQL 和密码登录 HTTP 测试覆盖原申请版本、准入与会话撤销、并发重复请求、过期版本、旧密文回滚、物理删除、账号级联删除、重复迁移和全部 500 场分页。契约检查覆盖十种轮次、UTC 时刻与命名时区、夏令时重叠的两个不同真实时刻及伪造来源和生成结果的拒绝。

## 完成记录与成长

本人标为 done 的当前记录会进入成长记录的暂记面试数量；改期、取消或删除后按当前记录重新计算，不代表面试通过或技能提升。面试列表展示与其他来源共享的成长卡片，来源认证、隐私边界与验证见 [本人成长记录](./career-progress.md)。
