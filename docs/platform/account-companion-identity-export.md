# 主理人名字与印章选择历史的私有导出

依据产品 09 §11 和 13 §4.5，账户捕获增加四个本人区段，对应四张已存在的个人表：

- `companionIdentityDrafts`：当前保存的名字、原始用户显示名、候选印章、墨色、命名版本和原生成/资源版本引用。
- `companionIdentityOperations`：完整的原命名命令和实际落地版本，不只导出最后一个名字。
- `companionIdentitySelections`：最近一次实际保存的印章选择及其当时的名字快照。`currentForIdentity=false` 表示后来改名使该选择失效，仍保留原选择，不把它当作当前确认。
- `companionIdentitySelectionOperations`：每次明确选择的原命令、独立选择版本和当时的完整名字快照。

`AccountCoreExport` 先在同一 REPEATABLE READ 事务内完成已有生成历史验证，再把其已验证的任务/预览投影作为内部归档输入交给 `AccountCompanionIdentityExport`。这些数据只用于核对私有历史，不是模型运行或命名执行权限；没有请求参数能提供这个来源，也不重复调用生成服务。

每份名字快照解密后匹配所属用户、任务、原生成版本、名字版本、原资源摘要和墨色；候选使用当时保存且摘要匹配的资源核对，不读取当前激活政策替代旧资源。印章必须属于对应旧名字的实际候选，并匹配原命名操作。当前版本必须对应最后一次原操作，命名与选择各自的历史版本必须完整、不重复。缺失、被篡改或回滚的历史不能产生一份看似成功的导出。

改名不重置选择版本；即使后来改回相同名字，也不自动恢复旧选择。导出保留这个区别。用户当前显示名、邮箱验证、模型同意或当前资源政策的变化，不会重写历史 `userNameAtSave` 或原候选。

四张表按 owner + UUID 游标完整分页，每页 100，服从账户归档的总大小限制；未计入输出字节的共享资源包最多缓存 8 份，缓存淘汰不删减历史；取消、晚到会话失效、损坏密文、跨用户密文或缺失资源会让整个事务回滚，密码再验证凭据仍可重试。无名字或选择时保持空，不创建默认值，不出生主理人，不调用模型。

只输出本人已保存的数据及资源引用。原始密文、会话/执行凭据、员工审核身份和共享资源全文不进入这些区段。共享 `platform_companion_identity_assets`/policy 仍保留为待审阅的组织数据，读取其原字节用于校验不代表该表已被全量导出覆盖。

本次无迁移：JSON 覆盖 106 表、剩余 58；带文件覆盖 109、剩余 55；另有 7 个既有豁免，总清单仍为 171 表。`complete=false` 保持，完整自助下载、其余资料投影和完整删除协调仍未完成。

测试使用虚构账户、独立 PostgreSQL schema 和 loopback 生成协议，覆盖真实改名/改选、改回名字后旧选择仍失效、资源/显示名/同意变动、105 次命名及选择跨页、四类密文损坏/串户、丢失或重复历史、真实旧快照回滚、历史命令与选择快照不一致，以及取消/鉴权/容量回滚。不调用付费模型。
