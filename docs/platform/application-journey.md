# 投递阶段与关怀期的共享规则

依据产品 05 §2.7、§3.1，03 §2.7 与 09 §3A。当前提交实现阶段值、本人变更意图的严格契约，以及 career-core 的纯状态规划；后续真实申请存储、阶段历史、关怀来源与看板必须消费这组规则。没有新建 HTTP 路径、任务签发或占位成功界面；完整 P0-9 仍未完成。

## 已实现的契约

`packages/platform-contracts/src/application-stages.ts` 提供 saved / applied / oa / interview / offer / closed、六个中性结束原因、五种 Offer 状态与三种真实投递通道的权威值和显示标签。本人阶段命令包含稳定 operationId、正整数 expectedRevision 与明确的新阶段；已结束必须选择原因，Offer 必须选择口头、书面、已接受、未接受或已过答复期。无关字段拒绝，不允许本人命令自行写 closedAtStage、submittedVia、来源、时间、actor 或执行权限。

状态描述不等于真实提交回执。submittedVia=null 表示尚无通道声明，不能由阶段选择自动推断插件已提交；公开客户端不能提供 extension / in_product 的回执归因。实际服务器写入路径必须区分本人记录「自己投过」和可信插件点击产生的回执，不能让模型或纯计划授予执行权。

## 纯规划与关怀规则

`packages/career-core/src/application-stage-policy.ts` 从实际旧状态、明确的阶段选择与调用方提供的规范时刻计算下一状态。首次结束的 closedAtStage 来自旧阶段；更正结束原因时仍保留当时结束的阶段。Offer 的 accepted 和 expired 都留在 offer，不自动结束；本人明确更正为其他阶段时清除不适用的结束或 Offer 字段，历史由实际写入器只追加保留。

仅当结束原因是 not_advanced / rescinded，且当时阶段是 oa / interview / offer，才规划 post_rejection 至时刻后 48 小时。saved / applied 的结束与 no_response / role_closed / withdrawn / declined 不触发。重复的同一结束与已经属于关怀范围的原因更正不延长已有窗口。规划中没有数据库、系统时钟、模型、浏览器、OAuth 或授权检查；它不代表关怀已经持久化或回应已经发出。

## 实际接入必须完成的条件

1. 从本人真实收藏的岗位创建申请，服务器核当前会话、账号、准入及真实来源；材料包和插件回执只能经各自可信路径关联，不接受客户端的已提交断言冒充回执。
2. 在同一账号锁和有限时事务中读取实际旧申请、核预期版本，写新状态、不可变操作凭证和阶段历史；服务器的数据库时间供给纯规划。同一操作重试只观察或恢复原结果，不重复推进状态。
3. 符合关怀规则时，同一事务记录真实关怀来源并更新主理人限制。现有 overlays=NULL 表示未投影，而非没有安全限制；不能为了追加关怀而默认制造一个安全的空数组，也不能覆盖真实危机或其他限制。
4. 初始回应经真实后台路径与原会话、当前安全门、费用、租约、校验和持久化接通；学生引擎的评测前置条件仍在，不使用固定文案伪称主理人已回应。
5. 看板的归属绑定客户端、领域接口和组件分开，实现真实列表、详情、变更、操作观察与更正。已结束采用中性标签，Offer 接受仍展示 Offer；失败或结果未知时不得乐观伪造已保存或已提交。
6. 真实 PostgreSQL、登录 HTTP 与接口协议测试覆盖跨账号、并发、旧版本、原操作重试、会话撤销、同事务关怀与事件，以及可信点击通道；在允许的环境中完成浏览器验收。

这些条件是后续实现范围，不能用本次纯函数检查替代。新申请 API、数据库迁移、学生看板、主动消息抑制及插件回执连接当前均未接通。

共享契约完整 40 项和求职内核完整 190 项通过，0 失败、0 跳过；两包类型检查通过。新增检查覆盖五种原阶段与六个结束原因的完整 30 种组合、全部 Offer 状态、重复与更正、未知字段、访问器、隐藏和符号输入，以及本人意图不能声明可信执行通道。上层 API / Web 类型检查也通过；日志与源码摘要保存在本提交的忽略目录。没有付费模型调用、真实申请、主预览更新或部署。
