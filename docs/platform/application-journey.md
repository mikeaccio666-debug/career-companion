# 投递阶段与关怀期的共享规则

依据产品 05 §2.7、§3.1，03 §2.7 与 09 §3A。阶段值、本人变更意图的严格契约与 career-core 的纯状态规划已接入真实本人申请存储、阶段历史、关怀来源与 Web 看板。完整 P0-9 仍未完成：主理人限制投影、即时回应和后续抑制通道尚待实际引擎接入。

## 已实现的契约

`packages/platform-contracts/src/application-stages.ts` 提供 saved / applied / oa / interview / offer / closed、六个中性结束原因、五种 Offer 状态与三种真实投递通道的权威值和显示标签。本人阶段命令包含稳定 operationId、正整数 expectedRevision 与明确的新阶段；已结束必须选择原因，Offer 必须选择口头、书面、已接受、未接受或已过答复期。无关字段拒绝，不允许本人命令自行写 closedAtStage、submittedVia、来源、时间、actor 或执行权限。

状态描述不等于真实提交回执。submittedVia=null 表示尚无通道声明，不能由阶段选择自动推断插件已提交；公开客户端不能提供 extension / in_product 的回执归因。实际服务器写入路径必须区分本人记录「自己投过」和可信插件点击产生的回执，不能让模型或纯计划授予执行权。

## 纯规划与关怀规则

`packages/career-core/src/application-stage-policy.ts` 从实际旧状态、明确的阶段选择与调用方提供的规范时刻计算下一状态。首次结束的 closedAtStage 来自旧阶段；更正结束原因时仍保留当时结束的阶段。Offer 的 accepted 和 expired 都留在 offer，不自动结束；本人明确更正为其他阶段时清除不适用的结束或 Offer 字段，历史由实际写入器只追加保留。

仅当结束原因是 not_advanced / rescinded，且当时阶段是 oa / interview / offer，才规划 post_rejection 至时刻后 48 小时。saved / applied 的结束与 no_response / role_closed / withdrawn / declined 不触发。重复的同一结束与已经属于关怀范围的原因更正不延长已有窗口。规划中没有数据库、系统时钟、模型、浏览器、OAuth 或授权检查；它不代表关怀已经持久化或回应已经发出。

## 实际接入必须完成的条件

1. 从本人真实收藏的岗位创建申请，服务器核当前会话、账号、准入及真实来源；材料包和插件回执只能经各自可信路径关联，不接受客户端的已提交断言冒充回执。
2. 在同一账号锁和有限时事务中读取实际旧申请、核预期版本，写新状态、不可变操作凭证和阶段历史；服务器的数据库时间供给纯规划。同一操作重试只观察或恢复原结果，不重复推进状态。
3. 符合关怀规则时，同一事务记录真实关怀来源并更新主理人限制。现有 overlays=NULL 表示未投影，而非没有安全限制；不能为了追加关怀而默认制造一个安全的空数组，也不能覆盖真实危机或其他限制。
4. 初始回应经真实后台路径与原会话、当前安全门、费用、租约、校验和持久化接通；学生引擎的评测前置条件仍在，不使用固定文案伪称主理人已回应。
5. 看板的归属绑定客户端、领域接口和组件分开，实现真实列表、详情、变更、操作观察与更正。已结束采用中性标签，Offer 接受仍展示 Offer；失败或结果未知时不得乐观伪造已保存或已提交。
6. 真实 PostgreSQL、登录 HTTP 与接口协议测试覆盖跨账号、并发、旧版本、原操作重试、会话撤销、同事务关怀与事件，以及可信点击通道；在允许的环境中完成浏览器验收。

当前已完成其中的本人记录、来源读取、同事务持久化、操作对账与看板；限制投影、回应、主动消息抑制、材料包、可信插件回执和浏览器验收仍未完成，不能用契约或构建检查替代。

## 本人申请路径与数据库（062）

`CareerApplications` 使用真实固定登录会话、学生账号、当前邮箱与协议准入；本人读取、操作结果观察和删除保留与现有私人资料相同的准入边界。创建命令只有实际收藏 ID、收藏版本和私人备注；`ManualJobs.readInTransaction` 在同一个有限时事务中核对真实来源、密文与最新不可变凭证。服务器保留当时的公司、岗位、地点、家族、截止和来源坐标，不复制 JD、岗位私人备注或身份原句。原收藏删除后，申请的历史概要独立保留；这不是当前可用的岗位来源，也不能继续用于原文检索或执行。

同一收藏最多有一条现存申请（包含已结束）；需要继续时本人可以更正原记录的阶段。明确删除后可新建另一条申请，新 ID 与旧操作相互独立。当前容量为每人最多 500 条现存记录；列表和历史每页 50 条，并提供真实 owner 游标，不以第一页冒充完整旅程。

应用记录完整状态与私人备注均加密，认证绑定本人、实际 ID 和版本。另有不可变操作凭证与不含备注/JD/公司正文的加密阶段事件，校验当前记录必须吻合独立的最新操作以及实际事件；旧有效密文不能回滚已生效的阶段。数据库时间决定版本事件与 48 小时来源；真实账号锁串行化同一人的操作，预期版本冲突返回 409。同一操作只恢复原凭证和目前的真实状态，不能重复记账，删除后的迟到创建也不能复活旧申请。

本人把阶段改为 applied 时，服务器记录 user_sends，界面显示「由你记录已投」。直接更正 OA/面试/Offer 允许没有投递通道声明。该路径拒绝客户端 packet、来源、actor、执行权限、extension / in_product 通道，不签发提交回执，不改动材料包状态，不联系外部网站。

符合关怀规则的阶段变更在同一事务写真实事件及 48 小时来源，重复结束或已经属于关怀范围的原因更正不延长窗口。内部读取器按数据库实际当前时间筛选有效来源并核对加密事件/凭证；申请删除保留最小历史与关怀证据，避免删除绕过限制。账号仍存在时事件和凭证不可改删；账号删除级联清理全部。现有主理人 overlays=NULL 或其他已投影限制原样保留，不能默认 []；当前来源日志没有替代实际 overlays 投影，也没有宣称已抑制主动消息或已发出主理人回应。

## Web 与接口

网页 `/journey/applications` 使用独立的严格领域契约、账号绑定请求客户端和页面组件。从真实收藏选择创建；读取详情、更正阶段、选择结束原因/Offer 状态、保存私人备注、读取分页历史和明确删除。桌面按六阶段分列，已结束默认折叠且不显示数量；小屏以分段控件显示单阶段列表，无横向滚动。已接受/过答复期 Offer 仍留在 Offer。计数仅说明当前已读取的活跃列，不生成累计结束统计。

写入超过 8 秒或返回不确定时，页面不更新成假成功；保留原 operationId 和完整原命令，可只读查询原操作结果或重试原命令。结果未找到不能推断没有保存。版本冲突保留未提交编辑供重新核对。账号变化或页面卸载会撤销请求、清除私人组件状态，不写浏览器持久缓存。

接口均受真实 cookie、账号窗口、CSRF、额度与固定会话约束，返回 private, no-store：

- GET/POST `/career/applications`：真实 owner 分页/建立记录；GET 可按 saved/applied/oa/interview/offer/closed/active 筛选。
- GET/PATCH/DELETE `/career/applications/:id`：读取、更改私人备注、明确删除。
- POST `/career/applications/:id/stage`：本人版本化阶段更正。
- GET `/career/applications/:id/events`：只追加历史分页。
- GET `/career/applications/operations/:id`：原操作真实结果观察；历史申请已删除时返回真实 tombstone，不复活内容。
