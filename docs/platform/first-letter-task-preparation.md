# 第一封信：持久化准备记录

依据产品 02 §5.4、05 初见流程和 09 后台生成要求，接续来源读取、内容编排、共用校验与语义复核。本步只给实际 C1「直接写信吧」路径建立可重复读取的准备身份；不扩展到尚未实现的 C6 或离开 30 分钟路径。

## 行为

FirstLetterTasks 是 buildApp 装配的内部服务，没有新增 HTTP 路由。prepare 必须读取已认证用户的真实诞生资料、人格和 C7 选择回执，重新检查当前协议、邮箱、会话及安全状态，然后用明确的服务端名单版本、启用队员和日期编排输入。

同一用户、同一 welcome 只保留一条记录。来源读取先取得已有的用户锁，再锁任务行；并发准备返回相同任务 ID 和创建时间。数据库唯一约束是第二道保护。记录状态只有 prepared，不代表排队、调用过模型或可发送。

read 在新的服务实例中重新读取原始资料并编排，比较 sourceId、preparationId、规则版本及归属坐标。名单、日期或来源发生变化时返回 FIRST_LETTER_TASK_PREPARATION_CHANGED（409）；不覆盖旧记录，不悄悄另建任务。损坏或移位的加密内容返回固定 503 错误；其他账户的任务标识返回 404。返回前再验证会话和取消信号，失败回滚。

**配置过期后的显式重新准备尚未实现。** 后续必须结合持久化阶段、已有调用和费用设计刷新规则，不能直接删除重建，以免清零重写次数或重复花费。当前的跨实例读取验证仅证明准备记录可重读，不等于进程崩溃后的执行恢复。

## 数据与账户生命周期

迁移 084 新增 platform_first_letter_tasks：

- 明文仅保存 UUID 归属/来源坐标、来源及准备摘要、固定规则版本、prepared 状态和时间。
- preparation_ciphertext 保存最小准备快照与服务端名单/日期配置，用现有 DataCrypto 按表、列、行 ID、用户和版本绑定；读取时与行元数据逐项一致。
- 不复制用户资料原文、人格文案、完整 prompt、会话令牌、供应商密钥或候选信件。
- user_id 直接归属用户；welcome 与 conversation 的组合外键同时绑定用户、主理人及诞生回执，删除均级联。唯一约束为 (user_id, welcome_id)。
- 已审阅实际隔离数据库的字段、三条外键及删除行为，更新账户覆盖基线为 owner_projection，而非仅替换摘要。

账户 JSON 和含文件归档都通过 AccountWelcomeExport 导出 firstLetterTasks。导出仍需登录和账户重新认证，但读取历史准备记录不要求当前模型协议或主理人仍活跃。导出不返回密文、不触发生成，也不赋予执行权限；损坏记录阻止整个导出，不消耗重新认证凭证。

覆盖清单现在有 172 张表，其中 7 张产品排除、165 张需投影；JSON 覆盖 142、剩余 23，含文件归档覆盖 145、剩余 20。账户导出仍是 complete=false，未覆盖部分没有被重新分类或隐藏。

## 尚未接通

本步没有模型调用、后台执行租约/心跳、每阶段 CostGuard 预留与结算、调用意图、加密候选稿检查点、持久化重写计数或恢复 worker。runFirstLetterReviewCycle 仍仅在一次函数调用内限制重写，不是可重启的任务状态机。

下一步需要在这个任务身份上接入上述能力，再与真实 ConversationTurns.post、唯一发布和 C7 完成衔接。真实模型质量评测门槛保留；没有把固定欢迎文案当第一封信，没有开启学生入口或主应用商业调用。

数据库迁移仅在隔离测试 schema 应用。主数据库、预览与部署未变。
