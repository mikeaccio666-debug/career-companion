# 求职准备的真实资料来源

依据 03 §3.4、§6.8、§8.5 与 09 §3A。项目事实、故事库与简历原稿的本人管理已经持久化；这里接通其内部准备索引和当前来源版本检查。buildApp 使用同一数据库、真实 CareerTargets、CareerStories、ResumeOriginalReview 与 CareerApplications 实例装配 CareerPreparationSources；申请读取器同事务核真实 ManualJobs。没有新增学生接口或将学生对话引擎开放。

## 真实索引与准备引用

read / readInTransaction 在同一有限时事务内核验固定学生会话、当前准入、实际归属、加密记录、查询投影、真实最新操作和确认凭证；读取期间账号重置则不能返回成功。方向取 active / exploring。项目按 03 §3.4 取本人 active、normal 的真实记录，包括本人填写但尚未确认的项目；索引明确区分确认状态，不把 self_reported 当作确认或技能证明。后续正文读取仍须按确认、真实分级与发言者权限独立准入。

故事索引只取本人 normal 且 confirmed 的当前版本。关联项目必须存在、active、实际版本一致、本人已确认，且仍为 normal、经历类型一致。变更、隐私提高、撤回、移除、恢复为新版本或尚未确认的关联会使故事离开可用索引；历史故事确认本身不被重写。无关联的故事可以独立由本人确认，不补造项目证据。敏感和受限记录不会变成普通索引条目。

准备摘要仅使用服务端的闭合经历类型、确认状态与岗位家族标签；不含用户标题、地点、项目背景、行动、结果、日期、STAR 正文或标签。简历增加真实首次 Web 确认时间，用于版本选择；这是不可变决定的时间，不是用户填写的经历日期或推测的更新时间。项目、故事和简历不只取列表第一页，项目、故事、简历、收藏和申请均完整读取各最多 500 条实际记录；超过容量或来源认证损坏时明确失败，不返回部分索引。

buildInTransaction 接入原 buildCareerRunContext 的真实 listTargets / listEvidence / listResumeVersions 端口：指定项目取实际 ID 与 revision，否则按原规则生成包含全部真实成员的快照；不随意挑一条。内置 prepare 是无执行器检查，tools 为空，档案与尚未接通的其他端口保持 unavailable；真实申请和独立收藏端口已接通。因此即使资料索引存在，也不能假装 skill 已 ready、主理人已使用资料或工具已经可调用。证据端口当前只接项目；练习证据不会由项目数量替代。简历端口使用真实已确认版本；尚缺的档案、实际正文分级、知识和执行器依然保持 unavailable，不会因为简历存在而把 skill 标为 ready。

## 本人确认的简历来源

ResumeOriginalReview 的内部读取器在同一个有界事务和 owner 锁内认证原稿、不可变正文历史、最新操作、真实首次确认决定，以及简历查询投影。只有 pending 对象已经 approved、简历行仍 active 的真实版本入选；草稿、放弃、过期、被替换和归档不会成为可用简历。索引的 ID 是实际 resumeVersionId，revision 是正文版本，不是操作 generation。只返回固定岗位家族与本人确认标签，不返回版本名、正文、claims、来源原文或个人事实。

按 03 §3.4，未明确选择时，resume-source 取真实首次确认时间最近的可用版本；reviewed-resume 在已经明确的目标岗位 track 内选择。真实时间相同或旧适配器缺少确认时间时保留歧义，需要明确选择；不按数组顺序、创建序号或客户端日期推测新旧。选择旧版仍可用时必须保留它；指定外人、不存在、归档或方向不匹配的版本时，不偷偷改选另一版。真实 selected application 与原 JD 已接入，因此 reviewed-resume 的 track 匹配已由实际数据库与密码登录后创建的申请验证；仍不声称材料包已经接通。

已确认旧版保持 active；新草稿不进入索引，不改变最近可用版本。新版确认后索引成员增加，默认选择它；旧版独立重复确认只增加操作 generation，保留首次真实确认时间，不会把旧版重新排成最新。明确归档或物理删除移除相应成员，让旧集合坐标失效；其他已确认版本保持原对象与版本。集合复核只要求准备索引重读，不改写既有简历或材料包的确认；未来材料包须对自己的冻结引用另核。

未安装真实简历适配器时 resumes 为 null，listResumeVersions 保持 unavailable；已经装配但没有可用版本时才是空数组。上传抽取经真实文件归属核验，保存为待确认原稿；只有本人真实确认后，才能经同一原稿读取器进入版本索引。准备构造器仍不接受 uploadedResumeId 等字段伪装一份可用文件。本人原稿路径见 [简历原稿](resume-original-review.md)。

## 当前版本复核

indexId 是当前真实元数据集合的内容地址，不是持久化 expert run、模型使用凭证或执行租约。assertCurrentInTransaction 在真实消费者的同一有限时事务中重读索引、核对本人和内容地址；新增或修改可用成员、确认、撤回、归档、删除与方向变更导致旧索引失效。其他账号的坐标返回不存在。身份与准入变化重新检查。

没有持久化假的运行记录，没有强行分类成 L0，没有申请提交、付费调用、模型回复、导师审核或埋点冒充使用。实际学生轮次尚需接真实档案、工具白名单、来源正文分级、当前版本冻结、租约、模型调用与持久化使用回执；本实现不解除 09 的引擎评测前置门。

## CI 暴露的数据库往返与级联修复

PR #58 的完整 CI 在最大三类各 500 条资料读取时超过既有事务截止时间；同一轮还出现账号删除触发消息房间复合外键的失败。没有将这一轮记为通过。准备索引改为在同一个 owner 锁和有界事务中批量读取真实最新操作、实际确认、必要的原稿历史及简历投影；每条密文、最大操作版本、原稿摘要与真实决定仍逐项认证，不按可变投影推断最新凭证。首次确认记录的查询只读所需坐标，不扫描全部历史，不复制私人正文进入索引。默认 2 秒事务期限保持不变；后续仍需最坏正文及生产并发负载验证。

追加迁移 059 将产品消息房间的 owner 复合外键改为 ON DELETE CASCADE，与已有 conversation_id 删除行为一致。真实账号删除移除房间及其消息，避免多个级联路径之间的临时检查阻挡；归属外键仍成立，不允许跨账号关联。迁移与真实账号删除重复验证，主数据库和主预览未应用本批迁移。确切提交的远端类型检查及 43 项相关 PostgreSQL / 来源 / 诞生回归通过；GitHub CI 以对应提交单独记录。

## 真实申请与独立收藏

申请与收藏是两个真实来源集合：applications 和 savedJobs；缺适配器时为 null，表示 unavailable，不制造空集合；实际已装配但用户没有记录时返回空数组。本人原文和备注仍在各自存储器里，索引只含实际 owner/ID/revision、闭合岗位家族、阶段、由服务端生成的固定说明，以及真实 JD 观察时间。不复制公司名、用户标题、地点、JD、身份原句、备注、简历或 STAR 正文，不标出一份假 L0。

ManualJobs 的准备读取器认证完整现存来源、原文规则定位结果和独立最新不可变操作。CareerApplications 的准备读取器认证完整现存申请、最新操作、当前事件，以及仍引用的历史关怀来源事件/凭证；批量读取实际证明，避免每条记录再访问一次数据库。所有读取共用实际有限时事务、固定会话、账号锁与准入门，账号重置不能返回成功；应用装配没有新建模型工具或 HTTP 准备接口。

`selection.targetJobId` 是本人真实申请 ID。target-job 仅取未结束且当前原 JD 实际存在的申请；`sourceDependencies` 另外保留该实际 JD 的 ID/revision，未来运行冻结与持久化必须一并消费，不能只记申请版本。未指明而有多个可用申请时保持歧义，不任意挑选。源 JD 被删后申请仍是可读的历史记录，job=null，不能贡献 target-job 或 reviewed-resume；恢复已删除源的旧有效密文仍被独立最新删除凭证拒绝。

`current-jobs` 从独立收藏与看板合成完整样本，门槛按不同 JD 判断，不按快照成员数量判断。同一原 JD 既收藏又有申请只算一个；有现存申请时该申请阶段约束这个原 JD，closed 不会通过原收藏再次贡献样本。尚无申请的真实收藏可独立参加样本，不制造 saved 阶段的申请记录。实际删除申请而保留收藏后，原收藏重新是独立条目；这不复活已删除的申请。

快照 members 保存每个实际 JD 的坐标以及对应现存申请的坐标，确定性排序后计算内容地址。三份 JD 各有一条申请时为三份样本、六个真实成员，不据此声称有六份岗位。申请阶段/版本、原 JD 成员或版本变化会让冻结集合改变。任一集合适配器缺失、重复绑定、未核对来源、少于三份样本，都不能用一份不完整的集合满足门槛。当前完整准备 indexId 也包括两集合及其实际关联；版本、删除或阶段变更后，原 index 必须重读。

选中的实际申请 track 可用于筛选同 track 的真实已确认 active 简历；默认仍用实际首次确认时间最近的一版，明确选了不匹配版本时不改选。材料包、工具白名单、正文当前安全等级、许可知识、租约、执行和实际模型使用记录必须另外真实接入。当前 prepare 的工具仍为空、真实档案尚未接入，不因拥有岗位与简历就变成 ready。
