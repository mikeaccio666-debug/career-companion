# 求职准备的真实资料来源

依据 03 §3.4、§6.8、§8.5 与 09 §3A。项目事实、故事库与简历原稿的本人管理已经持久化；这里接通其内部准备索引和当前来源版本检查。buildApp 使用同一数据库、真实 CareerTargets、CareerStories 与 ResumeOriginalReview 实例装配 CareerPreparationSources。没有新增学生接口或将学生对话引擎开放。

## 真实索引与准备引用

read / readInTransaction 在同一有限时事务内核验固定学生会话、当前准入、实际归属、加密记录、查询投影、真实最新操作和确认凭证；读取期间账号重置则不能返回成功。方向取 active / exploring。项目按 03 §3.4 取本人 active、normal 的真实记录，包括本人填写但尚未确认的项目；索引明确区分确认状态，不把 self_reported 当作确认或技能证明。后续正文读取仍须按确认、真实分级与发言者权限独立准入。

故事索引只取本人 normal 且 confirmed 的当前版本。关联项目必须存在、active、实际版本一致、本人已确认，且仍为 normal、经历类型一致。变更、隐私提高、撤回、移除、恢复为新版本或尚未确认的关联会使故事离开可用索引；历史故事确认本身不被重写。无关联的故事可以独立由本人确认，不补造项目证据。敏感和受限记录不会变成普通索引条目。

准备摘要仅使用服务端的闭合经历类型、确认状态与岗位家族标签；不含用户标题、地点、项目背景、行动、结果、日期、STAR 正文或标签。简历增加真实首次 Web 确认时间，用于版本选择；这是不可变决定的时间，不是用户填写的经历日期或推测的更新时间。项目、故事和简历不只取列表第一页，完整读取各最多 500 条实际记录；超过容量或来源认证损坏时明确失败，不返回部分索引。

buildInTransaction 接入原 buildCareerRunContext 的真实 listTargets / listEvidence / listResumeVersions 端口：指定项目取实际 ID 与 revision，否则按原规则生成包含全部真实成员的快照；不随意挑一条。内置 prepare 是无执行器检查，tools 为空，档案与尚未接通的其他端口保持 unavailable。因此即使资料索引存在，也不能假装 skill 已 ready、主理人已使用资料或工具已经可调用。证据端口当前只接项目；练习证据不会由项目数量替代。简历端口使用真实已确认版本；尚缺的档案、岗位看板及执行器依然保持 unavailable，不会因为简历存在而把 skill 标为 ready。

## 本人确认的简历来源

ResumeOriginalReview 的内部读取器在同一个有界事务和 owner 锁内认证原稿、不可变正文历史、最新操作、真实首次确认决定，以及简历查询投影。只有 pending 对象已经 approved、简历行仍 active 的真实版本入选；草稿、放弃、过期、被替换和归档不会成为可用简历。索引的 ID 是实际 resumeVersionId，revision 是正文版本，不是操作 generation。只返回固定岗位家族与本人确认标签，不返回版本名、正文、claims、来源原文或个人事实。

按 03 §3.4，未明确选择时，resume-source 取真实首次确认时间最近的可用版本；reviewed-resume 在已经明确的目标岗位 track 内选择。真实时间相同或旧适配器缺少确认时间时保留歧义，需要明确选择；不按数组顺序、创建序号或客户端日期推测新旧。选择旧版仍可用时必须保留它；指定外人、不存在、归档或方向不匹配的版本时，不偷偷改选另一版。当前真实岗位看板尚未接通，因此 reviewed-resume 规则的岗位匹配验证属于纯构造器回归，不声称材料包已经接通。

已确认旧版保持 active；新草稿不进入索引，不改变最近可用版本。新版确认后索引成员增加，默认选择它；旧版独立重复确认只增加操作 generation，保留首次真实确认时间，不会把旧版重新排成最新。明确归档或物理删除移除相应成员，让旧集合坐标失效；其他已确认版本保持原对象与版本。集合复核只要求准备索引重读，不改写既有简历或材料包的确认；未来材料包须对自己的冻结引用另核。

未安装真实简历适配器时 resumes 为 null，listResumeVersions 保持 unavailable；已经装配但没有可用版本时才是空数组。没有上传抽取适配器，不接受 uploadedResumeId 等字段伪装一份可用文件。本人原稿路径见 [简历原稿](resume-original-review.md)。

## 当前版本复核

indexId 是当前真实元数据集合的内容地址，不是持久化 expert run、模型使用凭证或执行租约。assertCurrentInTransaction 在真实消费者的同一有限时事务中重读索引、核对本人和内容地址；新增或修改可用成员、确认、撤回、归档、删除与方向变更导致旧索引失效。其他账号的坐标返回不存在。身份与准入变化重新检查。

没有持久化假的运行记录，没有强行分类成 L0，没有申请提交、付费调用、模型回复、导师审核或埋点冒充使用。实际学生轮次尚需接真实档案、工具白名单、来源正文分级、当前版本冻结、租约、模型调用与持久化使用回执；本实现不解除 09 的引擎评测前置门。

## 验证

真实 PostgreSQL 覆盖本人隔离、当前与未确认项目区分、敏感度过滤、当前故事关联、实际编辑/确认/撤回/删除后的索引失效、来源恢复的新版本、旧有效密文回滚、查询投影伪造、完整分页范围、真实会话重置与准入撤回。实际密码登录 HTTP 保存并确认的原稿进入 buildApp 装配的真实来源索引；未确认原稿和私有正文不入索引。新增数据库回归核对简历确认、重复确认、归档、删除、原操作认证、旧密文回滚、实际来源会话复核及适配器缺失；纯规则覆盖真实时间排序、同时间歧义与目标岗位方向匹配。三类各 500 条实际记录在未调整的 2 秒有界事务内完整复核；测试使用虚构短正文，不表示最坏正文容量或生产并发压测已经完成。实际资料进入原准备构造器，仍因真实缺失的档案和执行器保持 blocked；快照成员逐一对照数据库中的本人记录，不注入虚构来源。协议和纯规则回归不等于浏览器、真实模型或上线验收。
