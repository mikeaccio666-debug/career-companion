# 求职准备的真实资料来源

依据 03 §3.4、§6.8、§8.5 与 09 §3A。项目事实和故事库的本人管理已经持久化；这里接通其内部准备索引和当前来源版本检查。buildApp 使用同一数据库、真实 CareerTargets 与 CareerStories 实例装配 CareerPreparationSources。没有新增学生接口或将学生对话引擎开放。

## 真实索引与准备引用

read / readInTransaction 在同一有限时事务内核验固定学生会话、当前准入、实际归属、加密记录、查询投影、真实最新操作和确认凭证；读取期间账号重置则不能返回成功。方向取 active / exploring。项目按 03 §3.4 取本人 active、normal 的真实记录，包括本人填写但尚未确认的项目；索引明确区分确认状态，不把 self_reported 当作确认或技能证明。后续正文读取仍须按确认、真实分级与发言者权限独立准入。

故事索引只取本人 normal 且 confirmed 的当前版本。关联项目必须存在、active、实际版本一致、本人已确认，且仍为 normal、经历类型一致。变更、隐私提高、撤回、移除、恢复为新版本或尚未确认的关联会使故事离开可用索引；历史故事确认本身不被重写。无关联的故事可以独立由本人确认，不补造项目证据。敏感和受限记录不会变成普通索引条目。

准备摘要仅使用服务端的闭合经历类型、确认状态与岗位家族标签；不含用户标题、地点、项目背景、行动、结果、日期、STAR 正文或标签。项目不只取列表第一页，完整读取各最多 500 条实际记录；超过容量或来源认证损坏时明确失败，不返回部分索引。

buildInTransaction 接入原 buildCareerRunContext 的真实 listTargets / listEvidence 端口：指定项目取实际 ID 与 revision，否则按原规则生成包含全部真实成员的快照；不随意挑一条。内置 prepare 是无执行器检查，tools 为空，档案与尚未接通的其他端口保持 unavailable。因此即使资料索引存在，也不能假装 skill 已 ready、主理人已使用资料或工具已经可调用。当前只接项目证据；练习证据不会由项目数量替代。

## 当前版本复核

indexId 是当前真实元数据集合的内容地址，不是持久化 expert run、模型使用凭证或执行租约。assertCurrentInTransaction 在真实消费者的同一有限时事务中重读索引、核对本人和内容地址；新增或修改可用成员、确认、撤回、删除与方向变更导致旧索引失效。其他账号的坐标返回不存在。身份与准入变化重新检查。

没有持久化假的运行记录，没有强行分类成 L0，没有申请提交、付费调用、模型回复、导师审核或埋点冒充使用。实际学生轮次尚需接真实档案、工具白名单、来源正文分级、当前版本冻结、租约、模型调用与持久化使用回执；本实现不解除 09 的引擎评测前置门。

## 验证

真实 PostgreSQL 覆盖本人隔离、当前与未确认项目区分、敏感度过滤、当前故事关联、实际编辑/确认/撤回/删除后的索引失效、来源恢复的新版本、旧有效密文回滚、查询投影伪造、完整分页范围、真实会话重置与准入撤回。实际资料进入原准备构造器，仍因真实缺失的档案和执行器保持 blocked；快照成员逐一对照数据库中的本人记录，不注入虚构来源。协议和纯规则回归不等于浏览器、真实模型或上线验收。

验证日志保留在忽略的私人目录，结果以确切提交与对应 PR 为准。本次不改主预览、主数据库、付费开关或部署。
