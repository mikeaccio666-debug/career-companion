# 简历原稿与本人逐版确认

依据 03 §6.8、§9，05 §2.16，08 §7.10 与 09 第 3A、5 步。当前实现本人上传 PDF / UTF-8 TXT / Markdown，或粘贴原稿，随后核对正文、确认与另存版本，是待确认系统中的简历原稿路径。前辈改写、申请材料包、邮件、联系消息和学生对话尚未接通；不代表完整 P0-7 或 P0-9。

## 用户路径

网页入口 `/pending` 和 `/pending/:id`；诞生后入口与设置页提供链接。用户明确选择岗位方向，填写版本名并上传文件或粘贴全文，保存为待确认原稿。读取完整正文后才能点确认；确认绑定当前对象 ID、revision 和完整 payloadDigest，服务端记录真实 Web 决定及时间，简历行变为 active。原稿的事实由本人核对，确认不代表蔓藤导师审核、独立能力验证或已经发送。

pending 草稿可以修改，修改产生新正文 revision。final_action=none 的 approved 是终态，再改需新对象；用户可以从本人已确认版本另存草稿。新同方向对象只替换未确认草稿；已经确认的旧版保留 active，不被新草稿或新确认偷偷归档。明确归档收起可用版本，保留原稿与历史确认。移除则物理删除该对象所有正文版本、决定和简历行；另存的其他对象不会随之删除，但确认派生稿时必须重新核对仍存在且版本一致的真实来源。

过期以服务端数据库时间判断；创建和恢复后待确认期限为七天。恢复产生新正文 revision，必须重新核对和确认。列表保留过期与被替换条目，不把它们显示为已发出。没有批量确认、发件、后台投递或插件执行路径。

当前正文只来自本人粘贴、实际本人上传文件抽取或本人另存修改；draftedBy=null，不冒充前辈输出。payload 的 claims 固定为空，source_refs 指向该对象真实且不可变的初始本人输入；上传原稿另带实际文件 ID、完整文件 SHA-256 与强存储版本。未来模型改写仍须单独实现逐句来源、未核实事实和专家运行凭证，不得复用这一入口来伪装生成来源。粘贴与另存对象 uploadId 为空；上传对象保存实际 uploadId 和服务端抽取快照，不接受客户端伪造正文或来源。

## 存储与权限

迁移 058 追加 platform_pending_items、platform_pending_item_revisions、platform_pending_item_decisions、platform_pending_item_operations、platform_career_resume_versions 和按方向递增的版本计数。迁移 060 扩展上传来源约束，059 是独立的消息账号级联修复。当前表约束只接受上述原稿路径；后续其他类型需追加迁移和真实业务适配。查询投影只保存归属、类型、方向、状态、版本、摘要和服务端时间；姓名、版本名和原稿正文保存在 DataCrypto 认证密文中。原稿正文仅存在正文版本表，简历行和操作凭证不重复保存正文。

正文 revision 与操作 generation 分开：每次真实操作递增 generation，编辑和恢复才增加正文 revision。最新不可变操作凭证绑定完整加密元数据摘要；读取复核实际查询投影、原稿历史、真实确认决定及原操作。旧有效密文、伪造确认时间、错误摘要和移位密文均不能变成当前有效记录。历史正文与确认决定在对象存在时只追加；本人明确移除和真实账号删除允许级联擦除。

使用实际学生登录会话、账号窗口头、CSRF、固定会话复核和请求额度。创建、编辑、确认及恢复还要求当前协议与邮箱准入；本人私有读取、放弃、归档和移除在准入撤回后仍可进行。账号锁串行化写入，预期版本和摘要防止覆盖变化；中途真实会话重置回滚整个事务，包括前一草稿的替换和版本计数。

稳定 operationId 重试读取原凭证和当前状态。对象移除后，保留不含正文的加密操作坐标与请求摘要，迟到创建不能复活，版本序号不重用。GET /pending-items/operations/:id 查询原操作的实际结果，不能把一般的对象 404 当作操作失败。网页写入八秒未返回时中止等待并查询原操作；结果仍未知则保留原操作供重试。私人状态仅放组件内存；账号变化、失效和卸载取消请求并清空内容，不写浏览器持久缓存。

## 接口与边界修复

- GET /pending-items 和 /career/resume-versions：每页 50 条元数据，可按真实 owner cursor 翻页；支持 status 筛选，不返回正文。
- GET /pending-items/:id、/:id/revisions/:revision、/career/resume-versions/:id：本人完整原稿或不可变历史。
- POST /uploads：现有真实 multipart 文件写入；没有稳定操作重放，未知结果不得自动再次上传。
- GET /career/resume-uploads：当前本人已上传且格式可用的文件元数据列表，每页 50 条，不返回存储路径或正文；游标比较保留数据库时间精度。
- POST /career/resume-versions/from-upload：实际本人文件抽取为新的待确认原稿；使用稳定 operationId。
- POST /career/resume-versions：本人粘贴或从本人已确认版本另存。
- POST /pending-items/:id/revisions、/:id/decision、/:id/reopen、/:id/archive，以及 DELETE /pending-items/:id：逐对象操作。
- request_changes 明确返回执行器不可用；尚无专家改写、稍后再看或对外发送接口；本人原稿的历史正文对比见下文。

本批真实 HTTP 验证发现 Fastify 查询对象使用框架自有原型，直接交给领域闭合记录解析器会误拒绝筛选和分页。careerHttpQuery 在 HTTP 边界只复制自身可枚举的数据属性到空原型 DTO；访问器、隐藏属性和符号拒绝，重复参数保留数组并由标量领域规则拒绝。领域解析器保持闭合，仍不接受伪造 owner、来源、授权或未知字段。同样修复项目/故事、收藏岗位、方向和共享记忆的列表边界。旧记忆仍须本人选择类别与敏感度后确认，翻页不改变复核或共享状态。

## 真实文件抽取与中断恢复

上传分为已有通用 multipart 写入和新的原稿抽取保存两步。浏览器只对实际选中文件计算 SHA-256，不发送客户端生成的抽取正文；服务端先核对固定学生会话、当前准入与实际文件归属，再核对字节大小和强存储版本，完整读取流并计算文件指纹。抽取后复核存储版本、当前会话及数据库文件描述，再进入既有带 owner 锁的原稿写入事务。文件或权限变化不会保存新原稿，也不会替换已有草稿。结果只是 sensitive 的 pending 原稿，必须由本人核对并确认。

PDF 使用服务端固定的 Poppler pdftotext 参数，stdin / stdout 传递，不经 shell，不执行文件内脚本或链接，不写原稿临时文件，不保留解析器错误碎片。生产镜像包含 poppler-utils 与 util-linux；prlimit 将解析器限制为 384 MiB 地址空间、6 秒 CPU 和 64 个文件描述符。进程总等待上限 10 秒、输出上限 220000 字节，文件完整读取与抽取整体在同进程最多同时两份，在读取 20 MiB 缓冲之前拒绝额外请求；PDF 子进程同样最多两个；取消、超时或溢出都杀掉子进程并等待实际关闭。最多 100 页、50000 个 Unicode 字符，空白或只有图片的页面、损坏文件、超限及无完整文字输出会拒绝，不返回第一页或截断版。PDF 抽取只覆盖已有文字，页内图片文字不能识别；页面要求本人对照原文件检查缺漏。此路径没有 OCR，也没有视觉模型调用。

TXT / Markdown 用严格 UTF-8 解码并保留全文，拒绝伪装的常见二进制格式、无效编码、危险控制字符和超长正文。抽取快照保存实际工具版本、原文件大小、文件 SHA-256、强存储版本和初始文字 SHA-256；后续本人编辑仍保留初始文字来源，并认证真实 R1 历史，而不是把改后的文字指纹伪称为原文件输出。前端绑定实际 uploadId、文件指纹、对象归属与完整 payloadDigest。

本机文件读取或哈希未完成时，网页明确表示尚未发送；POST /uploads 发出后连接中断，则只表示结果未知，提供实际本人已上传文件列表，由本人选择继续，不自动重复上传。抽取保存请求已知操作坐标，八秒未返回时沿用原操作观察 / 重试通道；先查原凭证再做文件 I/O，原文件之后移除也不会让已完成操作重新创建已删除的原稿。账号切换与页面卸载取消请求、清空私有组件状态，不持久缓存文件与原稿。

保存下来的原稿正文是独立的本人版本；原文件坐标表达当时捕获的来源，不是任意原文件替换后自动刷新简历的关系。本人移除原稿会删除该对象的正文历史与决定，不代表已删除另外保存的原文件。09 要求的 DELETE /uploads/:id、当前文件清理和本人回执现经独立的[原文件移除流程](upload-removals.md)接通；待清理时只撤销访问，实际存储容量需清理完成后才释放。云存储、历史版本及生产恢复验收仍未完成。将原稿加入专家上下文还需真正的正文准入、分级和使用回执，确认原稿不授予执行权。

## 抽取执行器可用性与 CI 依赖

PDF 在传给抽取器之前，先用不含用户文件内容的固定版本命令验证实际 prlimit / pdftotext 工具链。缺少执行文件、无执行权限或子进程被操作系统信号中断时返回 503 服务不可用，不再误报为本人文件损坏；解析器对损坏 PDF 的正常非零退出仍拒绝文件，取消、超时、资源及正文上限不放宽。错误不包含原稿、程序路径、退出诊断或解析器 stderr。每次抽取仍捕获真实版本，不用缓存或固定版本冒充当前工具。

生产镜像显式安装 poppler-utils 与 util-linux；GitHub 验证环境也需要显式安装和验证这些依赖，不能假定 ubuntu-latest 预装。上传批次 #60 的 CI 失败包含 PDF 子进程非零退出和一项后台通知恢复断言；非零退出本身不足以证明具体缺少哪个程序。前述远端与容器成功不替代 GitHub CI。这次错误分类修复也不宣称修复了通知恢复断言。工作流依赖安装与超时调整需推送 .github/workflows/ci.yml，当前 GitHub OAuth 缺少 workflow scope，仍待账号持有人完成此前请求的授权；不在普通测试脚本中安装系统依赖来绕过该限制。

本次执行器修复检查：20 项真实子进程、PostgreSQL 和密码登录 HTTP 测试全部通过，0 跳过；平台类型检查通过。基于修复源码的生产镜像构建成功；禁止网络、只读根文件系统、移除 capabilities 并限定内存与 PID 的容器中，实际两页 PDF 全文读取与损坏文件拒绝通过（Poppler 22.12.0）。另构建仅移除 pdftotext 的隔离验证镜像，固定抽取入口真实返回 503，未返回虚构简历内容。此故障注入证明错误分类，不证明之前 CI 的确切缺失原因；容器没有启动应用或部署。


## 同一原稿的历史正文对比

依据 08 §7.9，在原稿完整内容中加入「看改动」。有至少两个正文 revision 时，本人选择较早版本，与当前打开的正文比较；手机行内显示删除与新增，宽屏左右对照。新增使用 air-tint 底与下划线，删除使用 ink-3 与删除线。页面接入共享 career-surface 设计变量，手机底部操作栏使用不透明背景和明确层级，避免与正文叠在一起。

GET /pending-items/:id/diff?from=N&to=M 在同一有界事务、真实固定学生会话和本人锁内读取两份不可变历史，核对当前记录、原始来源和完整 payloadDigest；结束前再次复核会话。参数必须是两个升序、已存在的正文版本，不接收额外归属或确认字段。跨账号不可读，响应 private, no-store。服务端可以比较两个历史版本；网页把目标绑定到本人当前打开的 revision 和摘要，若原稿已更新则要求重新读取，不静默切换版本。

比较保留两份完整正文和 Unicode 字符，采用共同前后缀与中间变化区段的线性比较；变化区段可能包含未变文字，界面明确说明，不冒充最小逐词 diff。网页从差异重建两版完整 payload，并分别重新计算 SHA-256 后才显示。只比较正文，不捏造未保存的历史版本名称，也不跨另存对象合成历史；空 unresolvedClaims 表达本人原稿没有模型断言列表，不表示事实已验证。

读取差异不会确认、发送或创建决定，原有逐版确认仍绑定完整正文摘要。中断、八秒超时、关闭、断网、账号失效和版本变化均清除对比结果；私人正文只保留组件内存。过期记录仍沿用原有读取时的实际期限处理，不把查看记录伪称为修改正文或确认。
