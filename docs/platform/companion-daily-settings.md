# 每日时间偏好

依据产品 02 §9、05 §2.2、09 第 6 步。当前只保存用户明确选择的时区、晨报时间、免打扰起止、每日分钟数和 Web 邮件提醒偏好，为每日计划提供前置数据。页面入口是现有 `/me/companion`，与付费建议同页。晨报尚未开放的说明始终显示；保存不会创建计划、启动调度或发送邮件。

## 选择与接口

没有已保存设置时返回 revision=0、preferences=null；不会根据浏览器或 IP 猜用户的时区。表单建议 09:00、22:30–08:30、90 分钟、不提醒，时区必须由本人选择。时区按 IANA 标识验证，时间必须是 HH:mm，免打扰起止不能相同，分钟数为 0–1440 的整数；0 是合法的休息预算，不暗改成 90。P0 提醒选项只有 none/email。跨夏令时的实际晨报执行策略仍由后续调度实现。

- GET `/companion/settings/daily`：本人当前主理人的设置。
- PATCH 同路径：companionId、operationId、expectedRevision、preferences；只接受真实登录、学生账号、已诞生的当前主理人、已验证邮箱和有效协议。
- GET `/companion/settings/daily/operations/:id`：核对原操作，返回它保存的版本/偏好与最新设置。原操作重试不能覆盖之后的新选择，同一个 id 不能换内容。

三个接口均使用固定账号请求上下文、现有速率限制、取消信号和 private/no-store。独立 daily 子资源避免改变付费建议现有严格协议，属于同一主理人设置领域。未来调度调用 readForPolicyInTransaction，与调用者共享事务；未选择时区明确拒绝，协议或邮箱条件失效时不能继续用来调度。本人读取和核对旧操作仍可用。

## 持久化和隐私

迁移 081 新建 platform_companion_daily_settings，使用追加的不可修改加密修订；按账号、主理人、版本唯一，账号和操作唯一。账号外键与 `(companion_id,user_id)` 组合外键均级联删除。解密上下文绑定表、列、操作、账号和版本，读取还核对密文里的来源、命令摘要、SQL 时间及修订关系。账号锁和乐观版本控制让并发修改只接受一份；写入后再次检查会话，失效时整笔回滚。

账户覆盖已审阅六个字段及两个外键，新增 owner_projection。内部账户归档加入 companionDailySettings，分页读取所有已保存版本，只输出已解密设置；不输出密文、命令摘要、认证版本或凭据。普通 JSON 现为 94 张已投影、7 张排除、66 张待处理；带文件为 97/7/63。两者 complete=false，不能当作完整归档交付。

网页不把偏好或未确认操作放进 localStorage。保存结果未知时保留原命令，可核对/重试；离线隐藏旧状态，恢复时重新读；账号切换释放旧请求与页面数据。页面关闭后不自动重试写入，下次以服务端保存值为准。
