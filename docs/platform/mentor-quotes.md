# P0 真人匹配、报价和时段占用

对应 [04 §3.5](../product/04-manteng-assets.md)、[06 §6.3](../product/06-business-model.md) 和 [07 P0-12](../product/07-first-cohort-mvp.md)。前置是 [实际预约意向](mentor-intents.md)、[已审核服务价目](mentor-service-offers.md) 与 [运营确认的导师/时段来源](mentor-capacity.md)。本层实现 `requested → matched` 和用户取消匹配，不等于付款或正式排期。

## 实际匹配

实际 `ops` / `org_admin` 通过本人当前会话操作已提交意向。服务端按组织与意向定位真实学生账号，检查验证邮箱、当前法律同意和版本；不替学生签发登录。导师来自真实的员工/mentor 角色、当前资料版本、逐项守则与保密/雇主声明和实际私有来源文件；时段必须仍在未来、版本吻合、覆盖同类服务的完整时长。资料声明/文件存在不替代人工签字、法务与服务质量验收。

匹配冻结当时导师称呼、资料/时段版本和建议时间。报价金额必须正数，且不高于意向提交时实际展示的价格，也不高于当前公开价格。已展示的描述、排除项、收款方、退款/申诉与利益披露保存在订单中；更新目录不改写已提交意向的条款。服务类别与时长改变时须重新确认，不能把用户原需求换成新服务。归因为用户主动请求 `user_request`，没有 AI 建议归因或收费推荐。

真实导师和建议时段回传给本人；私有来源命令、守则凭据、上传者、文件版本和证明摘要只保存在加密不可变匹配回执中，不返回学生或运营列表。匹配不授予聊天、记忆、身份日期、房间或资料包访问权限。

## 同一事务与占用

070 添加独立 `platform_mentor_orders`、`platform_mentor_slot_reservations` 和各自不可变证明；所有变更与意向操作回执、版本推进和员工审计同一事务提交。070 初始报价只允许 `quoted` / `void`；后续 [071 线下账务记录](mentor-payments.md) 扩展真实收款和退款，付款引用不再默认空。报价生成随机 32 字节交接码，数据库索引只存其 hash；当前没有付款外链、交接查询或对外发送，网页不展示交接码。

导师窗口由导师事务锁跨机构保护。同一真实来源窗口只允许一个有效占用；整个已确认窗口被占用，即使本次服务时长更短。比较前认证占用密文及 SQL 时间/状态投影，不能修改普通投影隐藏真实占用。来源目录读取仍先核对真实 profile、角色与文件，再结合占用判定 eligible。匹配持有组织 SHARE 防止来源变更，原操作 nonce 用独立事务锁串行；不会先拿组织 UPDATE 再等学生账号锁，与学生新提交的目录读取保持兼容。

占用独立于可修改的导师资料目录。更新/撤下资料、撤下时段或删除导师账号不会释放已匹配用户的占用或抹去历史报价；后续付款/排期仍须复核真实导师及服务。本人在 `requested` 版本 1 或 `matched` 版本 2 明确取消：已匹配意向变为 `cancelled` 版本 3，未付款报价变为 `void` 版本 2、交接码清除；已付款订单保持真实账务状态，退款另行记录。占用变为 `released`，同事务提交。账号/机构删除会级联删除私有记录；071 已保存独立的最少账务记录，仍须通过真实政策与对账验收。

原命令重试核对真实操作者、目标和闭合输入摘要，只返回当前状态加原操作 appliedRevision；取消后重放创建或匹配不能复活订单/占用。审计失败、账号/会话过期、来源失效、超时或取消均不返回成功；事务回滚覆盖意向、订单、占用和全部证明。

## 操作与 Web

运营使用固定 Node/pnpm：

```sh
./scripts/project.sh pnpm --filter @companion/platform-api mentor-match match --org ORG_ID --session-file PRIVATE_FILE --input-file PRIVATE_FILE
```

会话文件为 `{userId, token}`；输入只接受 `{operationId, sessionId, expectedRevision: 1, slotId, slotRevision, priceCents}`。两文件须本人所有、普通文件、非符号链接、权限严格 600。令牌不进 argv；输出只有意向坐标、当前状态/版本、原操作版本与 replayed，无称呼、需求、证据、交接码或凭证。配置仍须有服务端 `PLATFORM_MENTOR_ORG_ID`、数据密钥和当前法律文档。

HTTP 只增加读取，均要求真实登录/账号窗口，响应 `private, no-store`：

- `GET /api/platform/career/mentor-intents/:id/order`：本人的当前意向与真实订单成对返回；其他账号得到 404。
- `GET /api/platform/staff/orgs/:id/mentor-orders`：经组织角色授权与员工审计，返回最少订单坐标、状态、金额/币种和时间；50 条实际意向锚点分页，不含称呼、需求或交接码。

没有 HTTP 匹配/付款写入。已存在取消接口改为真实 expectedRevision；未知写入结果仍只能观察或重试原 nonce。

Web 请求层绑定当前账号，并核对成对意向/订单的归属、ID、服务/版本、时长、时间与操作。控制器在本人显式点「查看报价」后读取；账号改变、暂停、重新刷新或开始写入会清除旧报价，晚到结果不恢复。网页显示「已匹配 · 排期待确认」、真实导师及建议时区，展开真实报价金额和原条款；`quoted` 不显示已付款，建议时间不显示已排期。数据只在页面内存，没有自动提交、后台重试或本地存储。
