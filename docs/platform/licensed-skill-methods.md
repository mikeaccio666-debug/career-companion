# 技能加载已授权的方法卡

实现对应产品 04 §3.4 与 09 第一步 PR2 的能力目录。方法卡通过技能的显式版本引用读取，不进入私人资料搜索，也不成为系统指令或执行权限。

## 当前接线

- `CapabilityRegistry.methodReferences` 是服务端审核的技能清单扩展。构造时复制、校验并冻结；每个技能最多三张卡，同一 method_id 不能绑定两个版本。省略时沿用 career-core 的 methodRefs。没有真实审核内容时保持空清单，不生成假蔓藤方法。
- `CareerMethodReferences.open` 使用真实固定登录会话，绑定用户、轮次、发言者、组织和岗位家族，冻结发布批次上限及权益版本。岗位家族须由调用方从已确认资料取得，不能信任模型参数。
- `OrgKnowledge.readSkillMethodsInTransaction` 只取指定组织的 method_id/revision；缺失、未发布、未来生效、重复版本、岗位/技能/发言者不符均失败。不查询“最新”替代版本。
- 内容、授权凭据、权益与发布状态都复用已有验证；长读取交付前再次检查时间有效性。正文投影包含适用条件、步骤、停止条件、反例和转真人条件，移除内部员工身份及工具声明。
- `use_skill` 返回至多 4,000 字符的单卡摘录。长卡先给带边界条件的摘要；摘要仍过长则明确要求先取全文，不无声截去反例。工具权限仍由能力目录决定。
- `read_skill_reference` 默认读第 0 段，之后按 `nextPart` 继续，到 null 结束。单段最多 12,000 个 Unicode 字符，保留 method_id、revision、part/totalParts 和原始段落引用；整卡投影最多 64 KiB。不扩大 Agent 引擎已有的 64,000 字符单工具结果上限。
- 使用技能及后续读取都记录真实来源访问。后续每个模型步骤前再次读取并核对已加载方法；授权撤回、过期或数据变化会停止该轮，不能继续携带缓存内容调用模型。取消会回滚本次访问日志。
- 草稿执行端收到不可变的 `preparedSkills[].methodRefs`，可在持久化计划时保留所用版本。这个字段不代替真实任务租约、身份验证或记录版本检查。

## 版本与“看依据”

方法 revision 与来源发布 revision 是两种坐标，不能混用。新版发布后旧引用保持原版本；已撤回、过期、授权无效的旧内容仍拒绝读取。

已有明确引用允许查看仍有效的历史方法卡。网页标明“这是历史方法版本；查看它不会自动更新已有计划”。通用检索仍排除已被取代的方法，不主动推荐历史版本。用户接受新做法的提议流程尚未接入，本改动不自动迁移计划。

## 验证与实际边界

测试使用虚构导师、真实隔离 PostgreSQL 表、真实登录/权益/授权/发布操作，以及本机回环模型协议服务器。覆盖真实数据库 → 方法读取端口 → 能力目录 → 技能摘录/全文；另验证分页内容经过实际 Agent 循环不丢失、下一轮前撤回时不再发模型请求、员工身份不进入工具结果、跨用户/轮次/发言者与越权读取失败、取消不留下部分访问日志。网页静态渲染验证历史版本说明。

这些不是商业模型评测，也不证明真实蔓藤资料的质量。仍须提供审核和许可齐全的真实方法卡、审核具体版本绑定，并由正式轮次服务在真实身份、任务租约、授权及结果持久化下装配端口。当前应用没有自动挂载此能力，没有生产内容导入、部署或主预览重启；09 中主对话开工/首批开放的评测门槛仍保留。
