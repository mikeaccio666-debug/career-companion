# 今天：本人事项与计划历史

依据产品 05 §2.2、§3.3 与 09 第 6 步。本轮接通用户自己添加的事项，从 Web 到实际数据库的完整状态流。自动推荐三件事、专家动作回执自动完成、晨报和通知调度尚未开放，页面明确显示；这不代表 P0-6 完成。

## 可用流程

- `/today` 经现有账号、协议、首封信页面门槛进入；「我」和「旅程」均有入口。
- 先在主理人设置中保存时区。今天无计划时返回真实空状态，GET 不创建虚假计划或事项。
- 加一件自己的事（标题 1–160 字符、预计 1–1440 分钟），存为 `rule=user`、`proposed`。当前开放的是本人事项，没有模型生成记录或虚构队员。
- 接受这些安排：proposed 变 accepted，记录接受时间。新增事项仍需再接受。
- accepted 可变为 done / moved / dropped。本人点「我做完了」仅记 `completionSource=self_reported`，不写求职进展、技能、申请、练习或其他业务回执。系统建议的任务之后必须接入实际关联动作结果，不能复用这个入口冒充验证。
- 「挪到明天」在一个事务里标记今天 moved 并向下一个当地日期保存 proposed 事项。两条事项具有相同 candidateId 和不同 itemId；保留可审计的 movedTo 坐标。明天需要本人接受。目标计划预算不够或第二次写入失败时，两天全部回滚。
- 每个日期最多 50 条本人事项（包括终态历史）。非 moved/dropped 条目的预计总分钟数受当前每日预算限制；自动三件事的最多三件规则尚未启用，不能把本人添加事项当成算法选出的三件事。

## 日期、休息与恢复

使用已保存 IANA 时区与数据库时钟确定本地日期。以 ISO 日历日期推进到明天，不使用「当前时间加 24 小时」代替跨 DST 日期。每个新命令必须携带当时所见 localDate、planId 和 expectedRevision；跨午夜的旧命令拒绝，要求重新读取。已保存操作的原命令可以在新一天核对或重放，返回原操作结果和现在这一天的视图，不重建旧事项。

GET 在休息有效时只返回 paused 状态与非内容元数据，plan 为 null；任务标题和填写表单不出现。新写入会重新核对休息并拒绝。原操作恢复与本人账户导出仍可读取保存结果。Web 在休息保存成功时中止旧任务请求、保留结果未知的原操作，并刷新；晚到的旧响应不能重新显示任务。

前端请求有超时、固定账号代次和 AbortSignal；失去响应时保留原操作，可核对或用同一个操作重试。恢复网络只读取，不自动写；账号变化立即清空视图和待确认命令。任务正文不进 localStorage。

## 接口

- `GET /today`：当前本地日期、时区、日预算、休息状态、本人计划、automaticStatus=not_available。
- `POST /today/plan/items`：add。
- `POST /today/plan/accept`：accept。
- `PATCH /today/plan/items/:id`：done / move / drop，路径和命令里的 itemId 必须相同。
- `GET /today/plan/operations/:id`：只读核对，不重新执行。

所有路径使用现有固定账号、来源与限流校验，响应 private/no-store。新写入要求真实已诞生主理人、学生身份、邮箱和协议；撤回模型/协议准入不阻止本人读取已有记录或恢复原操作。开始和事务完成前均复核会话，晚撤销会回滚。客户端不能提供 userId、规则来源、完成证据、模型结果或执行授权。

## 存储和账户数据

083 新增三张表：

| 表 | 内容与归属 |
| --- | --- |
| platform_daily_plans | 本人、真实主理人、当地日期和计划静态身份；user/date 唯一，直接用户外键与主理人复合归属外键 |
| platform_daily_plan_items | 事项、候选根、所属计划的静态身份；直接用户外键与计划复合归属外键，plan/candidate 唯一 |
| platform_daily_plan_operations | 不可改写的加密整份计划修订与原操作证明；plan/revision 主键，user/operation/plan 唯一，直接用户及计划复合外键 |

三表均使用不可改写触发器，账户删除级联移除。用户标题、状态、完成来源和移动坐标保存在加密修订内；SQL 中的身份标记与最新修订逐一核对，缺失、损坏、归属或头部元数据不一致均失败。整份修订包含原命令和摘要，用于结果未知后的精确恢复；移到明天的同一操作有两份计划修订，并在同一事务提交。

账户导出新增 dailyPlans 与 dailyPlanHistory：当前计划、完整解码历史；不导出令牌、命令摘要、认证版本或密文。测试使用 105 个修订验证跨页读取和他人排除。

已检查迁移后的实际列、直接/复合外键及凭据归属，账户覆盖基线为 171 表、164 项需要投影、7 项排除。核心归档包含 98 项，仍有 66 项未完成；含文件路径包含 101 项，仍有 63 项未完成。完整导出完成度仍为 false。

## 规划来源

`TodaySources.dailyHistory` 现在来自真实计划存储，包含前两个当地日期（空日期也是实际查库结果）和候选根的 unfinished / done / dropped 记录。明确标 scope=owner_created_tasks；moved 作为已主动移出原日期处理，不冒充做完，也不被自动重复带回。标题不进入来源快照。

这只补齐本人事项的历史。后续自动计划写入与专家动作回执需接入同一存储，并扩展规则、链接与完成证据类型；初次问答的小步偏好已通过 [规划行为来源](companion-planning-source.md) 接入；仍缺少危机覆盖、旅程焦点和练习回执的完整来源，不能据此启动自动生成。

## 页面后台、断网与草稿恢复（2026-10-09）

今天页的本人安排和休息选择共用 private-page-lifecycle：初次挂载时页面隐藏或离线就不读；任一条件不满足时取消观察、清空可见结果；必须同时可见且在线才重新 GET。重复可见/在线事件不重复读取。保存休息安排后使本人计划过期也走同一入口，不能在隐藏页重新唤起读取。账号绑定、超时和迟到响应仍由各自控制器检查。

未收到回执的原命令只留在当前账号的页面内存，恢复只读，不自动重发。跨午夜重新读取真实新日期；原操作仍绑定其原日期，不改成当天操作。未提交事项的文字和分钟数移到页面级编辑状态，在隐藏或断网时不进入 DOM，当前账号恢复读取后重新显示；该草稿确认保存后清空，接受其他事项不会清除正在写的新草稿。账号失效清除草稿，组件卸载释放内存；无浏览器存储。未提交标题和未知操作都会触发离开提醒，浏览器强退仍不能保证保留。

## 修改本人事项（2026-10-09）

本人添加的 proposed / accepted 事项可以修改标题和预计分钟数。保存保留 itemId、candidateId 和原始创建信息，增加一份加密计划修订；旧版本不改写，账户导出保留修改前后的内容。已接受的事项修改后回到 proposed，需再次接受才能完成、移到明天或放弃。done / moved / dropped 不允许改写；此入口也不修改系统推荐事项、生成业务证据或代表真实任务已经完成。

现有 PATCH /today/plan/items/:id 增加 edit 命令，携带标题、分钟数以及所见计划/日期/版本。标题与分钟沿用原字段限制；预算按整份当前计划重新计算，超出即事务回滚。重复原操作只读取保存结果，更换内容复用编号拒绝；跨午夜不能把未保存的旧编辑套到新一天，已保存的编辑仍可核对原回执。

网页编辑稿保存读到的版本依据，且只留在当前账号页面内存。重新读取、恢复连接或切回可见页面不重写这份依据：如果有新版本，会同时显示当前保存内容和旧草稿，必须明确核对后才能再次保存。原事项已结束或不属于今天时只允许放弃该修改，不自动转移到其他事项。编辑时锁住其他事项动作；添加新事项的草稿单独保留。保存成功仅清除对应编辑稿；失败保留，未知结果继续走原操作核对。离线/隐藏/休息时编辑内容不进入 DOM，退出或换账号时清空。

没有新增表、列、外键或改动既有 SQL 历史；旧加密命令格式仍可读取。含 edit 命令的历史需要使用支持此命令的 API/worker 版本，不能回退到不识别 edit 的老版本继续服务。

验证：12 项隔离 PostgreSQL/真实登录 HTTP、14 项 Web 控制器/生命周期、3 项契约检查通过；最终更新后的 HTTP 流程单独复核通过；API/契约类型检查与 Web 生产构建通过。包含编辑前后历史与账户导出、同操作并发、版本竞争、预算拒绝不落库、终态拒绝、跨账户与午夜边界、客户端原版本绑定及错误回执拒绝。
