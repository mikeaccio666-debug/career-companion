# 文件写入与删除日志的账户归档

依据产品 09 §11，账户 JSON 新增 `uploadWrites`、`uploadWriteEvents`、`uploadRemovals`、`uploadRemovalEvents`，覆盖现有四张写入与删除日志表。普通 JSON 当前为 93 张已投影、7 张明确排除、66 张待处理；带私有文件模式为 96 / 7 / 63。当前计数包括后续加入的[任务历史](account-task-export.md)及[执行历史](account-execution-export.md)。两者仍 `complete=false`；文件字节仅由 AccountFileArchive 捕获，这四类日志本身不会读取或恢复文件。

## 保存哪些内容

写入记录保留本人 ID、日志 ID、原 status（writing、ready、cleanup）、writerFinished、当前 revision、lastEventId 与原 publishUntil。发布期限过期不推导为已删除或已发布；写入结果不明且清理失败的状态保持原值。写入日志没有原文件名，不从其他数据猜测；成功发布后按原生命周期已移除的写入日志和事件不重新生成。

删除记录保留本人 ID、原文件名、uploadId、operationId、原 pending/removed 状态、requestedAt、removedAt、generation 与 lastEventId。pending 不表示已删除；历史条款撤销或当前存储配置变化不会重写记录。写入事件保留 writeId、ownerId、id 与 revision；删除事件保留 uploadId、ownerId、id、generation 与原 createdAt。所有事件按父记录和版本分页，不能套用普通列表的数量限制。

不会输出 storageKey、存储 scope、writerToken、清理 leaseToken/leaseUntil、acceptedAuthVersion、密文或内部状态摘要。显式投影不能授予发布、清理或执行权限，也不携带原文件字节。

## 校验与历史边界

上传/删除服务与归档共用 upload-journal-codec 的纯解密校验：当前记录必须匹配 SQL 索引、AEAD 上下文、规范字段和最新事件中的完整记录摘要。正常服务原有身份检查、事务锁、写入、租约、存储和恢复流程保留；共享解码另加强最新事件父记录及事件载荷形状检查。

归档逐页读取全部事件，验证连续版本、已认证的事件载荷、当前尾事件，以及删除日志首事件时间。事件缺失、重复、密文损坏、未知记录字段、跨账号或孤立关联、当前记录回放到旧版本均使整包失败。写入事件没有 user_id，通过存活父日志归属枚举；删除事件按自身 user_id 独立读取并验证父日志，不能靠 JOIN 掩盖孤立事件。删号后为清理而保留的其他账号日志不会进入当前用户归档。

旧写入事件只封存状态摘要，没有历史时间和旧记录快照；旧删除事件只封存摘要与时间，没有每步旧状态快照。更早事件的父记录 ID 也没有独立写入其认证上下文，而由不可变 SQL 行和外键关联；当前尾事件摘要能够与完整当前记录核验，较早事件不能据此重建或独立证明每步完整状态与父记录。这里导出实际保存的事件元数据，不宣称实现了可重建的历史审计链，不补造时间或状态，也不通过迁移伪造过去的证据。

## 事务与执行边界

四类日志都在现有密码复核后的 REPEATABLE READ 捕获事务中读取，固定本人会话，分页前检查取消，结束后再核验身份。归档不对日志加写锁，没有 BlobStorage 依赖，不触发发布、删除、恢复或重试。真实 writer 完成或清理进程可以并发提交，当前归档仍保持事务开始时的记录与事件版本。

沿用 5 秒事务期限和 JSON 容量限制；失败回滚本事务的复核消费，不返回部分包。没有数据库迁移、主服务开关或公开下载接口。完整数据覆盖、持久化归档 worker、较大账户处理、ZIP/下载校验及删除协调仍需后续实现。

## 验证

新增 10 项隔离 PostgreSQL 集成测试使用真实 UploadWrites/UploadRemovals 和虚构文件：pending/removed 历史、未确认写入与清理失败、归属与字段损坏、历史缺页/重复/当前记录回放、未知认证字段、105 个写入和删除记录及全部事件跨页、取消与容量失败、真实并发 writer 完成、真实并发清理、实际删号遗留日志隔离。写入与清理并发用真实事务提交证明快照一致；导出不访问对象存储或外部模型。

定向测试 32/32 通过（包含新 10 项和现有写入/删除生命周期测试），API 类型检查通过。最终 24 份账户导出、覆盖检查、组织知识、导师履约及原上传/删除服务测试共 265/265 通过，无跳过；隔离 schema 已清理，git diff --check 通过。没有付费模型、第三方服务或主数据库调用。
