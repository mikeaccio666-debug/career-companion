# 新版入门安全提示交付历史的私有导出

依据产品 09 §11、13 §4.5，账户捕获增加原生 V2 流程的八个私有区段：

| 区段 | 原始历史含义 |
| --- | --- |
| `intakeDeliveryHeads` | 每个真实分类来源的发布版本和当前发布引用 |
| `intakeDeliveryOperations` | 原发布/恢复命令，包括指向既有版本的实际重试 |
| `intakeResourcePublications` | 每个资源版本的原正文、问题模板、资源卡及保留时间 |
| `intakeBodyProjections` | 实际签发的正文投影；签发不是展示证明 |
| `intakeFollowupStates` | 已封存操作链的版本与最后操作引用 |
| `intakeFollowups` | 正文展示、过期后的展示证据、确认、请求支持、明确继续与澄清 |
| `intakeHandledSources` | 原分类来源对应的明确处理记录；原级别不改为 L0 |
| `intakeResourceCutovers` | 从旧版交付切换时封存的旧提示卡引用与完整性摘要 |

`AccountIntakeDeliveryExport` 在原账户 REPEATABLE READ 捕获事务中完整分页读取本人历史。原始输入、分类结果、固定响应、历史资源审核/激活和发布操作均使用原协议校验；full 分类必须有其实际完成的模型用量记录。解密后的数据不是执行权限，不发布资源、不签发展示凭据、不处理问答，也不调用当前政策或模型。

原资源、响应与发布读函数只新增事务内 `lock=false` 的归档读选项；默认仍保留原锁和写路径的调用方式。后续操作的纯解密/请求/摘要验证由普通流程和归档共用。发布内容与原资源重算结果、激活记录、保留时间完全匹配；不把当前版本替换进旧记录。

每个发布来源必须有完整的 1..N 版本、原首份发布锚点及当前 head；每份提示的全部操作必须连接原 genesis、连续版本、摘要链和封存 head。展示与确认引用必须属于同一会话、同一正文投影；明确处理必须对应真实操作。总量审计同时检查间接归属的状态、正文投影及操作，缺失整段历史也不能被当作空记录。

归档按实际保存状态返回正文、模板和事件。模板中的问题不表示真的问过；共享安全提问的 occurrence/operation/scope/exposure 表仍待投影，未因返回模板而算作已覆盖。该归档不重新激活到期记录，也不将正文展示证据升级为用户确认、恢复问答或真实安全判断。

输出通过字段白名单排除会话 hash、展示凭据/摘要、执行凭据、原密文、员工身份/审核详情及历史授权版本；保留用户实际收到的内容、原命令的非凭据参数和处理时的协议版本。只核验共享资源资产与激活记录，不将组织资产/审核表标为已导出。

所有主表及单份提示的操作、正文投影均每页 100 条遍历，逐条纳入账户总字节限制。原来源缓存最多八份，淘汰缓存不会漏导历史；操作关系缓存不保存原密文。任何来源、密文、完整链、鉴权或容量验证失败均回滚整个捕获与密码凭据消费，不返回半份归档。

无迁移或 UI 变更。JSON 当前覆盖 117 表、剩余 47；带文件覆盖 120、剩余 44；另有 7 项既有豁免，共 171 表。两种模式仍 `complete=false`，公开自助下载、剩余资料投影、完整删除协调与整个 P0 继续实施。
