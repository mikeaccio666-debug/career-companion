# 真人服务线下收款与退款记录

对应 [06 §6.3 / §11.3](../product/06-business-model.md)、[04 §3.5](../product/04-manteng-assets.md) 和 [07 P0-12](../product/07-first-cohort-mvp.md)。前置是 [真实匹配与报价](mentor-quotes.md)。本层记录运营确认的已在线下发生的交易，不调用收款、退款、邮件、CRM 或商业模型。

## 真实来源与操作

`MentorPayments` 只接受实际 ops / org_admin 的当前账号、角色与组织，通过原意向定位真实学生和订单，检查验证邮箱、法律同意、账号版本、已有匹配及完整报价/占用证明。组织 SHARE 与真实 owner → session → order 锁保持兼容；独立 nonce 锁串行重复操作，不签发学生登录或假权限。

输入闭合为 action（pay / refund）、operationId、sessionId、expectedRevision（订单版本）、amountCents、externalRef、occurredAt、evidenceRef、confirmRecorded=true。externalRef 只接受有限长度的外部交易坐标，不接受邮箱/URL、用户或订单指定、金额改价、保留期限、付款链接或自选 paid 状态。凭据必须在操作者本人真实私有上传中存在，大小和强 ETag 版本一致；真实摘要、来源与操作者版本进入密文不可变账务回执，不返回学生和运营订单列表。

收款录入须金额等于真实报价，并再次检查当前有效服务价目、导师及窗口版本、时长、未来可约时间和公开价上限。资料/角色/价格变化会拒绝新收款录入。退款依据已接受的实际收款，不要求已撤下的导师重新可约；只能从 paid / refunded_partial 按新订单版本增加正数退款，累计不能超出已收金额。回执确认是运营对实际凭据的声明，文件存在并不等于平台独立验真了银行、支付机构或律师意见；真实对账与法务仍是上线闸门。

`quoted → paid → refunded_partial → refunded_full` 的交易状态只在订单上。任意匹配阶段取消仍释放占用；未付款 quoted 变 void，已收款订单保持真实账务状态，由运营另行记录退款，取消不冒充退款。创建、匹配和账务原操作重试都读取当前状态；同 nonce 不同输入/操作者冲突，不产生第二份交易或复活已取消预约。

## 存储、保留与清理

071 扩展订单与不可变证明，付款/退款证明绑定真实订单、原匹配回执、逐步版本、闭合输入、操作者和凭据。普通 SQL 的状态、金额、外部引用/哈希、当前版本和密文均须与回执一致；恢复旧有效密文不能撤销后来的收款/退款。

新交易要求服务端显式配置 `PLATFORM_MENTOR_RETENTION_DAYS`（1–36500 的整数天数，无默认值）和 `PLATFORM_MENTOR_RETENTION_EVIDENCE_REF`（操作者实际私有上传的政策凭据 UUID）。两者任缺，拒绝录入。天数只是执行参数，不是法律结论；实际政策、期限与凭据由法务/产品负责人审定，测试中的 365 天及文件不构成批准。捕获实际政策凭据与本次期限，账务变更时按同一事务延长到至少本次记录时间加该期限。

`platform_mentor_financial_records` 保存单独加密的最少账务：金额/累计退款、币种、外部收款引用、随机交接码、交易/更新时间、状态和保留截止；没有 user/org/actor/session/file ID、称呼、邮箱、本人需求、对话或记忆。加密绑定匿名账务记录自身 UUID。保留证明只有摘要、动作和外部交易引用 hash，防止账号删除后同一凭据再次记入另一份订单。外部引用须含收款系统的唯一命名空间，不能混用不同机构的同号交易。

账号或机构删除级联清除私人意向、订单、来源/交易证明及占用；最少财务记录独立保留。worker 每 15 秒执行有真实数据库时间和 SKIP LOCKED 的最多 100 条过期匿名记录清理，先认证内容、截止时间和不可变证明，再删记录并级联删保留证明；未过期或仍有私人订单关联的记录不清除，保留期投影损坏会拒绝清理并报告静态失败，不输出身份/内容。原始运营收款凭据目前仍属于上传者的私有文件；学生删除账号不会自动删除运营名下的源文件，真实收款启用前须完成按客户关联的原始凭据最小化/删除流程。活跃账号的订单历史、账号删除后的新退款/拒付对账、实际政策全链验收及备份保留仍须在真实收款启用前完成，不能把本层当成已批准的完整金融服务。

## CLI、HTTP 与网页

```sh
./scripts/project.sh pnpm --filter @companion/platform-api mentor-payment record --org ORG_ID --session-file PRIVATE_FILE --input-file PRIVATE_FILE
```

会话和输入文件须操作者本人所有、普通文件、非符号链接、权限严格 600；令牌不进 argv。只输出订单/意向坐标、当前状态/版本、原操作版本和 replayed；不输出金额、来源、交易引用、交接码或私人内容。相同原输入用于显式核对原操作；没有新的 nonce 来替代不明结果。

沿用真实登录、账号窗口和 `private, no-store` 的本人订单读取、经组织角色审计的最少运营订单读取。没有 HTTP 收款/退款 issuer，没有外部付款调用。Web 核对本人真实意向/订单对，可接受账务版本独立于履约版本推进；同页面已观察到更高账务版本后不会接受较旧回复。暂停或换账号清除缓存。

本人服务页用「系统」文字和纸底卡呈现已记录收款/部分退款/全额退款，数字来自实际订单，不展示外部引用/交接码，也不把 paid 表成已排期。真正主线的 system 消息 DTO、逐次通知历史及付款说明外链还未接入；现有不可变账务回执是后续通知来源，不伪造队员或运营聊天消息。

## 验证与后续

隔离的虚构资料经过真实 PostgreSQL、版本化文件存储、密码-cookie HTTP 和实际 CLI；没有真实付款、退款、商业模型调用或申请。检查覆盖收款/多次退款、并发原操作、金额与版本、凭据/政策、实际导师与公开价格变化、取消保留账务、原操作者/学生/组织隔离、重复外部凭据、审计/插入后取消与过期回滚、账号删除的最少保留、旧密文/投影拒绝、101 条有界过期清理与重复迁移。Web 验证独立账务版本、系统文案、金额及隐藏外部引用。

本轮 130 项相关 API 检查（新增 19 项账务集成）、760 项 Web 测试、workspace 类型检查及 Web 构建通过。既有 Web bundle 大小提示仍在，实际浏览器/法律/运营验收未替代为测试结果。

仍需接实际专用 handoff_code 付款说明/账户、完成记录与正式改期、内部评分复核队列、旅程卡及主线系统通知；免费诊断真实 cohort 权益、付费建议策略、完整 ChatList、法律与运营验收以及规模/浏览器验收仍是 P0 待办。本分支不合并、不部署、不更新主预览/主数据库，不把测试政策或来源文件当作上线批准。
