# 主理人与专家的上下文组装

上下文编译器为产品对话准备人格、记忆、资料和房间历史，避免继续使用 legacy 工作台的客户端 persona 与 memories。依据 [主理人规格](../product/02-companion.md#154-上下文组装与优先级)、[共享记忆与历史规则](../product/03-team-and-orchestration.md#85-敏感度与注入全产品唯一的表) 和 [Agent 引擎](../product/15-companion-agent-engine.md#6-上下文与缓存)。当前实现是服务端内部的编译与筛选模块，尚未接入学生聊天入口或真实数据库读取器。

## 输入与调用边界

`services/platform-api/src/context-assembly.ts` 的 `assembleCompanionContext` 接收服务端持有的 `CompanionContextSnapshot`。调用者必须先从真实登录账号取得 owner，验证房间归属，并读取有版本和敏感度的投影；HTTP 不得接受整个 snapshot，也不得用客户端字段拼出它。主理人的人格应来自验证过的 BirthOrigin 与生成来源，专家人格应来自已审阅的人格卡，不能以 SQL 中的可变名字或任意文本冒充这些来源。

编译器检查各条资料、人格、关系、历史、任务和简报的 owner，以及历史的 conversation；拒绝 legacy、错误发言者、错误专家房间与未启用的专家。缺少档案或关系投影时输出明确的 unavailable，不制造 revision 1、用户事实或阶段。关系阶段采用产品定义的 `acquainting`、`familiar`、`dormant`、`landed`。

所有输入先经过有深度、节点和字符预算的普通 JSON 快照。getter、原型对象、循环、稀疏数组、额外字段和冲突的资料版本均被拒绝。结果复制并深层冻结；异常只给出固定错误，不回显内容。此检查确认结构和来源之间的绑定，不能替代账号鉴权、分类器或数据库来源验证。

## 记忆与敏感度

`packages/career-core/src/companion/memory-policy.ts` 按 03 §8 筛选已确认且未过期的 high 与 medium 记忆；low、提议、归档和未来确认时间不进入上下文。medium 带确认日期和待核对说明，对外草稿只使用 high。排序为约定、沟通偏好、本轮意图相关、确认时间倒序；主理人最多 30 条，专家最多 15 条。

`only_if_user_raises` 需要服务端解析的对应记忆 ID。restricted 仅进入用户主动提起的 Web 主理人对话，或用户自己设定的对应提醒；不送专家、Discord、语音或普通主动消息。sensitive 原文只供 Web 主理人的允许用途使用。专家只接收类别表允许的 normal 记忆；情绪规律不直接注入，沟通偏好只能取另行确认的普通偏好句，不能在编译时推断或改写敏感特质。

档案、准备输入、旅程、今天三件事、任务目标、主线简报和上次结果都要求带 owner、revision、状态与敏感度的来源投影。普通摘要端口只传 confirmed normal；受限的任务或交接目标会阻止组装，而不是通过自由字符串混入专家上下文。敏感工作材料之后经专门工具读取，Discord 摘要和提醒模板也需独立的已审阅投影，本模块不自动生成这些摘要。

## 交接便条与技能

`packages/career-core/src/team/handoff.ts` 的 `buildHandoffNote` 直接拼接目标、允许引用的事实、已确认沟通偏好和本队员的上次结果，最多 600 字。引用事实最多四条，保持原文和 medium 的出处说明；过长事实不自动缩写或用模型包装。没有可引用事实、偏好或上次结果时明确说明缺失。它返回确切的记忆与结果版本引用，便于之后记入真实 expert run 与使用记录。

技能索引和续用说明从现有 `CAREER_SKILLS` 生成，只包含对应发言者、已开启分期且已评审的技能。续用要求匹配实际清单 revision；不能直接传入任意技能正文。索引、说明和工具目录只提供上下文，不加载执行权限；真实 prepared run、租约与当前工具 mask 仍由现有 CapabilitySession 和轮次服务核对。

## 历史与前缀

主理人仅接收主线窗口，专家单聊仅接收本房间窗口和独立的普通主线简报。窗口以 ordinal 的 20 条边界对齐，保留约 40 至 60 条的范围，不用旧记录补回已删除或 excluded 的消息。未校验的模型正文不进入历史。转发卡、系统记录、工具摘要和导师参考聚合为带来源标签的 user 数据块，不能冒充当前发言者的 assistant 历史。当前用户消息和已经并入的插话放在变化层之后。

平台与渠道规则使用固定 system 文本；人格、能力索引、关系和普通用户摘要位于历史之前，时钟、旅程、意图记忆、输入、便条与行为标志在之后。只传专家需要的 `gentle` 与 `noTaskPush`，不传覆盖类型。工具定义保持目录顺序，JSON 对象键采用确定顺序。

`stablePrefixDigest` 是本地字节相等诊断，不代表供应商缓存命中。相同稳定投影下，时钟、旅程与插话变化不改动该摘要。预算已饱和时，用户主动提起的条件约定可能挤出普通沟通记忆，使前缀改变；这保留了正确的排序、准入与 30/15 条限制，但尚未满足 15 §6 的全部稳定前缀要求。后续需要接入真实的每日摘要与版本策略，隐私准入、删除和撤销仍必须优先生效；本次不调整产品规格。

## 后续接入与验证

真实读库、记忆模型扩展与 `platform_memory_uses` 尚未接入。当前支持主理人主线和专家本房间历史；`consult`、叫名字的主线发言需要后续的独立简报上下文入口，不能把主线房间改成专家房间来绕过隔离。主理人的原始 overlays、按处境的模式卡、已审核身份事实片段及旧历史摘要也还需各自的真实来源接入。返回的 `memoryUseReferences` 和 `sourceReferences` 是待持久化的引用，不是已写回的使用回执。真实调用之前，还必须完成账号与法律门禁、当前 L0 分级、轮次租约、费用预留、逐句输出校验和事件持久化。此编译器没有模型调用或 HTTP 路由，也不放行 [PR3 评测前置门](agent-evaluation-preparation.md)。

远端验证包括 career-core 完整 180 项、API 三个相关测试文件 36 项、现有 Agent 循环 23 项，全部通过，无跳过；career-core 与 API 完整类型检查通过。其中新增记忆、交接和上下文测试共 34 项。与真实 ProviderAdapter 和 Agent 循环的协议连接使用注入的假单步 runtime；没有调用商业模型、提交申请、迁移数据库或改动主预览。它证明编译与隔离规则，不证明真实模型质量、全产品聊天或生产缓存效果。
