# 今天三件事：确定性选择规则

依据产品 05 §2.2、02 §2.3 / §8.1 / §9 和 09 第 6 步，在 `packages/career-core/src/today-three.ts` 实现 `pickTodayThree`。它是每日计划的规则层，不是晨报生成、数据库写入或调度器；不调用模型，也不读取浏览器、数据库或系统当前时间。

## 输入与选择

调用方提供固定的服务端时间、用户时区、按优先顺序排列的当前阶段、已上线队员、日预算、有效覆盖状态、候选动作、待进行面试与前两个本地自然日的历史。默认总预算 90 分钟；同一队员最多 2 件，总数最多 3 件。阶段可以重叠，不在这里推导职业进度、判断资格或根据资料推断心理状态。`fifteenMinuteSteps` 来自 02 §2.3 的 Q4A 决策，不是模型诊断；开启后只接受原始估时不超过 15 分钟的候选，不替较长任务伪造较短估时。

顺序：先排 48 小时内截止和 72 小时内面试准备，按实际事件时间由近到远；其余按传入阶段的优先级，再优先一次可延续的昨日任务，最后用候选 id 确定稳定顺序。同一天仍有待进行面试时，只选关联这些面试的准备。已经开始的面试不再生成准备任务，已过截止的候选也不能退化为普通阶段任务。所有任务都受预算、队员数量、来源和权益限制；不足三件就返回实际数量。

- 只放 `free` 或来源已证实 `included` 的内容；付费、未知权益、非普通敏感度、已完成或不可用来源排除。
- 只允许前辈、投递官、面试官，且必须出现在服务端启用名单；把未来队员塞进名单也不会扩大 P0。
- 动作用结构化的待确认、面试间或队员单聊引用表示；没有任意 URL、工具命令或执行令牌。重复的同一待确认/练习详情只占一个位置；不同内容可以指向同一队员单聊。
- 昨日未完成可以再出现一次；连续两个自然日未完成的任务本次退回候选池，避免自动第三次重派。后续经过一天间隔，可重新按正常候选参与。完成或放弃的历史不作为延续任务。
- 输出为冻结的引用与规则依据，不带标题、简历、记忆原文，也不制造「昨天没做」之类标签。用于排除原因的 `skipped` 及 `suppressed` 是内部诊断，不是可直接展示给学生的消息。

## 休息与覆盖

「今天不想」和仍有效的暂停优先，无论是不是主动要求任务；重新开始须由真实服务明确更新该状态。按 02 §8.1 与 09 第 6 步，系统主动计划在 `post_rejection` / `post_crisis` 期间为空，`sprint` 不覆盖这个限制。05 的「最多一件轻量任务」用于用户主动要任务的被拒覆盖期；危机覆盖期只有用户主动要求才可选。这里只接受服务端已确认的请求来源，不对 HTTP 暴露一个可自行填写的绕过开关。

该函数不产生或取消面试、截止提醒，也不处理提醒额度。提醒须由独立的 `canSendProactive` / 调度路径按 02 §9 实现。因此本次不声称提醒调度已完成。

## 数据接入的剩余工作

这些输入仍是领域快照，字段校验和同一 owner 检查不等于真实来源认证。后续服务必须从同一账号下的真实阶段、权益、待确认、面试、覆盖及历史记录组装快照，保证历史两天的读取完整，重新确认动作状态，并把源版本与规则结果绑定持久化。正常显示和传输还须经过现有身份、协议、第一封信和安全门槛。

尚未实现每日计划表、接受/完成/挪到明天/放弃的事务、动作回执自动完成计划条目、替换上限、自加任务的文字分级、晨报生成与简版、通知、`GET /today` 和今天页。不能把此函数返回值当作已保存、已接受、已发送或已完成的计划；尤其 `state=completed` 目前只排除候选，不会替代真实动作回执对旧计划的更新。
