# 未知执行结果的人工核对

任务可能已经调用了外部服务，但没有取得可靠的完成回执。用户需要查看已有事实，记录自己在外部系统观察到的情况，刷新后继续核对。人工记录与服务器执行回执分别保存：用户观察不会把任务改成成功，也不解除原有的重放限制。

## 产品入口

任务卡、原会话的任务列表和目标计划共用核对面板。普通任务卡先读取服务器明确的当前版本；会话任务与目标计划使用各自已绑定的版本。历史版本只读取自己的核对记录，不展示当前版本的执行事实。

用户可记录“看到了结果”“未找到结果”或“仍无法判断”，附加简短说明。所有记录固定标为 `provenance: user_reported`、`verified: false`。没有找到结果不证明调用没有执行；看到结果也不证明它就是本次调用产生的。界面持续显示服务器结果待确认，并将用户记录单独列出。

服务器事实只包括有界的状态、尝试次数、是否有供应商任务句柄、是否等待清理，以及浏览器／工作流检查点和 MCP 回执的安全摘要。检查点可能保留前次尝试的已完成工作，因此明确标为任务级检查点。普通 `Job.artifacts` 没有通用的版本绑定，不作为本版本的成功证据。

## 数据与接口

共享契约位于 `packages/platform-contracts/src/job-outcome-reviews.ts`。迁移 `020_job_outcome_reviews.sql` 增加独立的 `platform_job_outcome_reviews`；它不修改执行表。记录按任务、用户、版本和递增 revision 追加；同一用户的 request ID 唯一，正文摘要用于拒绝不同内容复用同一 ID。

| 接口 | 行为 |
| --- | --- |
| `GET /api/platform/jobs/:id/outcome-review?generation=N` | 读取指定版本的最新20条记录和是否还有更早记录；省略 generation 时由服务器确定当前版本 |
| `POST /api/platform/jobs/:id/outcome-reviews` | 保存当前精确版本的一个用户观察，不执行任务 |

写入字段只有 `generation`、`evidenceVersion`、`expectedRevision`、`requestId`、`outcome` 和可选 `note`。备注最多2000个 JavaScript 字符单元、8KiB UTF-8；拒绝未知字段、无效文本和客户端提供的状态／回执／供应商句柄。

读取使用账号断言、登录会话与所有权检查，响应禁止缓存。写入按用户→任务的顺序取得锁，重新读取执行事实并核对服务器 evidenceVersion 与当前核对 revision。版本、事实或并行核对变化返回冲突。历史版本、仍有执行租约或没有未知／受阻执行边界的任务不能新增记录。

相同 request ID 与相同规范化正文重送时返回最初记录，即使执行状态后来变化。不同正文复用 ID 会被拒绝。这个幂等规则解决已提交但响应丢失的问题，不授予执行权限。

## 保存与恢复

面板使用当前账号的固定客户端。卸载、切换账号、切换任务版本后的迟到响应不能写回旧界面；读取可取消，保存请求被中断后仍可能已提交。

如果保存响应丢失，界面显示保存状态未确认，在当前面板生命周期内保留这次 request ID 和草稿，通过用户点击读取记录核对。不会自动再次 POST。如果有界的最新20条中没有找到它，界面也不能推断没有保存。版本冲突后的草稿保留，重新读取事实后由用户决定下一次保存。

刷新或卸载面板会清除内存中的未发送草稿与未确认 request ID。刷新后能重新读取服务器已保存的核对历史，但这不等于自动恢复上次未确认保存的身份，也不保证找回超过最新20条范围的记录。

## 执行边界

保存任何结论都不修改任务状态、generation、attempt、租约、审批、outbox、检查点、供应商句柄、MCP 回执、成果或目标计划成功回执。不会抓取备注里的链接、查询供应商、发送邮件、把备注默认交给模型，或重新调用工具。

浏览器已开始动作、MCP 已开始调用、无句柄的未知工作流／ComfyUI 提交仍受现有重试限制。CLI 清理未确认仍需独立的运维清理证据；用户核对不能证明容器停止。后续计划步骤仍需其绑定版本的服务器成功回执。

这版提供持久的人工观察台账。供应商专属的结果查证、运维清理及经验证的执行恢复是另外的能力，不能由人工记录代替。开发验证结果另见 [验证记录](verification.md)。
