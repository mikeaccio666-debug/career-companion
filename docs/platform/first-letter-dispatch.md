# 第一封信的持久化请求与后台队列

按产品 02 §5.4、03 §6.5、05 C7 和 09 后台生成路径，把已经准备好的 direct_letter 任务交给可恢复的内部队列。学生入口、生产 worker 启动和信件发布仍未接通。

## 接收与执行

FirstLetterDispatch.accept 在真实会话、用户锁和当前准备资料下保存请求。客户端操作 ID、任务 ID 和观察到的 preparationId 必须一致；已有任务只能重复读取同一个操作，不能换操作来重置执行。请求和 outbox 在同一事务保存。已有阶段或费用意图不允许事后补建执行授权。

迁移 087 新增 platform_first_letter_requests 与 platform_first_letter_outbox。请求保存加密的原始会话哈希、账户鉴权版本、任务/来源/准备身份、服务器配置和明确模型路线；密文绑定本人及该记录坐标。解码核对封闭结构、摘要、列值和规范 JSON。outbox 只保存投递时间及暂停原因，两表沿同一账户、任务复合外键级联删除。

Redis 仅接收 requestId、taskId。worker 从数据库重建原始授权，重新核对真实来源、会话、协议、安全状态、准备资料和当前服务端路线。新登录不能替换最初接受请求的登录；重复接受也不延长授权。已接受的任务不能 refresh 准备资料。

执行复用 FirstLetterGeneration 的实际持久化阶段、后台租约、费用和复核历史。保存的原稿不会重新生成；复核最多允许已有规则规定的一次重写。任何可能已经发出的不确定请求都停止自动执行。reviewed 只表示内部复核后的草稿，不表示送达。

## 通知恢复和暂停

生产者串行化自身 dispatch，并使用 PostgreSQL 事务 advisory lock 协调多个生产者。每批最多 25 条；以原请求 ID 作为 Redis job ID。Redis 通知丢失或完成后可由数据库重建，仍须通过真实阶段服务的并发和费用检查。每次通知投递有有界超时，生产者关闭后不再接收调度。

只有配置/预算暂停会定期重查；授权失效、来源变化、损坏记录和终态保留暂停。数据库首次读取暂时不可用或锁争用时保留通知恢复机会，不把后续未知发送结果当作可以重发。Redis 内容增加字段、任务 ID 不匹配或错误 job 名称都不会执行。

实际测试发现，预算拒绝此前被流消费器转成通用阶段错误，导致队列无法识别配置暂停。现保留执行器内部 CostGuard 的真实预算拒绝，且必须尚无 callId、费用绑定、launch 或 admission；不根据模型输出决定可以重试。再次执行仍由数据库核对无调用和无费用意图。原稿及第一次复核都验证过恢复同一个未调用阶段。

## 账户数据

本人 JSON 和文件归档都包含 firstLetterRequests、firstLetterOutbox 的已认证历史元数据，不输出原始会话哈希、鉴权版本、密文或摘要。导出核对请求、准备和 outbox 的归属及一致性；损坏数据使导出失败，不能静默跳过。

已检查隔离迁移后的实际字段与外键，再更新账户覆盖审阅基线：175 张表、7 项排除、168 项需要投影；JSON 覆盖 145 项，含文件归档覆盖 148 项；剩余分别为 23、20，complete=false。新增两个投影不代表整个账户导出完成。

## 接入边界

app 组装 FirstLetterDispatch 内部服务；队列生产者和 worker 已可构建，但没有新增 HTTP 触发路由，也没有加入 worker-main 或自动从 C1 入队。后续需要接通真实的服务端日期、已上线队员配置和学生触发事务，再完成唯一 post 发布、C7 完成与端到端验证。跨日期/配置变更和原会话失效后的任务恢复仍需专门设计，不能自动替换已接受的资料或权限。

真实模型质量评测与 PR3 顺序门槛仍保留。本轮测试仅用虚构资料与注入模型传输，没有付费调用、主库迁移、部署或预览重启。

## 验证记录

2026-10-09，远端 Node 24.21.0 / pnpm 11.13.1。修复后的执行集 33/33、真实 Redis 队列 4/4、账户导出/文件归档/费用与 schema 覆盖集 42/42 均通过；本轮准备任务集 11/11 通过。platform-api 类型检查和 diff 空白检查通过，隔离 PostgreSQL schema 和测试专属 Redis 队列已清理。

队列测试删除的只是本测试 UUID 命名空间，再由数据库补回原请求；两个生产者和两个 worker 不重复购买阶段。分别在原稿和第一次复核之前限制真实 CostGuard 预算，恢复预算后原阶段 ID 不变，原稿及复核合计恰好两次注入传输调用。无外部模型 HTTP 请求。

请求测试还覆盖并发接收、outbox 写入失败的原子回滚、新登录不可替换原会话、来源变化、伪造通知、密文损坏、跨账户外键、账户删除和不含凭据的本人导出。生成回归保留此前四个真实 SIGKILL / 新进程恢复场景。

上述验证证明内部组件行为，不是已经启动的生产 worker 或完整学生使用流程验收。
