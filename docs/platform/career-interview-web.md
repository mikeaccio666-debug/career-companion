# 面试日程网页

面试邀请里的当地时间需要明确的时区，夏令时切换还可能造成时间缺失或重复。网页在保存前展示对应的 UTC 时刻和两个时区；用户确认后，通过本人登录接口保存真实日程。

依据：产品 05 §0.3、§2.6、§3.1，08 §7.17，09 §3A。服务端记录与加密回执见 [本人面试日程记录](./career-interview-records.md)。

## 入口和操作

- /journey/interviews：读取本人记录，每页 50 场，可继续读取；从投递旅程和初见后页面进入。
- /journey/interviews/:id：单独读取该场记录，支持列表第一页以外的深链；不存在或属于其他账号时显示「这条内容不存在或已经处理」。
- 新建时读取真实投递记录与版本。公司和岗位取自被核对的原申请，不提供示例记录或默认选择。
- 本人可以修改轮次 / 时长、明确改期、记为已面完或已取消、删除记录。状态修改和删除都有二次确认；投递阶段仍由用户在投递旅程里单独修改。

表单的新申请、轮次、时长、日期和面试时区均为空。双时区显示的初始值来自当前设备，标签明确说明该来源；用户可以改显示时区。它不替代面试时区，也不代表已保存的个人时区偏好。

当前入口是日程记录的一部分。面试间、免费练习、作战简报、复盘、日历 MCP、提醒与改期后的练习重排仍需各自接线。没有对应运行通道时，不展示可点击的练习 / 简报入口，不制造生成结果、通知或通过率。

## 时区和确认

网页固定使用 Luxon 3.7.2 和类型定义 3.7.6。根据 [Luxon 官方 API](https://moment.github.io/luxon/api-docs/index.html)，getPossibleOffsets 可以列出同一当地时间的不同偏移量；本实现还核对转换前后的全部日期时间分量，阻止缺失时间被自动顺延。

- 时区必须是服务端契约接受的有效命名时区；缺失时区、裸偏移量或无效日期不能回落到设备时间。
- 正常时间显示唯一的 UTC 时刻；用户仍须勾选确认后保存。
- 重叠时间显示两个带 UTC 偏移量的单选项，不默认选择首次或第二次。
- 缺失时间显示原因，禁止保存，要求重新选择时间。
- 编辑已保存的记录时，保留原 UTC 时刻对应的偏移量、秒和毫秒；修改时间或时区后清除旧选择和确认。
- 显示两个命名时区及各自的实际偏移量，保留跨日变化；时长使用等宽数字。
- 轮次和时长编辑不重新推算开始时间。

## 客户端与状态

career-interview-api 是独立的账号绑定请求端口，可以直接用于真实 HTTP 测试，不依赖 Vite、页面组件、模型或浏览器自动化。它核对所有者、对象坐标、操作标识、动作、应用版本以及最新结果。解析器派生的 action 不进入严格 HTTP 命令体。

controller 只在内存中保存状态。读取有 12 秒界限，写入有 8 秒界限；以 Promise race 和中止信号处理不响应中止的底层请求。超时、网络丢失、非结构化代理错误或无法核对的响应均保留原操作标识，锁住新写入，只提供明确的原操作观察 / 重试。观察 404 不代表原操作失败，不清除待核对的意图。

明确的版本冲突需要重新读取。表单保留本人的输入；记录已变化时，用户可明确选择放弃旧输入，用最新记录重新开始。删除当前分页坐标后，需要重新读取列表。

账号失效时中止请求并清空日程、申请选项、草稿和原操作。组件只展示当前捕获的账号与 controller 状态；停止或重新启动后，旧响应无法重新填回内容。没有 localStorage 草稿、后台自动重试或跨账号恢复。

## 验证与剩余工作

本批在远端完成：

- 717 项完整 Web 检查，含新增 30 项时区、严格 HTTP 协议、原操作恢复、账号失效、深链、分页和真实 React 静态渲染检查。
- 52 项完整共享契约检查。
- 50 项真实 PostgreSQL / 密码登录 HTTP 检查，含新增 3 项实际 Web 请求客户端到本人接口的桥接检查；同时回归面试、投递和共享记忆，全部通过且零跳过。
- 完整 workspace 类型检查与 Web 生产构建。

真实接口桥接验证创建、编辑、改期、状态、观察、删除，以及接受后响应丢失的同一原操作恢复；数据库核对只有一条记录和一条创建回执。测试使用隔离 schema 和虚构资料，模型外部调用关闭。

静态渲染检查不能代替浏览器视觉和交互走查。本批未完成真实浏览器视觉验收，也未更新主预览、主数据库 schema 或部署。构建仍提示单个主 JS chunk 超过 500 kB；路由加载优化和设备上的首次交互速度需在后续验收中检查。整条 PR 栈的 CI 结果需要单独核对，不以本地通过宣称 CI 全绿。
