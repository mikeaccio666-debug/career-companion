# 第一封信共用输出校验

依据 02 §3.3、§3.4、§5.4。reviewFirstLetterCandidate 将真实准备好的信件候选稿送入 packages/career-core/src/companion/output-check.ts 的同一个 checkCompanionOutput 入口，surface=first_letter。没有另建一份禁用词表，也不把人格预览模式当作信件校验。

## 已检查

- 代码共用的禁用表达、承诺和销售压力；自称真人、人类经历、依赖、模型/供应商披露、付费和身份内容。
- 规则覆盖检测：AI 身份与用户起名；记忆同意、查看位置和修改/删除；消息/材料待确认、表单逐项授权、本人最终提交；今天三件事；资料不足两条时的后续了解内容。
- 服务端队员名单与正文出现的名称对照，拒绝漏掉已列队员或把未列队员介绍进来。P0 名单没有自动默认；名单的实际上线状态仍由后续任务读取真实配置认证。
- 本人事实来源种类、不同来源引用数量、原始文本上的引用坐标、与服务端来源描述的逐字对照。来源描述保留结构值的区别，如在投且还没面试、未定岗位、尚未毕业、16 个月而不是擅自改成 18 个月。
- 正文连同真实签名和日期的 350 码点上限、无效日期/印章、格式、完全错误的语言文字覆盖、明确人格维度矛盾。人格维度来自同一真实生成完成回执，加入来源及准备摘要。
- 完成式执行声明与未来能力介绍分开检测：可以说明投递官以后帮用户整理投递，不能无回执声称已发送邮件/提交申请。未改动原人格预览的更严格检查。

## 语义复核仍缺失

规则命中返回 blocked；无硬规则命中仍返回 requires_review，并带 semantic_review_required。**第一封信当前不会仅凭这些规则返回 passed_rules。** 逐字引用只能证明词句在来源里，不能证明整句话为真；遗漏的事实、反话、否定、同义改写、语言自然度与人格一致性仍需真正语义复核。

缺少同义句识别时，coverage 检测可能要求改写或复核，不能据此声称已完整理解语句。例如「不是说我是 AI」即使被关键字识别，也不可能成为已通过信件；给「已取得博士学位」附上存在的学历 ref 也不能批准。测试覆盖这些证据局限，不用假的 semanticReview.approved 字段放行。

这是尚未完成的校验链路，不是把产品改为固定模板或人工逐封审批的决定。下一步需要实现并用真实模型评测完整语义校验/一次重写流程、可靠复核回执，以及最终发布前的实时资料/名单/授权/费用检查；当前没有复核通过接口或可发送状态。若采用模型语义评审，其调用同样需要获授权型号、真实费用记账、失败和取消处理，不能伪造评审结果。

## 接入状态

reviewFirstLetterCandidate 返回私有 candidate 和只含规则编号的 outputCheck。完整候选及来源不能进日志；未来 output_blocked 事件只能存规则编号和消息 ID。当前没有事件持久化、后台任务、重写、发送接口或 C7 完成。已有独立模型通道、候选解析和共用检查，仍不等同于端到端信件交付。

没有数据库结构变更、主库迁移、付费调用、通知、部署或预览重启。PR3 顺序门槛与正式质量评测保持。
