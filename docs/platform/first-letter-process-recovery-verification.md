# 第一封信进程退出与恢复验证

2026-10-09，edaix-dev，Node 24.21.0 / pnpm 11.13.1。

## 验证边界

测试使用实际 PostgreSQL 隔离 schema、实际初见来源和持久化任务、模型 runtime、费用服务与 HTTP 流。虚构供应商只监听 127.0.0.1；子进程显式过滤继承环境，不读取商业模型凭据。测试进程不迁移数据库，隔离 schema 由父测试建立和清理。

独立子进程在指定事务已经 COMMIT 后通知父进程；父进程对自己创建的子进程发送 SIGKILL，并确认退出信号。恢复通过另一个新进程执行，重新组装真实来源读取器与 FirstLetterGeneration，不使用上个进程的内存结果。

请求发送场景还要求 HTTP 服务读完请求体并发回响应头，才进入终止点。费用与输出场景分别停在实际回执事务、实际输出事务提交之后。不是抛出异常来模拟 finally 清理。

## 已通过场景

| 退出位置 | 重启后的真实行为 |
|---|---|
| 原稿请求已发出，响应正文未返回 | 租约尚有效时仍为 running；过期后为 uncertain。无正文、无正常回执，费用按保守规则记一次，重复恢复不重发 |
| 实际费用回执已保存，正文尚未保存 | 保留已结算的真实用量及费用，不虚构丢失的输出；恢复不再次调用或记账 |
| 原稿输出已保存 | 禁用供应商的新进程仍能读回同一份正文和回执，不重新生成 |
| 复核请求已发出 | 原稿仍可读取，复核保持 uncertain，不重发复核、不另开重写；复核费用归属其原有阶段 |

测试只在隔离 schema 调整执行租约、运行租约和费用预留的到期时间，以避免等待；没有改写阶段状态、输出或回执来制造恢复结果。因此证明真实进程丢失后的数据库恢复，不证明生产调度器会按时触发恢复。
