# 对话里的任务与结果

Agent 准备的任务需要留在发起它的对话里。聊天响应结束或连接中断后，用户仍能找到任务、核对最新进度、审阅需要批准的调用，并把已保存成果的引用带回本对话草稿。继续发送始终由用户决定。

页面刷新后，可从最近会话重新打开原对话。任务关联保存在服务器；未发送的临时草稿不会因这项功能自动持久保存。

## 保存与执行的分工

`platform_conversation_tasks` 只保存任务、账号、对话、assistant 消息和准备工具的关联，以及创建时的任务版本；不再复制模型工具参数、网页正文或工具结果。服务器从正在处理的聊天闭包固定来源，客户端和模型不能指定其他对话或消息。

关联与任务、审批或 outbox 在同一事务中创建。来源必须属于当前账号、对应尚未结束的 assistant 响应，并拥有有效聊天租约；中断、过期或删除的来源不能留下部分创建的任务。对话删除会移除关联，已存在任务仍保留在任务中心；删除对话不代表取消执行。

原对话恢复的是引用与状态。任务执行仍由独立 worker、当前版本的明确审批和有效租约控制；旧审批不能批准新的任务版本，`uncertain` 仍表示执行结果待核对。普通成果可能来自较早执行，显示已保存成果不代表当前执行已经成功。

## 读取接口

`GET /api/platform/conversations/:id/tasks?limit=20&before=<jobId>` 返回 `ConversationTaskPage`：

- `tasks[].origin`：原对话、assistant 消息、准备工具、创建版本和时间。
- `tasks[].job`：当前任务状态、检查点摘要和已保存成果。
- `tasks[].generation`：当前授权版本，和 worker 尝试次数分别表示。
- `tasks[].approval`：如有，仅包含当前版本尚待决定的审批。
- `nextBefore`：下一页的所属任务 ID；没有更早记录时为 `null`。

默认每页20条，最多50条，按关联创建时间与任务 ID 倒序。游标必须属于同一账号、同一对话；接口先检查真实登录、窗口账号断言和对话所有权。返回私人数据不缓存。

## 网页中的继续动作

任务面板直接读取当前对话的持久关联，不从全局最近100条任务推测来源。切换账号或对话会取消旧读取并丢弃迟到响应。同一范围刷新失败时保留已显示的记录，并说明它可能过时；不会把失败响应当作空列表。切换到更早的时间范围会先清除前一范围的记录，新范围读取失败时显示错误，不把旧范围当作新页。

工具结果使用既有的私人结果通道：MCP 的专用结果读取、浏览器观察、普通文字成果和私人媒体。外部内容仍是未经验证的资料，结果链接不自动抓取。

“带回本对话草稿”只追加来源引用，保留已有文字和附件，不自动发送、批准或重放任务。普通聊天需要用户明确选择在本对话启用 Agent，再由用户发送引用。选择结果本身不调用模型；发送后，所选模型可能读取用户指定的私人资料。

这条闭环用于用户审阅后继续讨论，还没有实现跨 MCP、浏览器和 CLI 的自动持久计划协调器。真实供应商、组织知识库、生产迁移和真机仍需各自验收；开发验证使用虚构资料，见 [验证记录](verification.md)。
