# 每日计划的真实来源快照

依据产品 05 §2.2 和 09 第 6 步。`TodaySources` 已在 `buildApp` 组装，复用实际数据库服务，在同一账号锁和事务内读出每日规划需要的来源。它是内部数据读取器；还不是每日计划保存、用户接受、晨报或 `GET /today`。

## 已接来源

| 来源 | 当前读取内容 |
| --- | --- |
| 时间偏好 | 已保存时区、晨报/免打扰时间、日预算、提醒偏好与真实修订；未选时区明确拒绝 |
| 方向与经历 | 在用方向坐标，普通敏感度的在用经历坐标、来源仍有效的已确认故事坐标；不把普通经历坐标声称为已核实事实 |
| 简历与待确认 | 当前已批准简历坐标，以及所有在库原稿审阅状态、内容修订、状态代次、原批准操作和到期时间 |
| 岗位 | 本人保存的岗位坐标、岗位家族、实际录入的截止时间和时区；不声称岗位仍开放 |
| 申请 | 真实看板阶段、Offer 状态、结束原因、本人报告的提交方式；对照原岗位版本和当前原岗位是否仍在 |
| 面试 | 实际日程状态、轮次、时区、开始时间、面试时长、原申请版本与当前申请状态；与练习会话保持区分 |
| 被拒覆盖 | 真实不可改写事件产生的有效 48 小时覆盖；删除申请后仍保留原事件约束 |

敏感原稿保持 sensitive 分类。快照不包含姓名、公司、职位标题、简历、JD、经历正文、私人备注、URL、身份日期、密码、会话凭据或密文。它仍是本人私有元数据，含申请结束状态和休息覆盖，不能整包发给模型或用作晨报/通知正文。候选动作和后续正文还要有自己的敏感度、权益、来源与输出校验。

## 一致性与状态

所有读取使用实际服务的加密解码、不可改写操作记录和当前最大版本核对。时间偏好先确认真实诞生、邮箱与协议，并取得所有来源写入也使用的本人锁。没有嵌套事务、浏览器来源对象、假用户资料、公开数据注入接口或执行许可。

集合使用完整有界读取：方向最多 100，经历/故事、原稿、岗位、申请和面试各最多 500；超过时失败，不把第一页或截断列表当完整数据。简历和岗位复用已有批量认证读取，原准备接口仍返回原来的投影。

快照的 `sourceId` 对内容寻址，`capturedAt` 由数据库读取。单纯重复读取不改变摘要；实际来源修订、归属、存续、偏好、本地日期，以及到期/48 小时截止/72 小时面试边界改变时会改变。`assertCurrentInTransaction` 必须在真实消费事务内重新读来源；它只证明这些已接来源仍一致，不代替缺失的来源或业务授权。

到期原稿保留数据库原 status，另给 `actionable=false`，不在来源读取中伪造过期操作。面试 `done` 不等于完成练习。审批坐标可供后续自动完成任务时核对，但本次不创建完成记录。原岗位/申请移除时标 missing，版本变化标 newer_revision；不悄悄把历史引用改写为当前引用。

## 未完成来源与接入

主理人的小步偏好、完整覆盖状态（含危机后状态）、当前旅程重心、每日计划历史和练习完成回执仍返回 null，而非空集合或否。已有 post_rejection 事件不代表全部覆盖状态已接入。第一封信、完整安全门槛和费用/调度等属于最终业务消费方，不能凭本快照通过。

下一步继续补这些实际来源，再连接 `pickTodayThree`、每日唯一计划和条目状态机、用户接受/换任务/暂停、动作回执自动完成、晨报生成校验与通知。没有减少产品范围，也没有把此读取器当作可向首批用户开放的 Today 功能。

## 验证

新增 8 项隔离 PostgreSQL 集成检查通过，使用真实服务写入虚构来源和 loopback 诞生流程：审批/拒绝/删除后坐标失效、源文件关联移除、面试 done 与练习的区分、被拒窗口保留、55 条原稿/面试完整集合、账号隔离与协议撤销、旧密文回滚拒绝、晚到会话撤销，以及数据库时钟夹具下的夏令时和 48 小时边界。首轮有一项测试把原稿状态代次错当内容修订，已按真实 API 修正并复验；没有放松服务的版本检查。

相关简历、岗位、申请、面试、准备来源、账户归档和时间偏好回归累计 125/125 通过，无跳过；后端完整类型检查通过。

没有新增数据库表、改学生页面、启用模型、创建计划/晨报/提醒、执行申请、修改主数据库或部署。
