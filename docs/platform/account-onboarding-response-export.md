# 入门问答安全提示与用户处理历史的私有导出

依据产品 09 §11、13 §4.5，账户私有捕获新增三个区段：

- `onboardingSafetyResponses`：原始分类来源、实际 pending/ready 状态、原资源版本、已准备的提示与资源卡、准备事件和保留时间。没有准备过的内容保持 null，不生成新提示。
- `onboardingSafetyPublications`：旧版流程实际持久化的提示卡及其原内容摘要。持久化不是用户看过的证明。
- `onboardingSafetyFollowups`：实际展示、确认、继续问答、澄清及请求支持的操作，保留前后问答版本、展示/确认操作引用和原 resumeStatus。仅明确继续或澄清的真实记录表示 handled；读取导出不替用户操作。

`AccountCoreExport` 先在同一 REPEATABLE READ 事务内验证入门草稿、原文本操作和分类结果，再把已验证的私有投影交给 `AccountOnboardingResponseExport`。接口只用于服务内部归档组合，不能接受来自请求的替代来源。响应必须逐项匹配原分类结果、代次和准备事件；全部已分类 L1/L2 来源必须有真实响应记录。

提示和提示卡共用原流程的纯解密/捕获校验函数。导出不调用会恢复 inbox、发布卡片或依赖当前政策的普通业务 read 方法。每份提示卡必须匹配原响应、时间、版本与完整投影摘要。用户处理历史必须绑定同一份提示卡、同一会话的实际展示与确认操作；跨会话拼接、缺失展示、重复处理或损坏密文都会使整次捕获失败并回滚再验证凭据。

三张表均按本人及 UUID 游标以 100 条分页，全量读取仍实际保留的历史。已到期但尚未删除的旧资源和操作仍可取回；导出保留原存储状态和到期时间，不将其重新激活。之后的用户显示名、模型同意、邮箱验证及资源政策改变，不重写历史内容。原分类仍为 L1/L2，不因用户继续问答而转换为 L0 或共享记忆。

会话 hash、展示凭据及其 hash、密文、员工资源审核详情不进入归档；用户曾收到的提示和资源卡正文被保留。准备事件以响应的附属元数据返回，但 `platform_safety_events` 还有命名来源，因此该表继续标为未完整覆盖。V2 的交付、提问与后续操作也仍需独立投影，本次不把旧版处理当作 V2 状态。

无数据库迁移。普通 JSON 当前覆盖 109 张表，剩余 55；带私有文件覆盖 112，剩余 52；另有 7 个已审阅排除项，总表数仍为 171。两种捕获均保持 `complete=false`。公开自助下载、完整归档 worker、删除协调与其他未覆盖数据仍需继续实现。

验证使用隔离 PostgreSQL schema 与虚构资料，走实际分类、准备、发布、展示和确认协议：包括三种状态、L1/L2、澄清与继续、过期内容、政策/同意变动、105 条真实响应/提示卡及 105 条展示/支持操作跨页、串户/损坏密文、缺失来源链、重新加密的不一致内容、跨会话拼接，以及取消、容量和晚到鉴权回滚。未调用付费模型、未部署。
