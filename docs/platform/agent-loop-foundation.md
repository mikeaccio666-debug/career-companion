# 求职 Agent 循环基础

对应 [实施路线第 1 步 PR2](../product/09-implementation-roadmap.md) 与 [Agent 引擎](../product/15-companion-agent-engine.md)。本页记录工程边界与验证，不改变产品决定。

## 边界

此阶段提供共享循环、单次模型调用、能力目录和渐进技能加载，暂不把新循环接入学生 HTTP 路由。现有 `streamChat` 路径继续服务旧会话；旧工具执行、六步与十六调用上限、错误和账务规则由回归测试保留。

没有新增数据库表或迁移。房间、轮次租约、账务新键、停止接口、插话持久化、专家转发卡、订阅流与后台任务按后续 PR 实现。循环中的服务端钩子只是这些能力的接入点，不能证明上述产品流程已可用。

## 分层

- `platform-contracts`：单次模型事件、工具效果、循环输入输出，以及专家 key 的共享契约。
- `ai-core`：`streamModelStep` 每次只发一个供应商请求；`ProviderAdapter` 调用这个接口；`runAgentLoop` 决定何时继续、执行或收尾。
- `career-core`：能力与技能的纯数据、准备条件和索引；不调用模型、不访问浏览器或 OAuth。
- `platform-api`：执行器注册与权限复核，使用服务端数据端口构造 `CareerRunContext`，通过 `prepareCareerRun` 决定是否可以加载技能。

单步结果的供应商续接状态只在运行内存在。OpenAI 的加密推理条目和兼容供应商的私有推理不能进入公共事件、持久化 DTO 或日志。OpenAI 使用固定工具定义与允许工具名单；兼容协议只发送当步允许的子集。协议依据：[OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling)。

## 执行规则

每步重新计算允许工具；执行时再次检查权限。只读并行、草稿串行且排在只读之后，结果按模型调用顺序返回。草稿幂等键绑定轮次与调用 id；学生发言者没有 `act`。工具失败作为有边界的错误数据交回，取消、租约丢失与账务未确认立即终止。

技能只向其归属发言者开放。索引不携带完整做法；`use_skill` 在真实准备条件满足后加载正文，并在下一步开放相应工具。资料、执行器、连接或方法卡不存在时返回缺失原因；准备计划不授予执行权限。

新技能的发布还需要产品文档规定的评测、方法卡许可和审核。注册目录记录或通过虚构资料测试，不等于可以向用户发布。

## 验证记录

本地验证通过：`@companion/*` 类型检查；career-core 19/19；ai-core 249 项中 248 通过，既有 Docker Codex 夹具因本地未开启而跳过 1 项；platform-api 相关 9 个文件共 70/70。最后两处服务端修复后重新运行了 API 类型检查和这 70 项，未修改已验证的 core 源码。

测试使用虚构资料、注入的单次 runtime 和仅监听 localhost 的双协议 HTTP fixture，覆盖真实适配器、共享循环与技能注册器之间的调用。验证包括下一步才解锁技能、资料版本冻结、取消信号、执行前权限撤销、草稿幂等、预算收窄、工具禁用后的收尾和私有续接状态。没有调用付费模型、提交申请或部署；这不是商业模型效果或完整学生流程的验收。
