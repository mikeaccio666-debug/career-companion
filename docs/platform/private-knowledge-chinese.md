# 私人资料库中文检索

对应产品 09 第 3C 步、15 第 4.2 节的中文召回前置条件。私人资料库现在为连续汉字建立重叠两字索引，支持换一种说法的中文和中英混合查询，供后续统一知识端口使用。组织库的 P0 结构化筛选、方法卡加载和授权规则保持原有边界。

## 检索行为

应用层的 `knowledge-tokenization.ts` 在保存和更新段落时生成相邻两字词，例如「系统设计」生成「系统」「统设」「设计」。空白、标点、英文和 emoji 分隔词组，不跨边界拼接。正文重复出现的词保留位置，查询词去重后以 OR 召回，并用 PostgreSQL `ts_rank_cd` 排序。

中英混合查询仍要求非汉字部分的每个字面词出现，因此「职业规划 missingword」不会因为命中「职业规划」就忽略后面的限定。查询中独立的单个汉字同样保留为字面条件。没有两字词的查询走已有英文全文检索和转义后的字面匹配；英文词、长查询和百分号、下划线、反斜杠的原有规则继续验证。SQL 参数化，用户提供的 OR、引号或其他符号不作为检索操作符解释。

账号与可选 sourceIds 在 materialized owned 子查询中过滤，再关联现行版本的段落、排序和限量。每次仍最多 8 段、48 KiB，返回原文及原始 citation，标记 `untrusted_knowledge`。索引不授予任何新的权限，也不将资料变成模型指令。

## 索引升级

迁移 `066_private_knowledge_han.sql` 增加 `han_search_vector` 和 GIN 索引，对现有段落回填。回填函数与应用层使用同一组冻结的 Unicode 17 Han 范围，来自项目固定的 Node 24.21.0；升级运行时前需核对范围，避免新旧索引与查询分词漂移。范围边界及扩展汉字通过真实 PostgreSQL 对照测试。

该迁移只建立派生索引，不改正文、source 元数据、revision、更新时间或 passageId；墓碑没有段落，不会被恢复。保存与更新在原事务中写入索引，更新继续替换旧段落，删除继续清空段落并保留无内容墓碑。当前活跃源码中，私人段落的两个写入路径均经过 KnowledgeSources；后续新增写入路径也须生成索引。

## 召回验证

`test/fixtures/private-knowledge-chinese.json` 包含 30 份虚构课程、项目和求职笔记及人工定义的期望来源。每条查询包含不同于正文的中文表述；包括 SQL 和 Python 混合查询。测试通过实际账号注册、cookie、账号请求头和 HTTP 检索，不传期望 sourceId 来缩小范围。另一账号有相同主题、且与查询完全匹配的资料，用于验证权限先于排序和数量限制。

同一测试集、同一 recall@5 定义下，原实现命中 0/30，增加两字检索后命中 30/30，高于产品要求的 0.8。这个结果适用于当前有限的虚构集，不能证明首批用户全部真实资料、同义词、语义改写或组织库的真实查询质量。真实资料整理后仍需独立评测；本实现不使用 embedding 或外部模型。

目标检查包括 46 个 API 测试：新中文召回与混合限定、索引更新和删除、实际 065 到 066 升级与重复迁移、SQL 和应用分词一致性，以及既有私人检索和组织内容授权回归。测试还覆盖字节预算、取消、版本冲突、账号隔离和注入内容。已有工作台 Agent 使用注入的虚构模型传输验证私人检索；没有商业供应商网络请求。

## 后续接入

统一 CareerKnowledgePort、知识批次冻结、entitlement 撤销后的运行准入、专家技能加载及真实聊天 citation 持久化继续按产品规格实现。中文检索通过不代表这些能力或完整学生 engine 已接通。

本切片的迁移仅在隔离测试 schema 验证，主开发库和当前预览没有应用迁移。合并与部署前仍需按环境检查迁移和检索；整个 P0 上线门槛保持开放。
