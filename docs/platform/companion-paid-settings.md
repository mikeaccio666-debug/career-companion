# 主理人付费建议设置：本人保存与恢复

依据 02 §13 / §15.2–15.3、06 §7.5、09 第 8 步，实现 `paid_suggestions_mode` 的真实本人设置路径。它控制建议偏好，不能启用付费触发器或发放推荐权限；完整推荐来源、频次预留和发送仍待接入。

## 用户路径

主理人诞生页的「主理人设置」和学生设置页链接到 `/me/companion`。页面提供「合适的时候告诉我」与「只在我问的时候」，本人点击保存后才发送修改。真人服务入口保留，免费帮助不受影响。未诞生时明确说明需先完成诞生，不创建虚构主理人或设置。这里不是完整的关系设置页：称呼、免打扰、通知、静音服务列表仍待各自来源与交互实现。

初次读取返回产品默认值 `when_relevant`，设置版本为 0，更新时间和操作 ID 均为空，显示「这是默认选项，尚未记录你的选择」。这不代表用户曾点击确认。设置使用自己的版本，不修改人格版本、诞生回执、印章、关系阶段或主线会话。

页面领域请求、控制器和 React 视图分离。请求绑定真实账号窗口；刷新、重新登录只读设置，不自动发修改。失联/超时保留原操作；可以 GET 核对其真实回执，或显式重试同一个 PATCH。重新读取列表、观察返回 404、离线及恢复连接都不会丢弃待确认操作或换操作 ID。待确认期间禁止新的选择，离开页面有浏览器提示；没有把私人状态放进 localStorage/sessionStorage。账号失效和组件退出释放请求与私人状态，晚响应不能写入下一账号。

保存回执可能对应旧操作，而当前值已被本人后来改过。这时呈现服务器的当前值并说明是后来的选择，不声称旧选项仍生效。设置首次读取直接显示实际保存的选项，避免先闪现默认项。

## 真实来源与存储

迁移 074 给 `platform_companions` 增加独立的 paid_suggestions 字段及设置操作表。默认版本 0 是产品默认，不补造用户操作。一次保存由真实学生会话和当前协议/邮箱门禁授权，在账号锁内核 `CompanionBirthOriginStore.readCurrent` 的真实诞生来源，核对目标 companionId 与预期设置版本，再保存加密状态和不可变操作回执。当前 mode 是可验证的查询投影；密文认证本人、主理人和设置版本，回执认证完整原命令、接受时账号版本及实际数据库时间。

读取同时校验当前密文、所有设置投影及最新不可变回执。有效旧密文不能回滚已经保存的偏好，也不能把一个已保存的选择伪装成未选择默认值。原操作重放返回当前设置，不重复修改；相同 ID 换内容会冲突。并发修改同一版本只接受一次。读写的末尾重新核会话，迟到的账号重置会使设置和回执一起回滚。账号删除级联清除相关记录；没有产生营销活动、定时任务或主理人消息。

撤回当前协议或邮箱门禁后，真实本人仍可读取设置和已提交操作；新的设置修改与内部政策消费要求重新满足门禁。`readForPolicyInTransaction` 从同一真实存储读取偏好，供后续网页/Discord 的服务端政策适配器使用，不接受客户端快照或授权布尔值。本次没有声称 Discord 或推荐引擎已接通。

## 接口

- `GET /companion/settings`：本人当前设置；须有真实已诞生主理人。
- `PATCH /companion/settings`：闭合命令 `companionId`、`operationId`、`expectedRevision`、`paidSuggestionsMode`。
- `GET /companion/settings/operations/:id`：本人原操作回执与当前设置；不存在或属于别人则 404。

均沿用登录、x-companion-account、CSRF/请求额度及 private, no-store。额外 owner、provider、confirmed 等字段不被接受；错误不回显输入。本人身份及当前源真实性与推荐发送权限是不同的检查，本模块不发放后者。
