# 保存目标、顺序步骤与精确结果

目标计划为同一个账号和原会话保存一个目标、最多八个顺序步骤以及每步的固定结果引用。步骤可以准备现有媒体、工作流、浏览器、CLI、MCP 任务，也可以明确运行一次读取证据的 Agent 分析。计划不是求职岗位列表，也不证明用户已经拿到面试或完成现实目标。

这是跨工具计划的第一层持久化。原来的模型工具循环仍由当前 chat runtime 执行；没有引入 OpenAI Agents SDK，也没有序列化一个供应商模型调用栈。OpenAI 对审批中断的建议是保存状态、审批后恢复原运行。这里先把应用自己的目标、步骤、审批与成果关系保存下来，后续运行器应延续这些边界。[官方审批与恢复说明](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals)

## 用户路径

网页「目标计划」绑定当前会话。没有会话时，可以明确创建一条计划会话。填写目标、可观察的结果、每一步的要求和服务；草稿保存不会执行任务。尚未配置的服务可以写入草稿，确认时服务器检查实际能力、模型、附件和已审阅的执行模板。确认后定义冻结，修改须另存一份草稿。

Agent 也可以通过 `propose_goal_plan` 提出一份草稿，使用同一套步骤及前序成果规则。它先用 `get_execution_capabilities` 读取有界的服务器配置；配置不证明商业账号已授权或实际调用成功。工具不接收用户、会话或消息身份，来源由当前登录的聊天处理器固定。一条 assistant 回复最多保存一份提案；相同规范化定义重试返回原计划的当前状态，不覆盖用户编辑，第二份不同定义明确拒绝。

能力结果整体最多32KiB，过多信息会省略完整条目并标记 `truncated`，不截断JSON。模型工具仍受现有64,000字符参数限制；较大的手动计划和工作流通过编辑界面保存，HTTP计划整体上限为192KiB。元数据发现不能读出私人端点、环境变量或密钥。

原聊天展示服务器保存的提案摘要。刷新、断线或没有收到工具事件时，可以重新读取；工具返回本身不触发导航或确认。用户点击「审阅计划」才打开原会话中对应计划。摘要中的「已确认」只表示定义已经冻结，实际步骤与成果须打开计划核对。未保存编辑内容在同账号、同会话的页面导航中保留；刷新、退出或账号代次失效会清空内存编辑。

每次明确「继续」只处理当前步骤。任务步骤准备一个现有 job；外部执行仍需在完整的独立审批中批准本次任务。确认整份计划不代替该审批。相同版本和步骤重复继续，会返回已有任务，不重复创建或执行。

分析步骤先准备一个继续引用，再由用户点击「执行本步分析」才发起原会话的消息请求。服务器从已确认计划构造要求、服务、模型与精确前序来源，客户端不能替换它们。分析保留聊天中未发送的文字和附件，不把它们作为分析输入发送。分析只读保存的证据和资料，不创建新的外部执行任务。

只有成功的原绑定版本才解锁下一步。任务版本变化、未确认的执行结果、MCP 授权变化、缺失成果或分析中断都会阻止后续步骤；不静默重放。暂停或取消计划阻止继续后续步骤，已提交的任务仍须在各自任务记录中核对，不承诺撤销已发生的操作。

后续任务可以使用固定输入，也可以明确选择前序分析正文、文字成果、参考图或终端输入文件。确认计划时冻结的是来源规则；准备本步时服务器读取成功回执中的确切成果，固定实际输入，再交给独立任务审批。来源尚未产出时不提前宣称已审阅实际内容。继续不会自行决定新的来源，也不会自动批准任务。

## 前序成果作为输入

编辑任务时可以选择更早的步骤，把完整分析正文或第几份文字成果追加到原要求后，也可以用该全文替换要求。接收文字的任务目前是图片、视频、朗读和CLI；工作流、浏览器、MCP的外层prompt不驱动内部参数，因此不提供这项替换。浏览器观察与MCP文字仍须使用专用读取器，不能从通用文字文件旁路接入。朗读另受已选服务的文字上限约束；超长内容明确拒绝，不截成第一页或一段短文。

图片／视频任务另可选择更早任务的第几张PNG、JPEG或WebP。来源按成功回执中的artifact ID顺序筛选，页面也使用相同顺序。静态附件加前序参考图总计最多四张，实际服务的格式、数量、总大小、模型与首尾帧等设置仍适用；来源没有匹配成果时明确停止，不换成最新图片或另一份文件。删除前序步骤若会改变引用指向，编辑器要求先取消或重新选择绑定；不会悄悄把它指向其他步骤。

终端任务可以选择前序普通任务的成果文件，把视频、配音、图片、代码或其他文件作为私人附件交给既有CLI执行器。文件序号按成功回执中全部artifact ID的顺序计算，不按MIME筛选；默认第1份。浏览器和MCP任务仍使用专用读取通道，不能以通用文件绑定绕过。固定附件与绑定文件合计最多四份，每份最多10 MiB、合计最多20 MiB；不存在指定文件、元数据不一致或超限时停止准备并回滚。

准备把原定义hash、实际输入hash和来源记录随任务一起保存。文字固定为完整输入，图像复用私人保存附件，并记录实际字节的SHA-256、大小和MIME；审批、worker进入执行器前，以及返回给执行器的实际图片字节都会核对该记录。原步骤随后被修改／删除或计划暂停时，不重新计算已准备的独立任务输入。绑定文件另外固定文件名、MIME、字节数和SHA-256，并在独立批准、worker预检及执行器实际读文件时核对来源任务的确切代次、所有者和文件内容。缺失或变化的绑定图片／文件会阻止该任务执行；取消已经准备的任务走它自己的取消入口。

静态附件保留既有上传引用，没有新增静态文件内容SHA冻结。混合CLI计划的静态文件也在读取前校验单份上限，执行器核对全部文件的合计上限；本次精确来源及内容快照只覆盖明确绑定的前序成果文件。

网页展示“已准备的实际输入”、前序来源、私人参考图预览及终端文件的名称／格式／大小和显式审阅链接；完整审批仍以实际任务要求和附件为准。来源全文和文件名属于资料，不产生新的执行权限。Agent 可以提出待审阅草稿；任意外部工具参数映射、分支／循环及后台自动推进仍未实现。

## 保存与执行接口

共享类型在 `packages/platform-contracts/src/plans.ts` 和 `goal-proposals.ts`。017 migration新增计划、版本定义、步骤绑定三个私有表；018在步骤保存 `resolved_task`／`input_sources`；019保存服务器固定的提案来源和初始输入hash。已准备任务的执行策略也自包含输入快照，不依赖计划持续存在。所有私人接口使用已有登录Cookie、账号断言和所有者检查。

| 接口 | 作用 |
| --- | --- |
| `GET/POST /conversations/:id/goal-plans` | 列出或保存原会话的草稿 |
| `GET /conversations/:id/goal-plan-proposals?limit=20&before=<planId>` | 分页读取本会话的提案摘要，不展开全部计划 |
| `GET/PUT /goal-plans/:id` | 读取或按 revision 更新未确认草稿 |
| `POST /goal-plans/:id/confirm` | 固定本版本的服务、模型及输入，未批准任务 |
| `POST /goal-plans/:id/continue` | 按 revision、stepIndex 准备当前步骤；不执行模型 |
| `POST /goal-plans/:id/state` | 明确暂停、恢复或取消计划 |
| `POST /conversations/:id/messages` 的 `goalPlanStep` | 明确运行该计划绑定的一次只读分析 |

接口路径相对于 `/api/platform`。草稿更新使用 revision 比较；确认后不可原地修改定义。没有新增假身份、任务签发或第二套执行器。

任务步骤的可选 `bindings` 包含 `prompt`、`referenceImages` 与 `artifactFiles`。`prompt` 必填 `fromStep`、`source: analysis_text | artifact_text`、`mode: append | replace`；文字成果可选 `artifactIndex`。参考图使用 `fromStep` 和可选 `imageIndex`；终端文件使用 `fromStep` 和可选 `artifactIndex`，选的是完整回执的文件位置。API索引从0开始，成果索引默认0、最多63，步骤必须指向同计划中更早的一步；界面从第1步／第1份开始说明。绑定不能直接提供任意message／artifact／upload ID。

## 成果与恢复边界

任务继续使用 `JobService`、独立审批、outbox 和既有 worker。计划来源独立于已经结束的聊天租约，必须由服务器在事务中验证当前计划与前序成功回执。任务最终发布事务在已有租约校验之后保存 job ID、绑定 generation 与本次成果 ID 集合，不能从 job 的全部历史成果推断本步输出。

准备输入时沿已有user → plan → 前序job／message锁顺序读取完整资料、规范化输入，再原子保存快照、job和审批。相同步骤已有绑定时返回原任务，不再次读取来源。没有为此复制上传文件或创建模型请求；事务失败不产生第二份准备记录。

分析绑定唯一 assistant message ID，由服务器完成消息时写入回执。前序文本成果、浏览器观察和 MCP 响应通过既有专门读取器读取；每次核对来源与授权。来源文字、文件名和工具描述仍是未经验证的资料，不能授予新执行权限。

重新加载网页或重启 API 后读取这些保存记录。已绑定但结果不明的步骤显示待核对，不生成第二个 assistant 或重复 job。全部步骤返回成功后，界面仍提示用户判断现实目标是否达到。

提案写入使用同一数据库事务保存草稿、定义与来源。用户锁、会话归属、assistant 的 streaming 状态及消息／运行租约都须有效；锁等待后和最终写入时再检查取消信号及租约。已过期或断开且未提交的请求不留下草稿。已提交草稿可以在回复随后失败或工具事件丢失时找回，不能因此自动确认或执行。提案列表保留 PostgreSQL 微秒时间及UUID的稳定分页；来源消息删除后摘要的messageId为null，计划仍可审阅。

## Agent 读取用户修改后的计划

普通 Agent 新增 `list_goal_plans({})` 和 `read_goal_plan({planId,revision,stepIndex?})`。服务器固定用户、对话和当前 assistant 来源；模型不能传入其他身份。列表只返回本会话最近10个保存记录及当前版本，`hasMore` 明确提示有更早记录未列出。读取要求明确的当前版本；草稿被用户修改时，旧版本返回 `GOAL_PLAN_REVISION_CONFLICT`，模型应重新列出计划。

读取结果标记 `untrusted_goal_plan`、`readOnly:true`、`executionAuthorized:false` 和 `executionReadiness:not_checked`。最多16KiB，包含有界目标、最多8个步骤的保存状态和精确回执摘要；指定从0开始的 `stepIndex` 才附加该步的有界 instruction／prompt。正文及回执ID裁剪有明确标记，任务文本标记为原计划模板。执行 options、审批参数、实际冻结输入、原始成果和私人文件地址不会进入这个端口。保存状态和成功回执需要用户继续判断现实目标是否实现。

读取按 user → conversation KEY SHARE → plan → 来源 job／message → step → 活跃 assistant／运行租约的顺序取得必要锁；返回前使用数据库时钟再次检查两项租约和取消信号。会话锁先于计划锁，以支持同时删除会话。新工具仅供普通 Agent；确认计划中的分析仍保留原10个只读工具及冻结来源约束。

计划输入错误现在可附一项有限诊断 `{path,reason,expected}`，区分字段缺失、类型、空值、长度和绑定错误。字段路径及预期格式由代码固定，不回显输入值或未知字段名；真实解析器仍决定接收规则。诊断反馈前仍验证活跃 assistant 来源，大小、身份、租约、取消及基础设施错误保持原失败行为。模型必须自行提交正确参数。工具说明附经过真实计划／浏览器／MCP／workflow 解析器校验的虚构格式示例；示例不会创建计划或成为失败时的替代答案。

## 验证范围

协议与边界测试使用虚构账号、合成模型响应和本地 HTTP fixture；另有已安装CPU Qwen通过完整14工具的真实三场景验收，错误恢复修复前后均为0／3，不能认定为可靠规划模型。独立 PostgreSQL 验证目录与数据库不会更新当前开发预览或其主表；检查结果记录在忽略目录。实际验证结果见 [验证记录](verification.md#已安装开源模型的真实规划与错误恢复)。付费模型质量、真实外部账号、手机设备与生产部署不由这些 fixture 证明。

新增读取与诊断后，完整16工具的原三场景仍为0／3，用户改版后的跟进为0／1，没有保存模型草稿。这轮API 452通过／4跳过，网页相关6项、类型及构建通过；包含7组新真实PG和1组HTTP改版读取回归。程序能力与模型可靠性分别记录，详情见 [计划读取与模型复测](verification.md#agent-读取用户改版与有限参数诊断)。

视频＋配音→CLI合成现在可以表达为待审阅计划。新增文件通道的数据库测试使用虚构供应商与文件，不证明真实模型、CLI agent或FFmpeg已经完成这条组合流程；实际合成质量和工具可用性仍需独立验收。
