# 共享记忆：本人复核与持久化

依据产品负责人 2026-10-08 的决定，旧记忆必须先由本人检查内容、类别与敏感度并明确确认，再加入队伍共享记忆。依据 02 §7、03 §8、05 §2.12 与 09 §3B；本次实现本人管理路径，不代表完整 P0-8 或学生对话已经接通。

## 本人管理路径

网页入口为 `/me/memory`，领域契约、账号绑定请求客户端和 React 页面分开。旧记录显示「待复核」，类别与敏感度均需本人选择，不预选「普通」。内容过长时由本人缩短，不自动截断。本人可以新增、修改、调整敏感度、设置「我主动提起时再用」、限定沟通偏好的发言者、设置有效期、归档与恢复。受限内容默认折叠。

管理接口使用真实登录会话、学生身份、账号窗口绑定、CSRF 和用户请求额度；账号失效或变化会中止返回并清除页面状态。本人读取与删除不要求重新同意当前协议；新增、确认、编辑、恢复和撤销仍受现有协议与邮箱门禁约束。服务端决定来源、确认时间、置信度和版本，客户端不能提交这些字段冒充一次确认。

同一操作 ID 重试只读取原凭证与当前状态，不产生第二次写入。版本冲突保留用户编辑并要求重新核对；结果不确定时可以只读核对原操作、重试原操作或重新读取，不能自动用新操作覆盖。页面不把私人内容放入浏览器持久缓存。

## 真实存储与迁移

迁移 `053_shared_memories.sql` 为旧表增加空的分类字段、结构版本，以及记忆操作、事件和使用记录表。旧内容、原始时间和归属保持不变，不补造来源、敏感度或确认；版本 0 仅表示未经新管理流程复核的旧结构，不表示已共享记忆的历史版本。旧明文在本人确认或删除之前仍保留原存储形态，仅本人管理接口可以读取。

新增、复核、修改及删除中的暂存内容使用现有服务端 DataCrypto 加密，认证绑定 owner、记录 ID、版本以及数据列。密文包含完整状态，数据库的查询字段须与认证状态相符；真实不可变操作凭证提供单调版本，不能用有效的旧密文回滚已生效的敏感度。操作凭证仅保存加密的命令摘要与来源坐标，审计事件不含记忆正文。账号删除会级联删除私人记录、凭证和事件。

## 删除、撤销与清理

删除后记录立刻从列表与上下文筛选中排除。服务端在持有真实账号与记录锁后读取数据库时间，提供 10 秒撤销；撤销产生新版本，不覆盖原事件。页面倒计时只是交互提示，实际期限以服务端为准。过期删除由 worker 每 15 秒的维护批次清理，每批最多 100 条；到期即不可撤销，物理清理还取决于 worker 运行与下一次批次，不宣称正好在第 10 秒完成。

清理删除密文和关联使用记录，保留不含正文的操作凭证及事件，避免迟到的旧创建请求重新生成已忘记的内容。操作和事件在本人账号仍存在时不可修改或删除；真实账号删除允许级联清理。

## 与实际对话的边界

内部 `SharedMemories.selectInTransaction` 从真实本人记录读取并认证，核对当前策略下真实 full L0 和尚未处理的风险，再调用 career-core 的类别、发言者、敏感度、有效期和用途规则。未复核旧记录从不入选；restricted 只在允许的 Web 主理人用途且本人主动提起或自设提醒时入选。当前筛选返回待持久化引用，不记录一次假模型使用，不授予任何工具权限。

旧工作台聊天已停止直接读取旧明文记忆；其 `read_saved_memories` 兼容工具明确返回不可用，不能绕过复核路径。已排除的消息不再进入旧历史窗口。本人在管理页输入的新自由文本，已有内部真实来源与安全分级服务（见 [分级来源](shared-memory-safety.md)），但保存接口不会自动调用它，学生轮次也尚未接入；没有实际 full L0 的内容不被内部筛选器选中。这里的本人确认不冒充安全分级结果。新学生轮次仍需接入真实房间来源、当前安全分级、费用护栏、租约、模型输出验证和持久化使用回执。尚未接通时不把“可按规则入选”描述成已经发送给模型。

`GET /memories/:id/uses` 读取真实本人使用表；没有实际写入的记录就返回空，不制造“最近被用到”。使用写入器尚未接入学生轮次。专家提议、忽略与 30 天去重、14 天提议清理、90 天置信度降级、原消息与提议卡的完整删除/撤销生命周期、材料与交接便条中的引用清理，以及 Discord 10 分钟撤销仍是后续工作。带真实原消息关联的同时删除请求当前明确不可用，不假装已经完成。

## 接口

- `GET /memories`：本人列表，默认 50 条，最多 100 条；基于数据库实际微秒时间与 ID 的分页，不在同一毫秒漏记录。
- `GET /memories/:id` 与 `GET /memories/:id/uses`：本人单条及真实使用记录。
- `POST /memories`：显式新增；需 operationId、content、category、sensitivity、usePolicy、speakerScope、validUntil。
- `POST /memories/:id/confirm`：复核；需 operationId、expectedRevision、category、sensitivity，可显式提供 editedContent。
- `PATCH /memories/:id`：修改；需 operationId、expectedRevision 与允许的改动。
- `DELETE /memories/:id` 与 `POST /memories/:id/undo`：删除与本人撤销，均需操作 ID 和真实预期版本；撤销还需原 deletionOperationId。

所有返回采用 `private, no-store`；本人归属之外返回不存在。闭合契约拒绝未知字段、访问器、伪造 owner 或来源，错误不回显私人内容。

## 页面恢复与草稿保护（2026-10-09）

本人管理页现在使用独立 SharedMemoryController 和共享页面生命周期绑定。首次在后台或离线时不发请求；离线或隐藏会中止当前请求、清除列表/分页/使用记录的展示，恢复到可见且在线时只重新读取，不自动重放新增、确认、修改、删除或撤销。每次请求有明确超时和读取代次；即使底层请求不响应 abort，迟到结果也不能写回新的页面状态。

未提交的编辑与未确认操作只保留在同一账号、同一页面实例的内存里。未确认操作的 ID 和规范化参数冻结；列表重新读取不作为原操作完成的证明，页面明确提示由本人选择“核对这次操作”或“用原操作重试”。版本冲突要求读取后再次核对。读取失败会隐藏旧内容但保留草稿；同一操作真正返回有效回执后才清除它对应的编辑，归档其他记录不会误清当前草稿。未提交的修改或结果不明的操作会触发离页提示；不承诺在浏览器强制终止或刷新后恢复，也不写 localStorage/sessionStorage。

账号失效、切换或组件卸载清除控制器状态，编辑值另按客户端实例绑定。列表、使用记录和修改的请求适配器在发送前与返回后都验证当前账号，空响应也不例外。删除后的临时撤销状态只保存 ID、版本、删除操作 ID 和截止时间，不再额外保留删除正文；计时只用于界面，服务端仍决定真实撤销权限。

## 原操作的只读核对（2026-10-09）

新增 `GET /memories/operations/:id`。接口先认证本人真实会话和不可变加密操作凭证，再读取这条记忆的当前版本；查询不重放命令、不新增记忆/事件/操作记录。本人读取不受新增内容所需的协议和邮箱准入限制，仍检查学生身份、账号窗口和当前会话，并使用 `private, no-store`。

已删除内容只返回 ID、版本、删除操作和撤销期限，不返回正文或撤销快照。物理清理后必须由最新的真实删除凭证和已到期的数据库时间证明删除；仅仅查不到记录不能当作删除成功。原操作摘要、密文和认证版本不进入响应。回执损坏、无删除证据的缺失或读取期间会话失效均不返回成功。

页面新增“核对这次操作”，只发送该操作 ID 的 GET，逐项验证本人、动作、目标和原预期版本。查询失败或未找到回执仍保留原意图，用户可再次核对或用原操作重试。核对得到后来保存的版本就显示新版本，后来删除的记忆则移除；撤销入口只保留当前原删除且尚在有效期的坐标。页面恢复仍只读取列表，不自动核对或写入；列表本身不证明原操作完成。
