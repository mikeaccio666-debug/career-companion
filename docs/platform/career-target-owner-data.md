# 目标方向：本人记录与确认

依据 09 §3A、05 §1 与 §2.3、03 §2.7。本次落实实际目标数据表和本人网页管理路径，不代表完整求职数据层、旅程状态机或方向建议生成已完成。

## 用户路径

入口 `/journey/targets` 从已诞生的学生页和设置页链接进入。用户先选择岗位家族，填写方向名称、可选地点与排序；服务端保存为 `exploring`（还在比较）。本人在确认区点击「确认这个选择」后，才可转为 `active`（暂定主攻）、`paused`（先暂停）、`dropped`（已放下）或回到探索。所有决定可以调整，不给出匹配百分比、市场数量或录取概率。

复看日期由本人选择，使用不带时区的 `YYYY-MM-DD` 日历日期；可以改期或清空。卡片原样显示日期，不转换为 UTC、不猜测旧记录的日期，也不宣称已安排提醒。`exploring` 显示「还在比较」，`active` 显示「暂定主攻」，遵循 05 §2.16。

岗位家族使用 career-core 原有目录的同一个共享契约常量，保留原有 `ROLE_FAMILIES` 导出。页面与账号绑定请求客户端、契约和服务端分别实现；页面不读取数据库、模型密钥或浏览器自动化接口。手机窄屏使用单列、换行操作和至少 44px 的操作目标，样式沿用纸面、墨色与中性色调。复看日期增量已在实际 React 页面与全局样式上做 Chromium 检查，使用虚构账号客户端；这不替代完整真实登录端到端验收。

读取中的账号失效、切换或页面退出会取消请求、清空私人状态。版本冲突保留编辑内容，要求先读最新数据；未知结果保留原操作 ID，只能重试原请求或重新读取，不自动生成新操作覆盖。客户端验证 owner、目标 ID、操作 ID、实际版本和未重放写入的字段及状态，不能把变成主攻的伪响应当作本人已经确认。私人数据不放进浏览器持久缓存。

## 真实存储与授权

迁移 055 新建 `platform_career_targets` 和不可变的 `platform_career_target_operations`，不种默认目标、提议、已确认用户事实或模型来源。标题、地点、复看日期及完整记录使用 DataCrypto 加密；SQL 只保留查询需要的岗位家族、排序、状态、版本和时间。密文认证 owner、目标 ID 和版本，读取核对全部投影以及最新真实操作，旧有效密文不能回滚已经生效的主攻决定。

`reviewOn` 是加密记录的可选扩展：旧密文保持缺省字段，继续按原始规范字节和原操作摘要校验；新建未选择日期时写入 `null`。PATCH 省略字段保留原值，显式 `null` 清空，日期变更走同一版本及不可变回执。该扩展不新增明文列或迁移；旧操作的命令摘要不因新字段自动补值而改变。

每次操作由真实学生会话授权，使用数据库时间与账号锁串行化。新增、编辑和状态变更要求当前法律与邮箱门禁；私人读取与删除在当前协议撤回后仍可进行。同一个操作重试核对原加密摘要和来源，再返回当前真实状态，不再次写入；改变请求复用操作 ID 会冲突。每账号最多保存 100 个方向，列表完整读取这 100 个，不静默截断为前几个。

删除在同一事务中物理删除记录密文，保留不含标题或地点的加密操作摘要及坐标。迟到的旧创建重试只返回已移除状态，不复活正文。真实账号删除级联清理目标和操作凭证。本人之外的目标读、改、改状态或删除返回不存在；HTTP 同时核登录、账号窗口、CSRF 与请求额度。错误不回显正文。

## 接口与边界

- `GET /career/targets`、`GET /career/targets/:id`：本人完整列表或单条。
- `POST /career/targets`：本人记录新探索方向，显式 operationId、expectedRevision=0、roleFamily、title、locations、priority，可选 reviewOn；客户端不能提交 active、proposed、owner、来源或专家归属。
- `PATCH /career/targets/:id`：修改名称、家族、地点、排序或复看日期，携带真实 expectedRevision。
- `POST /career/targets/:id/status`：本人显式决定新状态，携带真实 expectedRevision。
- `DELETE /career/targets/:id`：本人移除，携带真实 expectedRevision。

所有响应采用 `private, no-store`。当前不提供专家提议写入器；数据库为后续真实提议保留 `proposed` 状态，但本人接口和当前记录解码器不能生产或接受它。没有虚构提议卡、专家运行或用户点击凭证。

初见 O2 的角色选择仍保存在现有认证问卷来源中，尚未自动投影到新表。职业档案、身份字段、投递、故事和成长数据表，以及旅程阶段与真正的 `read_journey`/学生工具接入仍待完成。内部 `readForPreparationInTransaction` 在调用者的真实有限时事务中重新核当前本人、法律、邮箱、密文与最新操作，仅返回 active/exploring 的真实 ID、版本、状态和受控岗位家族标签，作为 `OwnedCareerTarget` 准备索引；不返回用户填写的标题或地点，不制造档案或执行许可。用户保存的标题和地点没有被送给模型；正式自由文本上下文读取之前必须接入真实来源与输入保护，不能拿管理 DTO 当作已经通过 L0、已授权工具或已形成职业规划。此路径不解除 PR3 的评测前置门，也不开放学生聊天。

## 验证

隔离的真实 PostgreSQL 与真实登录 HTTP 测试覆盖状态变更、加密、原操作重试、并发版本冲突、跨用户、账号重置、当前条款与邮箱门禁、物理删除与迟到创建、有效旧密文回滚、不可变操作、真实账号级联删除和重复迁移。协议测试使用虚构传输数据，核对归属、版本、字段、伪造主攻状态以及删除后的重放，不替代真实数据库证据。模型调用与外部供应商请求为 0；主预览、主数据库和部署未更新。类型、构建和完整回归结果以对应 PR 和私人验证回执为准。

复看日期增量验证：契约 57 项、网页 782 项、隔离真实数据库和登录 HTTP 13 项通过（共 852 项，新增 6 项，无跳过）；三包类型检查与网页生产构建通过。覆盖日期校验、原命令摘要、旧密文、改期/清空、迟到重试、删除和跨用户。Chromium 的虚构客户端故障演练确认回执丢失后沿用原操作、重新读取、编辑恢复、显式清空和账号失效清屏；390×844 与 1440×900 无横向溢出，截图已查看，无控制台错误，无浏览器持久缓存。保留现有主 bundle 大于 500 kB 的构建警告；这不构成首批用户上线或模型质量验收。
