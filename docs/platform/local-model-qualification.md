# 本地模型验收

当前 Qwen2.5 7B 已证明能返回文字和调用部分工具，但不能作为通过验收的通用 Agent。完整 16 工具的上一轮真实验收中，三种规划均未通过，修改后跟进也未通过，模型没有保存计划草稿。具体结果见 [验证记录](verification.md)。协议测试通过不代表模型能正确选择工具、填写计划或根据诊断修正参数。

## 9B 候选与资源

首个候选为 `qwen3.5:9b-q4_K_M`，使用 Linux GGUF 的精确标签，而不是可能改变格式的通用标签。官方标签声明图像理解、工具调用和思考能力，下载约 6.55GB，包含语言权重和视觉 projector；这不代表相同大小的运行内存，也不代表已能生成图片。[Ollama 标签](https://ollama.com/library/qwen3.5:9b-q4_K_M)、[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-9B)

验收固定 manifest digest `56671c2ab9385f9cfcb404638e32cd62d88e3501d44822208363c010179a3c90`。当前测试 runtime 为 Ollama 0.33.2；该版本有 Qwen3.5 的专用工具解析器。模型为 Apache 2.0，商业使用与分发应遵守许可证及适用声明。[固定版本解析器](https://raw.githubusercontent.com/ollama/ollama/v0.33.2/model/parsers/qwen35.go)、[模型许可证](https://huggingface.co/Qwen/Qwen3.5-9B/raw/main/LICENSE)

备选为纯文本的 `qwen3:14b-q4_K_M`（约 9.28GB）和 `qwen3:30b-a3b-instruct-2507-q4_K_M`（约 18.56GB）。后者每 token 激活约 3.3B 参数，但完整权重仍需驻留，不能按 3B 模型估计内存。尚未下载或验收这两个备选。[14B 标签](https://ollama.com/library/qwen3:14b-q4_K_M)、[MoE 官方模型卡](https://huggingface.co/Qwen/Qwen3-30B-A3B-Instruct-2507)

CPU 验收时开发服务器约 30GiB 内存，系统 GPU 工具返回 NVML 驱动/库不匹配。该轮使用独立、只发布 localhost 端口的 CPU 模型容器，不改变主 Ollama、API、worker 或预览。容器限制 14GiB 内存、12 CPU、单模型与单并行请求、16K 上下文，禁止云模型。GPU 可用性与 CPU 延迟必须实际测量，不能由机器型号、模型标签或官方 GPU benchmark 推断。

随后只读排查确认 GPU 型号为 RTX 3090；已加载内核驱动为 595.84，系统 NVML 链接为 595.91.07，`nvidia-smi` 退出 18 并明确报告版本冲突。当时尚未验证实际 VRAM 与 CUDA 计算。所查 ldconfig 缓存和标准系统库目录未找到匹配 NVML，不代表全盘都不存在；Docker 当时只广告 runc 相关 runtime，也不证明 toolkit 未安装。该次只读检查没有安装、修复驱动或重启服务；私有凭据为 `.local/migration/gpu-readonly-20261006.json`。

## 产品配置与实验条件

`OLLAMA_REASONING_EFFORT` 是后端可选配置，允许 `none`、`low`、`medium`、`high`；省略时保留供应商默认，非法配置在发送前拒绝，其他供应商不受影响。这是产品支持的窄子集，不是 Ollama 所有可接受值。

本轮明确使用 `none`。Ollama 0.33.2 将其转为关闭思考；Qwen3.5 在该版本中把其余三个支持值均视为开启思考，不能称为三个计算预算档位。默认思考不能靠提示词假定已经关闭。[兼容接口映射](https://raw.githubusercontent.com/ollama/ollama/v0.33.2/openai/openai.go)、[Qwen3.5 解析器](https://raw.githubusercontent.com/ollama/ollama/v0.33.2/model/parsers/qwen35.go)

保留全部 16 工具、4096 输出上限、6 轮和 16 次工具调用上限、每次模型请求 120 秒，以及每场景 240 秒的客户端保护。没有缩小工具集合来取得通过。请求未显式覆盖 temperature/top_p；该 runtime 的兼容接口默认均为 1.0，报告须记录此条件。新模型、思考设置和 CPU 分配同时变化，结果不能解释为单变量对照。

## 验收内容

- 保留原来的研究规划、文字到图片到视频规划、交流练习规划三个提示词，检查实际工具顺序、保存草稿、输入及跨步骤绑定的语义。
- 人工通过 API 编辑计划后，检查模型实际列举并读取 revision 2，再准确复述新标题和第一步；普通文本中的伪工具调用不算读取成功。
- 用独立对话上传两张无文字的虚构 PNG，对比同一提示词下的位置、颜色和形状识别；第三个无附件场景必须承认缺少图片。答案仅保存在私有验收数据中，不进入模型提示或文件名。
- 核对本地图片、用户上传 blob 和实际模型请求中的图片 SHA 一致；另一用户的附件引用应在调用模型前拒绝。
- 检查真实账户、会话、计划与用量持久化、重启后恢复，以及零任务执行、审批、outbox、外部写入。缺失用量不是零用量。

所有素材为虚构测试资料，原始模型事件和运行产物保存在忽略的私有目录。计划与视觉分别计分；单轮通过只表示小规模验收。仍需真实图片生成、视频生成、实时语音与个人声音训练的独立模型验收，不能用配置、协议 fixture 或人工拼接视频替代。

## 2026-10-06 实测结果

上述 9B 候选已在独立 CPU 容器完成一次规划与视觉验收，未替换主预览的 Qwen2.5。实际 `/api/ps` 记录为 16384 上下文、`size_vram: 0`；整个测试容器的 cgroup 内存峰值为 7,986,327,552 bytes，OOM 与 OOM kill 均为 0。这是当前配置的一次观察，不是生产容量保证。固定输入、工具、请求预算、模型原始结果与独立评审均保存在忽略目录。

| 场景 | 实际结果 | 单次耗时 |
| --- | --- | --- |
| 研究规划 | 首次请求超时，没有工具调用或草稿 | 120.0 秒 |
| 文字→图片→视频规划 | 查询真实能力后保存三步草稿，前序绑定正确；有视频时长与审批表述瑕疵 | 217.7 秒 |
| 交流陪练规划 | 保存两步分析草稿，但漏了要求的能力查询 | 86.7 秒 |
| 用户改版后跟进 | 真实列举计划并读取 revision 2、step 0，正确复述新标题与正文 | 119.4 秒 |

原验收脚本报告规划 0/3、跟进 0/1，原始文件不改写。独立复核发现两处评分器错误：草稿后续步骤正常为 `blocked`，不应要求全部为 `pending`；跟进应核对实际详细读取，而非只检查更早的摘要读取。保持其余要求后，修正后的技术结果为规划 **1/3**、跟进 **1/1**。陪练确实保存了草稿，但缺能力查询仍判失败。共保存两份模型草稿，跟进场景另有一份人工准备并修改的计划；没有执行这些计划。

创作草稿宣称视频 30–45 秒，超过当前适配器 30 秒上限和特定 Seedance 模型 15 秒上限；它还把分析继续与执行审批混为一谈。草稿技术通过并不表示内容完全正确、图片或视频已经生成，也不表示接入凭据就足以执行。10 次实际规划模型请求中，9 次完成且用量 reported，合计 51,739 输入、1,684 输出 tokens；1 次中断且用量未知，不记为零。

视觉验收用真实账号上传两张不同排列的无文字 PNG，核对本地文件、私有 blob、GET 与模型请求里的真实字节 hash；不是只看模型标签是否声称支持 vision。每次仍提供完整 16 工具。

| 视觉场景 | 内容与行为 | 严格验收 |
| --- | --- | --- |
| 图片 A | 位置、颜色、形状、圆形数量全部正确，但输出单引号对象，违反 JSON 要求 | 失败，51.6 秒 |
| 图片 B | 错误调用生成图片的 `create_job`，被未配置供应商拒绝；没有图像答案或任务执行 | 失败，53.1 秒 |
| 不上传附件 | 承认没有收到图片，但输出散文且泛称自己无法查看附件，违反 JSON 要求 | 失败，27.5 秒 |

严格像素验收为 **0/2**，无附件控制也未通过。图片 A 的语义识别正确应单独记录，不能通过宽松解析把严格结果改成成功；图片 B 证明工具选择仍不稳定。三次视觉请求均完成并 reported，共 16,510 输入、288 输出 tokens。另一账号的附件引用在模型入口前返回 404，模型调用、运行入口与消息新增均为 0。

当前结论：9B 比原 7B 能做更多实际动作，但完整 Agent 的可靠性与 CPU 延迟仍不足，不作为通过验收的默认生产模型。可继续比较较小的 `qwen3.5:4b-q4_K_M`（约 3.32GB），或在单独核验 GPU 可用后复测 9B；4B 尚未下载或推理，速度优势只是待验证假设。[4B 精确标签](https://ollama.com/library/qwen3.5:4b-q4_K_M)

测试进程已结束，两个一次性数据库及 QA 环境文件已删除，独立模型容器已移除；权重保留在私有忽略目录。主预览源码、001–016 迁移、原模型服务与 4321 转发保持不变。没有付费模型、真实申请、推送或部署。综合证据与源码版本区别见 [验证记录](verification.md#comfyui-输出类型与真实-9b-模型验收)。

## 私有 GPU 与真实图片生成

2026-10-06 后续验证：官方 595.84 runfile 经固定 SHA 核对后，仅提取到用户私有目录，没有运行安装器、替换系统库或重启服务。私有 NVML 工具实际读取 RTX 3090 的 24,576 MiB 显存；Torch 2.14.1+cu130 的 float32/float16 小矩阵运算经过 CUDA 同步与 CPU 回读，结果正确。进程映射确认使用私有 595.84 CUDA/NVML；这不表示系统工具的版本冲突已修复。[NVIDIA 提取选项说明](https://download.nvidia.com/XFree86/Linux-x86_64/595.84/README/installdriver.html)

官方 SDXL base 1.0 的固定 revision、6,938,078,334 字节 safetensors 与 SHA 均核验，通过 ComfyUI 0.39.0 的七个标准节点生成一张 512×512 图片。真实 Platform API 注册、任务审批、父任务租约、步骤检查点和私有成果持久化完成；同账号三次读取（包括 API 重建后）得到相同 SHA，另一账号返回 404。唯一实际生成请求完整执行约 10.07 秒，Pillow 完整解码与人工图像检查通过。设备显存使用的采样最高值为 7,341 MiB，是设备总量和离散采样，不能当成模型独占峰值。

两次验收 helper 的标识符错误在生成前被拦截，原报告与 uncertain 任务保留；没有改数据库来绕过重放限制。之后新建并批准的任务完成，实际 `/prompt` 总计一次。引擎已经按精确进程身份停止，端口关闭、显存恢复基线。CPU 图片路线、真实视频生成、本人声音训练和生产 GPU 容量仍未验收。NVIDIA 驱动许可中的托管与 GeForce 数据中心条款也需按实际生产环境另行评估；这里仅记录私有开发验证。[官方驱动许可](https://download.nvidia.com/XFree86/Linux-x86_64/595.84/license.txt)

## GPU 9B 复测与音频聊天

同日后续使用独立 Ollama 0.33.2 GPU 容器、原精确 9B 别名与 16K 上下文，未替换主模型。第一次真实音频聊天由于私有库目录缺 PTX JIT 的版本链接返回 HTTP 500，原始失败保留。仅在用户私有目录补齐匹配 595.84 的 PTX JIT 与 gpucomp 链接后，真实模型成功运行；没有修改系统库、Docker daemon 或重启主服务。实际 runner 映射确认加载私有 CUDA 与 PTX JIT，33/33 层进入 GPU；逐请求 `/api/ps` 的模型 digest 为 `c80d1d84ecb47880004702ce44a2318add372df8e4533f83544d0ba7a1135740`，context 16384，size_vram 6,113,858,682 字节。该映射快照未显示 NVML/gpucomp，不能从链接存在推断全部已载入。

保持完整工具 schema、原四个提示词、关闭思考、4096 输出、6轮/16调用和原请求时限复测：研究 5.636 秒、创作 9.238 秒、陪练 4.989 秒、用户改版后跟进 4.744 秒。三个规划均保存真实可修改草稿，所有步骤 `ready=false`；研究与陪练漏掉规定的能力查询，严格规划仍为 **1/3**，真实版本续读为 **1/1**。创作没有旧视频时长错误，任务审批表述正确，但把配置密钥与服务实际就绪说得过于简单。11 次实际模型请求全部 complete/reported，共 62,970 输入、2,193 输出 tokens；执行、审批、outbox、attempt和遗留租约均为0。API 实例重建后提案和草稿相同，没有新增模型调用或被统计的执行写入。

核心 chat 实现与工具 schema SHA 均与上一轮 CPU 评测一致，但本轮已预热、能力元数据和 API 源码有变化，只能记录实测延迟改善，不能宣称严格单变量性能对照。单次小样本仍不足以证明默认生产 Agent 可靠。

另用同样两张无文字 PNG 及无附件对照复测视觉输入，原文件、账号私有 blob、GET 与实际模型图片字节 SHA 一致。两图的位置、颜色、形状及圆数量均正确，没有工具尝试或执行；无附件时正确承认没有图片。A 6.410 秒、B 1.420 秒、对照0.537秒。原 helper 自动剥离代码围栏，因此报告 normalized 2/2；B 实际输出带代码围栏，违反“只返回 JSON”。独立原始 JSON 验收应为 **1/2**，内容语义为 **2/2**，无附件严格对照为 **1/1**，原报告不改写。3 次调用全部 reported，共 16,510 输入、265 输出 tokens。另一账号的上传引用返回404，在模型入口前拒绝，没有新增消息、runtime入口或模型调用。

真实音频验证使用虚构 Kokoro 英文 WAV，经 Whisper 得到原始转写，在普通聊天中明确审阅编辑后交给 GPU 9B。程序链路和真实网页点击各有一次 ASR/聊天，成功轮累计 speech1、ASR2、chat2；两次聊天用量为375/27与674/21输入/输出tokens。不可改写的原 ASR 与用户审阅正文分别保存，模型只收到标记为未核实来源的编辑文字，不收到原音频；任务执行副作用为0。网页编辑清除确认，重新勾选后才能发送；刷新恢复回答、编辑正文和独立原文。375×812 与1440×1000真实 Chrome布局无横向溢出，截图经过人工检查；这不是真机、本人声线或麦克风验收。未登录时的 auth/me 401 为预期，已登录刷新后控制台无错误或警告。

## 真实本地视频生成

2026-10-06，Wan 2.1 T2V 1.3B fp16 已在独立 ComfyUI 0.39.0 引擎通过 Platform API 完成一次真实文生视频。三个官方重打包权重固定 revision `123acf1cc74bccbb9bfff8ac1ee72edc08c2341d`，合计 9,828,025,775 字节，完整大小、SHA 和 safetensors 数据偏移均核验；没有下载整个模型仓库。模型、scaled FP8 UMT5 文字编码器和 VAE 的来源及 Apache 2.0 许可分别保留，外部 ComfyUI 引擎仍采用 GPL v3。[固定权重仓库](https://huggingface.co/Comfy-Org/Wan_2.1_ComfyUI_repackaged/tree/123acf1cc74bccbb9bfff8ac1ee72edc08c2341d)、[官方 Wan 说明](https://github.com/Wan-Video/Wan2.1)、[ComfyUI 许可](https://github.com/Comfy-Org/ComfyUI/blob/b0b743566f65daafc423b4fea8a2fbda94b3384a/LICENSE)

生成部分沿用固定官方示例的 832×480、33 帧、30 steps、CFG 6、uni_pc/simple、shift 8 与单 batch，固定 seed。仅将示例保存节点替换为 stock CreateVideo／SaveVideo，以 16 fps 保存 H.264 MP4；实际引擎 object_info 核对了动态格式输入、范围和连接类型。没有 custom nodes、拼接静态图片或改写供应商输出元数据。[固定官方工作流](https://github.com/comfyanonymous/ComfyUI_examples/blob/cb13911e7d83e4f61ca12e29629cab85a6c08856/wan/text_to_video_wan.json)

真实账户注册、HTTP 审批、父任务租约、processJob、步骤检查点和私有成果读写完成。唯一生成请求执行约 **80.160 秒**，输出 473,452 字节、2.0625 秒 MP4。同账号三次读取（含 API 重建）SHA 相同，另一账号 404。FFmpeg 和 PyAV 完整解码 33 帧；真实 Chrome 桌面和 375×812 手机尺寸播放／seek 成功。这里未启动 BullMQ worker，也没有真机 iOS／Android 验收。

红色纸船、涟漪和倒影符合主要场景，但纸船基本保持中央，未明确实现提示词中的从左向右漂移和拖尾。独立九帧审阅不能证明全程无闪烁；实际短片播放通过也不代表专业质量、长视频或高并发能力。设备显存离散观察最高 13,769 MiB，监控最初出现身份断言故障并有采样缺口，不能作为完整或独占峰值。原生成进程经精确身份核对后继续被观察，没有再次提交模型请求。

这条路线可以作为开发和质量比较用的独立 GPU 执行端。此次单请求结果不足以把 3090 设为生产容量承诺；托管视频 API、不同质量档位和专用 GPU worker 仍需按实际使用量另行比较。详细版本、错误与清理证据见[真实视频验证](verification.md#真实-wan-视频与网页播放)。
